# 无限画布开发方案

本文是从零开始的本地无限画布的分阶段开工方案。没参加过过程讨论的工程师，应按本文的阶段、目录、字段和验收动手，不要再去拼五份过程稿。

本文与 [进度查询与工程审查](进度查询与工程审查.md) 并列，同为项目主文件。任何对话开始之前先读这两份。本文写边界与验收；进度、完成度和阶段审查状态只写在那一份里。

写作依据：

- 任务书已定边界（见第 1 节）。
- `docs/plan-notes/01-产品与信息架构.md`、`02-画布引擎与交互.md`、`03-执行与模型接入.md`、`04-媒体工程与运行形态.md`、`05-体验质量与验收.md`。五份说明互相打架时，以第 1.3 节拍板为准，不把「详见过程稿」当作正文。
- 本会话在工作区根目录核对过：`node --version` 为 `v24.19.0`；`npm --version` 为 `11.17.0`；`command -v ffmpeg` / `command -v ffprobe` 均为 `ffmpeg-not-found` / `ffprobe-not-found`；`require('node:sqlite').DatabaseSync` 可用；`LOCALAPPDATA` 为 `C:\Users\Lenovo\AppData\Local`。工作区没有本产品源码，只有计划目录。`eval/` 若存在，不当作模块。

文中的毫秒、帧率、并发初值、张数上限、人周，都是选定目标或判断区间，不是本机测出来的容量，也不是厂商配额。本文没有访问云厂商 API，不记录任何真实请求或响应报文。ComfyUI 的请求体、上传字段、历史响应结构以公开路由页拟定，落地前必须对照本机已安装版本核实。

## 1. 结论与原则

### 1.1 一句话

这是一张带角色有序槽的无限画布，不是第二个 ComfyUI。用户只看见文本、图片、视频、音频，以及一次生成结果。计算图留在本机配方里，不画到画布上。

### 1.2 开工原则

1. **画布是本体。** 节点种类只有五种：`text`、`image`、`video`、`audio`、`generation`。生成节点绑定用户能看懂的能力（文生图、图生图、参考图生成、图生视频），用有序槽接收输入。
2. **同一套能力接口。** 本机 ComfyUI 与云端模型对画布是同一个入口。换的是配方或绑定，不是换一套连线方式。
3. **ComfyUI 只填槽。** 只接受 API 格式工作流，包在我们自己的配方里。不把 KSampler、VAE、Checkpoint、CLIP 暴露成用户能连的线，也不做任意工作流往返编辑。
4. **成功只追加版本。** 新的成功运行追加版本，不覆盖旧版本媒体。变体默认留在节点内的变体条；只有用户拖到画布上，才变成新节点（复制引用，不抠走）。
5. **上游改了只标过期，不自动重跑。** 运行动作只有三个：运行此节点、运行下游、运行选中部分。
6. **本地并发字面量 1。** 真正的采样队列在 ComfyUI。云端车道另算，不占用这一个名额。
7. **视频不是大图片。** 必须有时长、首帧图、尾帧图、封面和代理。画布不播原片。
8. **第一版是浏览器加本机后端。** 后端只监听 `127.0.0.1`。现在不做 Electron / Tauri，也不做纯静态页。
9. **工程可拷走，密钥不跟着走。** 媒体按 SHA-256 放在工程文件夹。工程 JSON 只记正斜杠相对路径和参数，不含 API Key、不含二进制、不含 ComfyUI 地址。密钥进 Windows 凭据库。
10. **每个阶段都能演示，精美写进该阶段验收。** 不单开美化阶段。空状态、失败人话从阶段 1 起算；拖拽帧率从阶段 2 起算；进度、取消、离开再回来从第一次真生成（阶段 4）起算。空状态次句只承诺本阶段工具栏里真有的入口。
11. **工作区从空仓库开始。** 不要假设已有画布库、执行器或媒体模块。
12. **运行读工作副本。** 浏览器不必为了生成先点保存。`POST /api/execution/runs` 不发送工作流。执行器读后端内存工作副本。客户端 PUT 按第 9.9 节**合并**，不得整表覆盖 `phase` / `versions` / 哈希。落地由后端写副本并 `node.patch`。
13. **第一字节入库即哈希。** 阶段 4 起，生成或导入的媒体必须按 SHA-256 进 `media/blobs`。画布近景只加载缩略图票据，禁止 `blob:`、`file://` 或未鉴权静态原图。阶段 2 夹具若需要图块，使用已经哈希进夹具工程的小缩略图，走同一套票据。

### 1.3 跨领域冲突：本文拍板

| 冲突 | 不采用 | 采用 | 理由 |
| --- | --- | --- | --- |
| 图生图的底图角色 | 画布过程稿把图生图写成参考图槽；执行过程稿角色 `reference` | 正式 id：`source_image`（原图）、`reference_image`（参考图）。一律蛇形 | 图生图改的是一张确定原图，和参考图不是一捆无名图 |
| 「运行下游」范围 | 执行过程稿：起点加上下游 | **不含起点自己**。起点过期时先说明，仍不重跑起点 | 三个动作必须分得清 |
| 「运行选中部分」最少节点 | 画布过程稿要求至少两个节点 | 展开后 **至少一个生成节点** 即可 | 只选一个生成节点时，效果等于「运行此节点」（含新鲜确认） |
| 成功后的变体条 | 执行过程稿：新变体替换变体条 | **追加版本**。只补失败格子且指纹未变时，才写回当前版本 | 边界要求分得清新版本和覆盖 |
| 拖出变体 | 从条里抠走 | **引用抽出**：新节点共享内容哈希，源变体条保留，幽灵带「+」 | 抠走会改源的当前输出，整条下游被误标过期 |
| 取消后的主徽章 | 画布过程稿持续「已取消」芯片 | 短暂提示「已取消」，主徽章回到静止态（空 / 成功 / 失败 / 过期） | 重新打开后不得挂着「已取消」 |
| 新鲜节点再点「运行此节点」 | 静默跳过 | 先确认：「当前结果还没过期。再跑会新增一个版本…」 | 静默跳过会让人以为按钮坏了 |
| 工程文件名 | 产品过程稿建议 `project.json` | **`canvas.project.json`**，另有 `.bak` 与 `.autosave.json` | 避免和任意 JSON 混淆；备份策略跟媒体域 |
| 节点集合形状 | 媒体过程稿用数组 | 工程里 **`nodes` / `edges` / `groups` 用 id 映射** | 查找与补丁都按 id |
| 角色字符串风格 | 媒体过程稿 kebab-case（`reference-image`） | **蛇形**：`reference_image` | 与产品、执行对齐，工程里只存一套 |
| 能力标识 | 媒体过程稿 `image.from-text` 等 | **`kind` + `profileId`**：如 `image.generate` / `txt2img` | 能力接口一次留好，新厂商加绑定不加新连线方式 |
| 边是否记录变体下标 | 媒体过程稿 `fromVariantId` | **边只连到节点当前输出**。换当前变体等于换输出，下游过期 | 扇出读的都是当前输出，不隐含「每条线各取一个变体」 |
| 任务库位置 | 媒体过程稿放进工程 `tasks/` | **`%LOCALAPPDATA%\CanvasApp\execution.sqlite`**，不进工程目录 | 拷走工程时旧结果还在；失败句子和队列可以不在。这是已知限制 |
| 过期指纹与随机种子 | 执行过程稿成功指纹写入 `seedUsed`；中文「随机」与 `"random"` 混用 | **存储与指纹只用 ASCII `"random"`**；界面显示「随机」。`seedUsed` 记在变体上 | 否则新鲜节点会永远过期或永远跳过 |
| 浏览器如何碰 ComfyUI | 媒体过程稿泛化转发 `/api/comfy/*` | 浏览器 **只打能力接口**。后端内部才调 Comfy。不把 `/prompt` 原样暴露给页面 | 避免画布变成第二个工作流编辑器，也避免开放代理 |
| 空画布次句 | 体验过程稿「双击空白处添加节点」；旧稿一次写上生成和拖图 | **阶段 1**：「从左侧加上文本节点」。**阶段 3** 工具栏出现生成后改为「从左侧加上文本或生成」。**阶段 4** 图片导入可用后再加「或把图片拖进来」。不承诺双击创建 | 阶段 1 精美验收不得做成假入口 |
| 部分成功主徽章 | 执行过程稿 `partial` 当节点新鲜度 | **至少一张成功就是成功或过期**，副文案「4 张里成功了 2 张」。一张都没有才是失败 | 用户主徽章不超过：空、排队、运行、成功、失败、过期 |
| 运行下游 vs 部分成功 | 「运行下游」既跑可补失败格，又跳过指纹相符的成功 | **运行下游只跑空、失败、过期。** 部分成功（成功徽章+副文案）当新鲜跳过。补洞只走「只补失败的」/`retryFailed` | 两句命令不能相反 |
| 媒体层是否触发运行 | — | **禁止**。派生完成、文件替换、密钥更新都不得「顺便运行下游」 | 过期必须停在角标上 |
| 运行读哪份文档 | 运行前必须保存；或 POST /runs 附带工作流；或客户端整表覆盖工作副本 | **工作副本合并**（第 9.9 节）。执行字段服务器权威；落地走 `node.patch` 并 +`contentRevision`。执行只带 `RunScope` | 否则入队 PUT 会盖掉排队态，出图 PUT 会盖掉哈希 |
| 第一张图怎么出 | 阶段 4–5 占位原图 / blob URL，阶段 6 再哈希 | **阶段 4 第一字节即 SHA-256 + 缩略图票据。** 阶段 6 做拷走、回收、缺失、版本切换打磨 | 边界是产品要求，不是第六段才开始哈希 |
| 画布运行意图 | 另搞 `RunIntent`（`run-node`、`originNodeIds` 数组） | **只使用 `RunScope`**：`node` / `downstream`（单个 `nodeId`）/ `selection` | 阶段 3 按钮与 `CapabilityService` 同一合约 |
| 过期谁写入 | 每次按键打 `markStaleFrom` HTTP | **用户编辑**在 EditorStore 调 `packages/schema` 的 `applyStaleFrom`，随工作副本同步。**生成落地**由后端用同一函数标下游，经 `RunEvent` 回来 | 阶段 3 断网验收不能依赖执行 HTTP |
| 图生视频密钥 vs 夹具 | 夹具绕过密钥，或阶段 7 没有写密钥入口 | 夹具配方 **`requiresSecret: false`**。另备 `requiresSecret: true` 的桩配方演示提交前「还没有配置这一家的密钥。」Windows 凭据库在阶段 9 | 成功路径与缺密钥路径拆开，不互相拆台 |

后文若与上表不一致，以上表为准。

## 2. 产品定义

这是一个从零开始的本地应用。一个人、一台 Windows 电脑、一个浏览器窗口。用户在无限画布上摆文本、图片、视频、音频和生成结果，用带角色的线把它们连起来，再点三个运行动作之一去生成。

生成后端有两类，对画布是同一个能力接口：

- 本机 ComfyUI：只通过 API 格式配方填槽执行。
- 外部模型：API Key 存在系统凭据库，适配器消化上传、轮询、时长等差异。

第一刀能跑的能力：

| 用户看见的名字 | `kind` | `profileId` | 第一刀 | 槽 |
| --- | --- | --- | --- | --- |
| 文本（手写） | 素材节点 `text` | — | 阶段 1 就要有 | 无。文本节点不是语言模型 |
| 文生图 | `image.generate` | `txt2img` | 要跑 | 提示词 1 个，必填 |
| 图生图 | `image.generate` | `img2img` | 要跑 | 提示词 1 个必填；原图正好 1 个必填；遮罩最多 1 个，且配方接受才能跑通 |
| 参考图生成 | `image.generate` | `reference` | 要跑 | 提示词 1 个必填；参考图至少 1 个、最多 4 个（配方另写上限时以配方为准）；风格参考、角色参考各最多 4 个、可选 |
| 图生视频 | `video.generate` | `img2video` | 图像三条跑通后再接一条 | 首帧正好 1 个必填；尾帧最多 1 个可选；提示词 1 个可选。参考图槽只有配方声明时才出现；默认虚构配方**不声明** |
| 文生文 / 文生视频 / 对口型 | 对应 kind | `complete` / `txt2video` / `talking-head` | **只留接口**，菜单里禁用：「这一类还没接入。」 | 不注册可运行配方 |

打开工程的人被当成这台机器的使用者。工程可以拷到另一台机器，密钥和 ComfyUI 地址不跟着走。缺配方或缺密钥时，旧结果还在，只是不能再跑。

## 3. 非目标

第一版明确不做。没写进第 10 节该阶段「范围」的，默认也不是这一刀的承诺。

- 不把 KSampler、VAE、Checkpoint、CLIP 画成用户能连的节点，也不做「在 ComfyUI 里打开这张图」的往返编辑。
- 不做任意工作流的导入导出；加载器直接拒绝 ComfyUI 界面格式（顶层同时有 `nodes` 与 `links`）。
- 不把每个变体自动铺成节点；松手到空白不自动造无名连线节点。
- 不在上游一变时自动重跑，包括「只自动跑脏了的那几个」。
- 不在画布上播放原片；不把视频画成没有时长的大图；不在画布里做遮罩画笔或音频波形。
- 现在不做 Electron / Tauri；不做纯静态页；浏览器不持有 API Key，不直连 ComfyUI。
- 不把密钥、媒体字节、ComfyUI 地址写进工程。
- 不做文生视频、对口型、文生文的可运行适配器；不做第二家云厂商；不做云端文生图。
- 不做本地并行跑多个生成，也不提供调节并行度的控件。
- 不做多人协作、评论、图层市场、插件商店、工程级时间旅行。
- 第一版不保证磁盘不增长：会话内不回收媒体；下次打开才隔离到回收站，满 7 天再物理删除。
- 不把任务库拷进工程，因此只拷工程文件夹到另一台机器时，不保证失败句子和未完成队列还在。
- 不规定、也不宣称已测帧率、并发吞吐或某一家模型的时延。
- 不把 `eval/infinite-canvas-src` 当成本产品模块。
- 不单开「统一美化」或「最后补测试」阶段。

## 4. 用户场景

每个场景都是以后验收能对着做的路径。没写进场景的能力，不在第一刀里做。

**写一句提示词并出图。** 添加文本节点并写字，添加文生图节点，把文本连到提示词槽（也可以只用生成节点上的草稿），运行此节点。节点从空到排队、运行，然后成功或失败。成功后图出现在这个节点里，不自动铺成一排新节点。

**同一句话分出两张结果。** 一个文本节点连到两个文生图节点。改一次字，两个生成节点都过期，而且都不会自己重跑。

**多张图汇成一次生成。** 原图、风格参考、角色参考分别连进目标节点从上到下的槽。顺序就是交给生成的顺序。没有「一捆没有角色、也没有先后」的线。

**变体留在节点里，需要时再拖出去。** 一次运行可以要最多 4 张变体。它们出现在节点底部的变体条。只有把某一张拖到画布上，才变成新的图片节点。拖出去是复制一份引用，变体条里原来的那张还在。

**上游改了，下游只标过期。** 改文本、改参数、换连线或换成另一张变体之后，受影响的生成节点标成过期，预览仍留着旧结果。用户自己点三个运行动作之一。

**图生图和图生视频用的不是同一类输入。** 图生图改一张确定原图。参考图生成吃有序的参考图、风格参考或角色参考。图生视频吃一张首帧，可选尾帧和提示词。视频节点能看见时长、封面，并且现在不能播原片。

**关掉再打开，工作还在，密钥不在。** 保存之后的工程文件能重新打开。文件里有相对路径和参数，没有图片字节，也没有 API Key。

**离开再回来。** 生成过程中切换标签、刷新、甚至关掉浏览器再打开同一工程：任务由本机任务库接着记，不记在某一张标签的内存里。

## 5. 信息架构：节点、边、角色、版本、脏状态

### 5.1 词汇

| 词 | 含义 |
| --- | --- |
| 工程 | 用户选定的一个文件夹。身份是 `projectId`。工程文件是 `canvas.project.json` |
| 节点 | 画布上的一块。种类只有文本、图片、视频、音频、生成 |
| 素材节点 | 文本、图片、视频、音频。它们不能自己调用模型 |
| 生成节点 | 一次生成结果所在的节点。对外输出仍是文本、图片、视频或音频中的一种 |
| 槽 | 生成节点上的一个有序入口。同一时刻最多接一条线 |
| 角色 | 这条线在目标槽上的职责。角色写在槽上，边与槽保持一致 |
| 变体 | 某一个结果版本里的一张（或一条）输出。默认只活在变体条里 |
| 版本 | 一次运行产生的一批变体。新的成功运行追加版本，不覆盖旧版本的媒体 |
| 当前输出 | 当前版本里被选中的那一个变体。扇出的所有下游读的都是它 |
| 过期 | 节点还有旧的成功结果，但旧结果的指纹已经对不上现在的输入或参数。不是失败 |
| 配方 | 应用自带的一份填槽说明。用户只看见配方标题。本机配方内部才有 API 格式工作流 |
| 绑定 | 某个能力在这台机器上的一条可运行通路：一张本机配方，或一家云端 |
| 下游 | 沿输出线能走到的全部分支里的生成节点，**不含起点自己**。中间穿过素材节点时继续往下走 |
| 内容脏 | 用户的工作相对上次保存有改动，顶栏出现「未保存」 |
| 首帧 | 两个东西不要混。槽角色「首帧」是图生视频的输入。视频上的「首帧图」是这条视频导出的第一帧图片 |

分组是画布上的框，不是节点种类，也不是一次运行的单位。分组不改变连线含义，不参与指纹。运行前先展开成里面的节点。

### 5.2 工程顶层

一个工程是用户选定的一个目录。媒体库在同一目录内。用户在 Windows 上选的文件夹可以带盘符和反斜杠；写入工程文件之前必须收成相对该目录的正斜杠路径。工程文件里不得出现盘符、不得出现反斜杠、不得出现以 `/` 开头的路径、不得出现 `..`。

媒体按内容哈希存放。两个节点用到同一批字节时，磁盘上只有一份。第一版不因为删除节点就删除媒体文件。无人引用的文件下次打开工程时才进 `media/trash/`，满 7 天再物理删除。会话内不回收。

顶层字段见第 9 节。要点：

- `schemaVersion` 第一版只允许 `1`。更高或缺失：整份不打开。
- `contentRevision` 只有内容操作才加 1。视口、选择、悬停、撤销栈不决定内容脏。
- 视口可单独写入，不点亮「未保存」。
- 撤销栈只活在这一次打开里，不写入工程。重新打开后撤销和重做都是空的。
- 保存是覆盖这份 `canvas.project.json`，不是新开工程级历史。另存为必须换新 `projectId`。
- 保存时若磁盘上的 `contentRevision` 已经不是本次打开时读到的值，拒绝覆盖：「这份工程在这次打开之后被写过。为避免覆盖，请另存为。」
- 启动时后端连不上（还没有打开过工程）：加载圈最多 5 秒，然后整页只有「本机服务没连上」，主动作「重试连接」。**不**进入一个只存在浏览器内存里的工程。中途断开用第 11.1 节横幅，不用这句整页。
- 带令牌打开但尚未选定文件夹：`no-project`「还没有工程」。只有新建或打开成功之后才出现 `empty-canvas`。
- **工作副本**活在后端内存。客户端 PUT **不能整表覆盖**执行器刚写的 `phase` / 版本 / 哈希。合并规则见第 9.9 节。运行读工作副本。视口走单独接口。
- **自动保存**：结构编辑防抖 1 秒写入 `canvas.project.autosave.json`，**不**改 `savedContentRevision`。生成结果由**后端**在写入工作副本的同一事务里立刻写 autosave。失败句子：「自动保存失败，当前修改还在这个页面上。」

### 5.3 节点

五种节点，没有第六种。生成节点的 `outputKind` 决定它向外提供的是文本、图片、视频还是音频。

会让「自己（若已有成功版本）以及全部下游」过期的操作：生成节点上正在生效的提示词草稿封口且内容变了（没有提示词连线时草稿才生效）；改参数；换配方；连接、断开、替换、重排槽；添加或删除槽；用新文件换掉素材的媒体。

**改文本节点的 `text` 并已上屏**：文本节点自己不过期（它不是生成结果），`outputRevision` 加 1，**全部下游生成节点**过期。不看草稿是否生效——连着提示词线时，下游读的就是这份 `text`。

只让下游过期、不让自己这次结果过期的操作：切换当前变体（成功格子）；切换历史版本（自己是否过期看指纹是否仍相符）；点击失败格子（`output` 置空，见第 5.5 节）。

完全不过期：移动、改尺寸、改标题、改 z、成组、解散、只把变体拖到空白、平移缩放、选中。

### 5.4 边、角色与有序槽

一条边从源节点的唯一输出出发，落到目标生成节点的一个槽。素材节点没有输入槽。第一版不允许把线连到文本、图片、视频或音频素材上。

正式角色 id：

| `role` | 显示名 | 接受的源 | 第一版谁使用 |
| --- | --- | --- | --- |
| `prompt` | 提示词 | 文本节点 | 需要文字的能力。第一版每个生成节点最多 1 个提示词槽 |
| `source_image` | 原图 | 图片，或输出为图片的生成节点 | 图生图，正好 1 个，必填 |
| `reference_image` | 参考图 | 同上 | 参考图生成。按槽的顺序从 1 数 |
| `style_reference` | 风格参考 | 同上 | 参考图生成的可选槽 |
| `character_reference` | 角色参考 | 同上 | 同上 |
| `mask` | 遮罩 | 图片 | 只有配方声明接受时，运行才允许通过。第一版不在画布里画遮罩 |
| `first_frame` | 首帧 | 图片 | 图生视频，正好 1 个，必填 |
| `last_frame` | 尾帧 | 图片 | 图生视频，最多 1 个，可选 |
| `audio_reference` | 音频参考 | 音频 | 枚举先留着。第一刀界面不提供这个槽 |

连线规则：

- 不允许连到自己：「不能连到自己」。
- 不允许有向环：「会形成循环，已取消」。
- 种类不合：「不能把「视频」接到「提示词」槽」。
- 视频输出第一版不能落到任何槽：「视频结果现在还不能接到别的槽上。要用画面的话，拖首帧或尾帧。」
- 一个槽已经有线时，把新线松进这个槽等于替换。一次操作。
- 松在空白处：不创建节点，「要连到槽上，已取消」。
- 还没有结果的生成节点也允许被连出去。槽上显示「已连接，对方还没有结果」。真要运行时，必填槽没有可用媒体，按缺输入处理，不把线静默丢掉。
- 远景色块上松手：不猜测槽，「放大到能看清槽之后再松开」。不自动放大。

提示词只有一个真相，画布和执行必须用同一个 `resolvePrompt`。实现文件：**`packages/schema/resolvePrompt.ts`**，前端 EditorStore 与后端计划函数都 import 这一份，禁止各写一套。

- 提示词槽上有线：用源文本节点的 `text`。源是空字符串就用空字符串，不用草稿顶上。输入框只读，「提示词来自连线」。
- 没有这条线：用该生成节点的 `promptDraft`。

媒体槽读源节点的当前 `output`（`packages/schema/resolveSlotMedia.ts`）。过期不把图藏起来。文本类生成结果读变体上的 `text`，不走 `MediaRef`。

### 5.5 版本、变体、汇合

一次运行请求 `variantCount` 张（下限 1，上限 4，产品裁剪不是显存测量）。入队前就为每个下标抽好 32 位无符号种子。用户参数里可以用「随机」：过期指纹只记录「随机」，不把具体数字算进去。真正抽到的数写在该变体的 `seedUsed` 上。

变体条默认只显示 `currentVersionId` 这一版，不把历史上每一次运行的所有图片平铺成一条无限横条。节点上另有版本切换。

变体条只渲染 `versions` 里 `id === currentVersionId` 的那一版的 `variants` 数组。节点上没有 `node.variants` 字段。外壳高度公式里的「变体条是否出现」看这一版 `variants.length`（第 9.2 节）。

当前变体：新版本落地时设为这一版里最后一个成功变体。失败格子不自动变成当前。

点击变体格子：

- **已有媒体（或文本结果）的格子**：设为当前，更新 `output` / 对外文本，`outputRevision` 加 1，下游过期，该节点自己这次结果不过期。
- **失败且没有媒体的格子**：允许点，以便预览区读错误。`output` 变为 `null`（文本结果则对外正文清空），`outputRevision` 加 1，**下游过期**。预览显示 `error.message`，没有句子时「生成失败，没有更多说明」。
- **排队或运行中的格子**：可点来看进度，**不**改变 `output`，不标下游过期。

部分成功：至少一张成功时版本成立。主徽章走成功或过期。副文案：「4 张里成功了 2 张。」指纹没变时可以「只补失败的这几张」，补进当前版本空位，不新开版本。指纹已经变了就拒绝：「输入已经变了，不能只补失败的那几张。请重新运行这个节点。」

拖出变体：

- 拖到空白：新建同种类素材节点，`origin` 为 `detached`，共享哈希，源不变，下游不因此过期。
- 拖到兼容槽：同样新建素材节点并接线；目标及其下游过期；源不变。
- 排队中、运行中、或没有媒体的格子不能拖出。

扇出：一个输出可以连到很多个槽，全部读同一个当前输出。

汇合：多个源进入同一个目标的多个槽。`order` 就是顺序。交换风格参考和角色参考，目标及其下游过期，源不过期。

### 5.6 生成状态机（用户主徽章）

存储用 `phase` 与 `freshness`，以免「正在跑」和「跑完会过期」互相覆盖。徽章按顺序判断，命中就停：

| 顺序 | 条件 | 主徽章 |
| --- | --- | --- |
| 1 | `phase` 为 `queued` | 排队 |
| 2 | `phase` 为 `running` | 运行 |
| 3 | 从未有过成功版本，且 `phase` 为 `failed` | 失败 |
| 4 | 从未有过成功版本，且 `phase` 为 `idle` | 空 |
| 5 | 有成功版本，且现在的输入指纹不等于 `lastSuccessFingerprint` | 过期 |
| 6 | 有成功版本，最近一次尝试失败，且该尝试的指纹等于现在的输入指纹 | 失败（旧图留着） |
| 7 | 有成功版本，且指纹相符，最近一次不是失败 | 成功 |

不增加「部分成功」「中断」「已取消」作为永久主徽章。取消没有产生新版本，`phase` 回到进入这次排队之前的静止相位，短暂提示「已取消」。

正在排队或运行时输入又变了：不改 `phase`，只把 `inputsChangedWhileRunning` 设为真。跑完若指纹已变：新版本仍然写入，然后徽章为过期：「跑完的时候输入已经变了，这张图已标成过期。」不自动再跑。

`lastAttemptFingerprint`：任务**入队成功时**写成当时的输入指纹（与 `TaskRecord.fingerprintAtStart` 相同）。失败落地不改它。成功落地且完成时指纹仍相等，则把它抄到 `lastSuccessFingerprint`。这是徽章表第 6 行「最近一次尝试失败且指纹仍相符」的依据。

预检失败不入队，不改 `phase`，不追加版本，也不把成功改成失败。预检包括：缺必填槽、种类不合、配方不接受这条线、参数越界、这台机器没有配方、云端没密钥、这一类还没接入、这个节点已经在排队或运行、成环。

### 5.7 三种运行

**运行此节点。** 只跑这一个生成节点。不把上游加进来，也不跑下游。上游即使过期，也只读取它现在的输出。计划里若用到了过期输入：「将用上游当前的过期结果运行 1 个节点。」不阻断。

`RunRequest.force` 默认 `false`。当前徽章若是成功且指纹相符：先确认「当前结果还没过期。再跑会新增一个版本，旧结果还留在版本里，不会被盖掉。」用户确认后 **`force: true`** 再 `startRun`。空、失败、过期不弹确认，`force` 仍为 `false`。

**运行下游。** 不含起点自己。只跑下游里**空、失败、过期**的生成节点。指纹相符的成功节点跳过——**部分成功（成功徽章 +「4 张里成功了 2 张」）也按成功跳过**。要补失败格，用「只补失败的」/`retryFailed`，不要用运行下游。起点是文本时，不为文本建任务。若起点自己是过期或失败的生成节点，先说明这次不会重跑当前节点。运行下游 **永不** 把 `force` 设为 true。

**运行选中部分。** 先把分组展开成节点。只考虑选中的生成节点，不把选区外的节点拉进来跑。选中的生成节点即使用户没改过也要跑（点名）。若其中有指纹相符的成功节点，确认「选中的生成节点都会再跑，包括还没过期的。每个都会新增版本。」确认后 **`force: true`**。选区里至少要有一个生成节点。只有一个时效果与「运行此节点」相同，包括新鲜确认。

同一批里，某个选中节点所依赖的另一个选中节点失败了，或因缺输入没跑：下游这个不提交。「上游没成功，这一步没跑。」与它没有依赖关系的选中节点继续。

调度器启动时不扫描全部过期节点来补跑。

### 5.8 什么标脏，什么新开版本

内容脏看 `contentRevision`。排队位置、进度百分比、对账中的刷新，都不点亮「未保存」。成功版本落地会增加 `contentRevision`，但不进入撤销栈。

**文本封口（三种粒度分开，不要混成一个词）：**

| 粒度 | 何时发生 | 作用 |
| --- | --- | --- |
| 已上屏 | 非 IME 的 `input` 使 `text`/`promptDraft` 变化；或 IME `compositionend` 之后。`compositionupdate` 与组字中 Esc **不是**已上屏 | **立刻**加 `contentRevision`（内容脏）、重算过期、文本节点或对外输出变了则 `outputRevision` +1、同步工作副本。这是 P17 的 100ms 目标 |
| 撤销合并 | 同一节点同一字段 `coalesceKey = text:${nodeId}:${field}`；失焦、或距上次已上屏超过 600ms、或插入别种命令时收成 **一条** 历史 | 上屏后 Ctrl+Z 一次撤整句（或这一段合并窗口），不是逐拼音、也不是每个字一步 |
| 组字中 | `compositionstart`→`compositionend` | 不提交命令，不缩放画布，Esc 恢复聚焦时字符串、不留半条历史 |

| 操作 | 内容脏 | 生成版本 | 过期 |
| --- | --- | --- | --- |
| 平移、缩放、框选、点选 | 否 | 无 | 无 |
| 新建、粘贴、成组、解散 | 是 | 无 | 成组不过期 |
| 删除节点或边 | 是 | 不删媒体文件 | 失去输入的下游重算 |
| 移动、改尺寸、改标题、改 z | 是 | 无 | 无 |
| 文本节点已上屏且内容变了 | 是 | 无 | **全部下游**生成节点。文本节点自己不过期 |
| 生成节点草稿已上屏且内容变了，且当前没有提示词连线 | 是 | 无 | 自己（若已有成功）和全部下游 |
| 草稿已上屏但提示词来自连线 | 是（草稿仍存着） | 无 | **无**。下游读的是线上的文本 |
| 封口/已上屏但字符串没变 | 否 | 无 | 无 |
| 导入或替换素材成功 | 是 | 无 | 该素材的下游 |
| 连线、断开、替换、重排、增删槽 | 是 | 无 | 目标及其下游 |
| 改参数、换配方、改变体张数 | 是 | 无 | 自己（若已有成功）和下游 |
| 通过预检并入队 | 否 | 无 | 无。后端 `node.patch`：`phase=queued`、`lastRunId`、`lastTaskId`、`lastAttemptFingerprint`、`executionRevision+1` |
| 运行成功，至少一张 | 是 | **追加**新版本 | 自己变为成功或过期；当前输出变了所以下游过期 |
| 只补当前版本失败格子且指纹未变 | 是 | 不新开 | 仅当对外输出变了才让下游过期 |
| 运行失败，一张都没有 | 否（指针未变） | 不新开 | 不因失败本身再标下游 |
| 取消成功 | 否 | 无 | 无 |
| 切换变体或版本 | 是 | 无 | 下游；自己是否过期见状态机 |
| 点击失败格子 | 是 | 无 | 下游（`output` 已空） |
| 拖出变体到空白 | 是 | 新的是节点，不是版本 | 无 |
| 拖出并连到槽 | 是 | 新节点 | 目标及其下游 |
| 保存成功 | 清除脏标记 | 覆盖工程文件 | 无 |
| 自动保存成功 | 仍脏 | 只写 `.autosave.json` | 无 |

**`outputRevision`：** 从 1 起。只在对外输出身份变了时加 1。下游过期看输出身份和指纹，不看坐标。会加 1 的：文本节点 `text` 已上屏且变了；素材替换媒体；生成节点当前变体/版本切换导致 `output` 或对外正文变了；新成功落地改了当前输出；点失败格使 `output` 变空。不加 1 的：移动、标题、z、分组、视口、仅改未生效的草稿。

**复制粘贴（阶段 2 起）：** Ctrl+C 把选中节点的文档字段放进会话剪贴板，只抄 `MediaRef` / 正文，不写系统剪贴板二进制。Ctrl+V / Ctrl+D：全部新 id（节点、槽、边、分组），位置各偏移 (24, 24) 世界像素。**只有两端都在被复制集合里的边才复制**，并改指向新槽 id。只有一端在集合里的边不复制，避免悄悄占掉外面的槽。复制品若原件正在排队或运行，复制品回到静止徽章，不继承那条任务。版本和媒体引用按原样复制（同一哈希）。这是内容脏，不是新的一次生成。

## 6. 总体架构：浏览器、本机后端、ComfyUI、云端适配器

```text
[本机 Chromium]
  画布 UI（React 近处外壳 + Canvas 2D 连线/色块）
  只访问 127.0.0.1 的 HTTP / WebSocket
  不读磁盘，不持有 API Key，不直连 ComfyUI
        |
        |  令牌 + Origin 检查
        v
[canvas-backend  只监听 127.0.0.1]
  工程 JSON 校验与原子保存
  工作副本（运行与指纹的读模型）
  媒体库（哈希、派生、票据、回收）
  任务库 SQLite（不进工程目录）
  能力接口 / 调度器（本地车道并发 1，云端车道另算）
  SecretStore（Windows 凭据库；阶段 9 接正式实现）
  ffmpeg / ffprobe 子进程（找不到则降级，不启动失败）
  Comfy 客户端（内部调用，不把 /prompt 暴露给浏览器）
        |                         |
        v                         v
[用户自己启动的 ComfyUI]     [云端适配器]
  API 格式配方填槽            上传 / 轮询 / 下载
  本应用不安装、不内置它       密钥只在发请求那一次进内存
```

进程边界：

| 进程 | 谁启动 | 做什么 | 不做什么 |
| --- | --- | --- | --- |
| 浏览器标签页 | 人打开终端打印的地址 | 画布界面 | 不直接读磁盘，不调 ffmpeg，不保存密钥，不请求 ComfyUI |
| `canvas-backend` | 人在开发机上手动启动 | 工程、媒体、ffmpeg、任务库、密钥、能力接口 | 不内嵌浏览器，不安装 ComfyUI，不加载模型 |
| ComfyUI | 人按它自己的方式启动 | 本地生成 | 不是本仓库子模块。计算节点不进入用户工程 |
| ffmpeg / ffprobe | 后端按需拉起，参数数组，`shell: false` | 探测、抽帧、转代理 | 不改原片，不生成模型，不访问网络 |

默认监听 `127.0.0.1:8787`（选定端口，本会话没有检查是否被占用）。拒绝绑定 `0.0.0.0`。`Host` 只接受 `127.0.0.1:<实际端口>` 和 `localhost:<实际端口>`。

端口已被占用时进程退出，终端打印：`端口 8787 已被占用。如果画布后端已经在运行，请打开原来的地址；否则换一个端口再启动。`（把 8787 换成实际尝试的端口。）不要杀掉占用者。

变更请求的 `Origin` **必须**是下列之一，并且端口与这次实际监听/开发服一致。没有 `Origin` 的变更请求拒绝。不要把请求里的 `Origin` 反射回去。

| 允许的 Origin | 谁用 |
| --- | --- |
| `http://127.0.0.1:5173` | 开发：Vite 只听 127.0.0.1:5173 |
| `http://localhost:5173` | 同上，用户敲了 localhost |
| `http://127.0.0.1:<后端端口>` | `--serve-web` 演示切片 |
| `http://localhost:<后端端口>` | 同上 |

开发时 Vite 把 **`/api` 的 HTTP 与 WebSocket 一并代理**到后端（`ws: true`）。事件路径是 `/api/execution/runs/:runId/events`，**没有**单独的 `/ws`。可演示切片：后端 `--serve-web`，浏览器只打开 `http://127.0.0.1:8787/#token=<一次性令牌>`。

会话令牌每次启动生成，写入 `%LOCALAPPDATA%\CanvasApp\session.token`。除 `GET /health` 和 `--serve-web` 的静态文件外，接口都要令牌。媒体字节走短时票据（第 9.3 节），因为 `<img>` / `<video>` 加不了自定义头。

新建/打开工程的文件夹路径：**主路径是用户粘贴绝对路径**。可选：后端用 `powershell.exe -NoProfile -STA` 调 `System.Windows.Forms.FolderBrowserDialog`，失败则只留粘贴。**不**为此引入 Electron、Tauri 或其它 GUI 库。第一周只做粘贴即可。

`comfyBaseUrl` 写在 `%LOCALAPPDATA%\CanvasApp\app.json`，不进工程。**阶段 4** 设置页就要有这一栏和「重新检查 ComfyUI」，否则「Comfy 关掉」的演示没有填写入口。阶段 9 再加密钥，不把填地址推迟到阶段 9。

一个后端进程同一时刻只打开一个工程。应用数据目录里放单实例锁。

浏览器不接收、也不保存 API Key、底模内部图、或 ComfyUI 计算图。

## 7. 技术选型：每个决定写选定方案和被否决的方案

| 决定 | 选定 | 否决 | 否决原因 |
| --- | --- | --- | --- |
| 产品形态 | 带角色有序槽的无限画布 | ComfyUI 皮肤 / 任意工作流编辑器 | 边界：不是第二个 ComfyUI |
| 运行形态 | 本机浏览器 + 只听 `127.0.0.1` 的 Node 后端 | 第一版 Electron / Tauri；纯静态页；Python 后端 | 壳后置；静态页进不了凭据库也不能稳定代理 Comfy；前后端共享 TS 类型，不引入第二套运行时 |
| 画布内核 | **自研混合渲染**：近处 React 节点外壳，一张 Canvas 2D 画连线与远处色块 | React Flow / xyflow、Rete、LiteGraph、AntV X6 当内核 | 它们的基本形是端口对端口，会滑向第二个 ComfyUI；也没有「远处卸掉 DOM、只留色块」 |
| 白板库 | 不用 | tldraw、Excalidraw 当内核 | tldraw 文档模型是形状绑定，生成状态/有序槽/变体条要逆着 store 写；其许可证不是 MIT（画布过程稿 2026-09-22 核过公开 LICENSE 摘要，不是法务意见）。Excalidraw 是涂鸦箭头 |
| 第一版绘制层 | Canvas 2D | 第一天就上 WebGL / Pixi / Konva / Fabric | 难的是输入法、槽命中和变体条，不是精灵批处理。千节点夹具若连色块+直线都守不住预算，再单独立项换绘制层，**不换文档模型** |
| 撤销 | 命令的正反向操作，拖拽过程不入栈，栈深 100 | 整页深拷贝快照；每个 pointermove 记一步 | 快照会把媒体字段反复复制；拖拽一步撤销会被做成上百步，主线程被占满 |
| 热路径 | 平移缩放只改 `translate3d`+`scale`，pointermove 不 `setState` | 用 `top`/`left` 移动上百个节点；pointermove 里提交 React | 阶段 2 帧率目标会做不到 |
| 语言与仓库 | TypeScript 单体仓库；前端 React；后端 Node | 前后端两套语言；把 Comfy 的 Python 当后端 | 契约放共享包。本会话 Node `v24.19.0`，`node:sqlite` 可用 |
| 任务库 | SQLite 文件在应用数据目录 | 任务只放前端内存；任务库拷进工程文件夹 | 离开再回来和刷新必须靠后端；工程拷走不带走队列 |
| 媒体 | 每工程一份内容寻址库，SHA-256，派生跟工程走 | 全局哈希池；派生只放应用数据；画布播原片；缩略图失败改显示原图 | 拷走会缺文件；边界禁止播原片；缩略图失败必须可见 `partial` |
| 密钥 | Windows 凭据库 `CredWrite`；超 2560 字节才 DPAPI 到应用数据目录 | 写进工程 / `app.json` / 明文文件；为密钥上 Electron | 边界：密钥进系统凭据库。换电脑后重新填写是预期 |
| Comfy 集成 | 后端内部客户端 + API 格式配方填槽 | 浏览器直连；原样代理 `/prompt`；界面格式往返；把计算节点画出来 | 跨域、密钥进页面、变成第二个 ComfyUI |
| 本地并发 | 字面量 1，一次只向 Comfy 提交一个变体 | 可配置本地并行；把一批预先灌进 Comfy 队列 | 取消报文尚未核实；边界要求并发为 1 |
| 云端视频 | `CloudVideoAdapter` 约束字段挡在核心外；第一张用 **不联网夹具** | 在调度器里按厂商名分支；把厂商报文写进核心；没密钥还发请求 | 不编造云厂商报文；没密钥的句子是「还没有配置这一家的密钥。」 |
| 包管理 | 已安装的 npm `11.17.0` | 本阶段再引入第二套运行时或包管理器 | 减少空仓库启动摩擦 |
| 前端构建 | Vite（开发服只听 127.0.0.1:5173，代理 `/api` HTTP+WebSocket） | 双击打开静态 HTML | 需要令牌和同源。阶段 1 手工确认：带令牌能打 `GET /health` 与保存接口，另一来源拿不到令牌。**不出缩略图**（缩略图从阶段 2 夹具票据或阶段 4 生成管道才有） |

与体验预算冲突、因此禁止的实现（不是库名，是做法）：

- 每个节点放一个原生 `video` 播原片，或磁贴里自动播放。
- 远景和近景都解码原图。
- 拖拽过程中在主线程做整份工程落盘、大文件哈希、等待网络或跑 ffmpeg。
- 用估计时间驱动百分比。
- 进度只存在弹窗里，或任务数组只放在前端内存。
- 每次出变体都铺成新节点并自动重排画布。

**配方如何贴上节点。** 用户点的是能力（文生图 / 图生图 / …），不是配方文件。创建生成节点时：

1. 写入 `capabilityId`、`profileId`、`outputKind`，按描述符生成 `slots`：**每个角色创建 `minCount` 条空槽**（`required` 时 `minCount` 至少为 1）。参考图 `minCount: 1` → 默认 1 行；风格/角色参考 `minCount: 0` → 默认 0 行，用户用「添加槽」加到 `maxCount`。第一版创建后不能改能力。
2. 在 `listRecipes()` 里找该 `profileId` 且 `enabled && implemented` 的配方。
3. **恰好一张**：写入 `recipeId` / `recipeVersion`，`params` 用配方里 `userFacing` 参数的 `default`（种子的存储值是 ASCII `"random"`，界面显示「随机」）。`requiresSecret` 时写入 `secretRef: { providerId, account: "default" }`。阶段 4 只发布一张文生图配方，所以演示「点运行此节点」时节点上已有 `recipe.image.txt2img.fictional`。
4. **一张都没有**：`recipeId` 为空，运行禁用。「找不到这张配方。」或「这台机器上没有可用的配方「标题」。」
5. **多于一张**：默认选列表第一张 enabled，检查器可换。换配方是内容脏，已有成功则自己和下游过期。

检查器的参数默认值只来自 `RecipeSummary.params[].default`，**不**读 `comfy.prompt`。

生成节点高度公式（`apps/web/src/canvas/metrics.ts`，外壳和命中共用，禁止两套魔法数）：

```text

slotRow = 36
addSlotRow = 28
previewMin = 120
variantStrip = 72   // 当前版本 variants.length === 0 时为 0；看 versions[currentVersionId].variants，没有 node.variants
```

### 9.3 媒体引用

画布与工程共用这一份。路径字段要么为 `null`，要么是合法相对路径，不要用空字符串冒充。

```ts
interface MediaRef {
  kind: Exclude<MediaKind, "text">;
  relativePath: ProjectRelPath;          // 原件 blob 路径。画布不得把它设成 <video> 地址
  contentHash: string | null;            // sha256 小写 64 位；未知则为 null，不要编
  byteSize: number | null;
  mimeDetected: string | null;
  width: number | null;
  height: number | null;
  durationMs: number | null;             // 没有时长就显示「时长未知」，不要 0:00
  firstFrameRelativePath: ProjectRelPath | null;
  lastFrameRelativePath: ProjectRelPath | null;
  coverRelativePath: ProjectRelPath | null;
  proxyRelativePath: ProjectRelPath | null;   // 画布唯一允许的播放文件
  thumbRelativePath: ProjectRelPath | null;   // 近景图片只用它
}

function blobRelPath(sha256: string): ProjectRelPath {
  return `media/blobs/${sha256.slice(0, 2)}/${sha256}.blob`;
}
```

生成出来的视频，只有时长、首帧图、尾帧图、封面、代理和原文件哈希都写进媒体库之后，才进入成功版本。缺任何一件，这次不算成功，画布不改播原片。

图片近景 `img` 只请求缩略图票据。没有缩略图就用色块，不请求原图。缩略图失败：「缩略图没加载出来」，提供「重试」，不准改成直接显示原图。

媒体入库：完整字节进 `incoming/<taskId>.part` → SHA-256 → 改名到 blob。相同哈希且内容一致则复用。**阶段 4 第一条生成结果就必须走这条路径**，不得用占位原图蒙混过关。

票据只签发给当前打开文档引用的 `media/blobs` 与 `media/derived`。不给工程 JSON、任务库、回收站签发。响应支持 `Range`。有效期 **10 分钟**（选定值）。

```text
POST /api/projects/current/media-tickets
Authorization: Bearer <令牌>
Body: { "relativePath": "media/derived/…/thumb-….webp", "purpose": "thumb" | "cover" | "proxy" | "original" }
201: { "ticketId": "<随机>", "expiresAt": "<ISO-8601>" }
400: 路径不合法
403: 该路径未被当前文档引用，或 purpose=original 被画布误用来当节点 <img>
禁止在 URL 里放相对路径。purpose=original 只给检查器下载，画布 <img> 只用 thumb，<video> 只用 proxy。

GET /api/media-ticket/:ticketId
200: 字节；支持 Range
403 正文：预览地址已过期。
正在发送中的响应不要中途掐断。过期后由界面重新要票据。
访问日志丢掉 ticketId，也不记 Authorization。
```

### 9.4 能力接口

画布只依赖 `CapabilityService`。它不引用 Comfy 类名，不拼云端 URL，不读密钥。画布按钮发出的就是下面的 `RunScope`，**不要再定义 `RunIntent`**。

`CapabilityService` **没有**给浏览器用的 `markStaleFrom`。用户编辑的过期由 `packages/schema/applyStaleFrom.ts` 在画布进程计算并写入工作副本。生成落地由后端用同一函数标下游。

**谁写 `versions[]` / `output` / `phase`：** 后端是唯一写入者。流程：变体终态 → 入库 → 更新工作副本（`versions`、`output`、`phase`、指纹、`outputRevision`、`executionRevision`、`contentRevision`、下游过期）→ 立刻 autosave → 先发 `variant.finished`（条上这一格的 `seedUsed`/进度）再发 `node.patch`（上面那些字段 + 两个 revision）。画布：`variant.finished` 只更新条上的格子；**节点存储以 `node.patch` 为准**。不要只听其中一个。

拖拽（`move` 手势）期间到达的 `node.patch` **先排队**，等 `pointerup` 且 `moveNodes` 提交成功后再应用。禁止用补丁把节点打回按下时的坐标。平移/缩放不排队补丁（不改节点坐标）。

`GET /api/execution/recipes` 的 JSON 就是 `RecipeSummary[]`。**不得**包含 `comfy.prompt`、bindings、类名、密钥。浏览器不接收 ComfyUI 计算图。

| --- | --- |

### 9.5 配方

配方是安装目录里的只读 JSON，`recipes/<id>.json`。工程和节点只存 `recipeId` 与 `version`，不内嵌工作流，不内嵌 API Key。

加载器必须拒绝：

- 顶层同时有数组 `nodes` 和 `links`：`RECIPE_UI_FORMAT`。「这是 ComfyUI 的界面格式。本应用只接受 API 格式，并且要包在我们自己的配方里。」
- 顶层就是一张 API 格式 prompt 字典、但没有我们的 `id`、`slots`、`bindings`：「请把 API 格式工作流放进配方的 comfy.prompt，不要单独导入一张工作流。」

`comfy.format` 只能是 `"comfy.api"`。绑定：`concat`（文本按 order 拼接）、`set`、`byOrder`。媒体写入 prompt 之前先上传，上传失败不提交。用户看不见 `class_type`。绑定目标里的 `nodeId` 是配方内部 id，不是画布节点 id。

云端配方没有 `comfy` 段，也没有 URL 和报文体。只有槽、参数和 `cloud.constraints`。真正的 HTTP 细节留在适配器代码里。

任务库表建议：`runs`、`tasks`、`variants`、`events`。每次状态变化在一个事务里写完。进程在事务中间退出时，重启后仍是上一笔完整状态。

```ts
interface SecretRef {
  providerId: string;            // [a-z0-9._-]{1,64}，写入前小写
  account: string;               // 默认 "default"
}

interface SecretStore {
  put(ref: SecretRef, secret: Uint8Array): Promise<void>;
  get(ref: SecretRef): Promise<Uint8Array | null>;  // 只在发请求那一次进内存
  present(ref: SecretRef): Promise<boolean>;
  delete(ref: SecretRef): Promise<void>;
}
```

Windows 正式实现：`CRED_TYPE_GENERIC`，目标名 `CanvasApp:provider:<providerId>:account:<account>`。短于或等于 2560 字节走凭据库（微软文档 `CRED_MAX_CREDENTIAL_BLOB_SIZE`）。超过则 `CryptProtectData` 到应用数据目录，不要设 `CRYPTPROTECT_LOCAL_MACHINE`。查询接口只返回 `{ present: true | false }`，不回显。本会话没有调用过 `CredWrite`。

```text
PUT    /api/secrets                 { providerId, account, secret }  → 204，响应不回显
GET    /api/secrets/:providerId     → 200 { present: true|false }
DELETE /api/secrets/:providerId     → 204，不改节点上的 secretRef.providerId
```

`requiresSecret: false` 的配方（夹具、本机 Comfy）预检不查凭据库。

### 9.9 工程与工作副本 HTTP

除 `GET /health` 外都要令牌。`absolutePath` 只出现在响应和应用数据的最近列表，**不**写进 `canvas.project.json`。

| 方法与路径 | 请求体 | 成功 | 失败 |
| --- | --- | --- | --- |

| `PUT /api/projects/current` 保存 | 无正文或 `{ contentRevision }`。服务端把**当前工作副本**写入磁盘 | 200 `{ contentRevision, savedContentRevision }` | 409 冲突；400 含密钥键；507 磁盘满。不要让客户端再 POST 一份可能过期的整表去覆盖 |

| `POST /api/projects/current/media/ingest` | `multipart/form-data` 字段 `file` | 201 `{ media: MediaRef }`。**先入库，前端再用返回的 MediaRef 建节点**。失败不建节点 | 400 SVG/不支持/非法路径；413 超过 2GiB；507 磁盘满。句子见第 11.1 节 |

工作副本同步时机：与撤销命令同一拍（指针松开、文本已上屏、菜单命令）。禁止在 `pointermove` 里 PUT。不要求运行前先保存到 `canvas.project.json`。

**合并规则（阶段 1 就要写成函数，阶段 4 执行器依赖它）：**

客户端权威字段：`x y width height z title text promptDraft slots params variantCount recipeId recipeVersion capabilityId profileId outputKind groupId origin provenance secretRef kind`。用户切换当前变体时，客户端也可以写 `currentVersionId`、`activeVariantId`、`output`、`outputText`、`outputRevision`、`freshness`，但若该节点 `phase` 为 `queued` 或 `running`，这六项仍以服务器为准。

服务器权威字段（客户端 PUT **不得覆盖**）：`phase`、`progress`、`versions`、`lastSuccessFingerprint`、`lastAttemptFingerprint`、`lastError`、`runner`、`lastRunId`、`lastTaskId`、`inputsChangedWhileRunning`、`executionRevision`。入队后客户端再 PUT，只能改提示词/槽/坐标，不能把 `phase` 打回 `idle`。

`contentRevision`：客户端 PUT 必须等于服务器当前值。执行器落地会把服务器 `contentRevision` +1，并经 `node.patch` 带回；客户端先应用 patch，再带新值 PUT。入队后的全量旧文档 PUT 会 409，不会盖掉哈希。

生成落地只由后端改工作副本，再 autosave，**不**等客户端把带图的节点 PUT 回来。

### 9.10 自动保存

- 文件：`canvas.project.autosave.json`。
- 结构编辑：距上次内容修订 **1 秒**（选定间隔）写一次，内容是当时工作副本。
- **不**改 `savedContentRevision`。顶栏仍是未保存。
- 生成结果媒体指针由后端写入工作副本后立刻写 autosave，不走 1 秒、也不等客户端 PUT。
- 手动保存成功后可以删掉过期 autosave，或留着直到下次覆盖。
- 打开时：正式文件损坏但 bak 完整 → 打开 bak，「工程文件损坏，已打开上一份备份。」autosave 比正式文件新且通过校验 → 载入工作副本并标脏，「已从自动保存恢复。」两份都坏：不创建空工程盖住，「工程文件损坏，而且没有可用的备份。文件还留在原地。」
- 自动保存与手动保存冲突：手动保存以工作副本为准写正式文件；若磁盘正式文件的 `contentRevision` 已不是本次打开值，走 409，不拿 autosave 去覆盖别人。

**交互要点。** 按下阈值 4 屏幕像素。同一时刻一个手势。文本框聚焦后不开始移动；双击预览区文本才聚焦。拖拽 1:1 跟手，不许缓动。松手后一条 `moveNodes`，位移为 0 不提交。撤销一次拖拽只占一步。框选默认完全落入；Alt 相交。Ctrl+G 至少两个节点。删除正在跑的节点（本阶段还没有真跑）也必须通知执行域能取消就取消——接口先留着。命中从上到下：覆盖层 → 槽热区（连线时扩 12px）→ 近景 DOM → 远景色块 → 边（8px）→ 分组框 → 空白。连接桩热区目标至少 24×24 CSS 像素。

**难点与方案。** 中文输入法组字窗口须在插入符旁；组字时滚轮不缩放画布；上屏前 Esc 取消组字不是删节点。Windows 上 Chromium 的 Ctrl+滚轮整页缩放必须 `preventDefault`。触控板捏合若被实现成带 ctrl 的滚轮，走同一条路径。第一版不单独做触摸手势。

**可在本机演示的验收。** 二十夹具：平移、拖节点、拖连线各 3 秒，帧间隔超过 32ms 的次数目标为 0（P3，**没有叠层读数不得记通过**）。拖节点滞后目标 ≤ 1 帧（P2）。撤销一次回到起点。复制只含内部边：复制两个已连线节点，外面第三条线不跟着占槽。一百夹具走 P4（近景可带夹具预置小缩略图，经票据加载；禁止把原件当 `img.src`）。一千远：平移平均目标 ≥ 30fps，视口内只画色块和标签，不解码原图（P5）。视口内带缩略图节点目标不超过 40，再多边缘降成色块（P6）。缩放围绕光标（P7）。中文组字与撤销整句（P8，合并窗口见第 5.8 节）。150% 系统缩放下桩能点中（P9）。重叠夹具同一点选中的是槽不是组。系统「减少动态效果」时状态仍靠图标和文字分辨。

**风险。** 没有叠层就把帧率写成通过。用会触发布局的 `top`/`left` 硬撑一百节点。为赶进度引入节点图库。夹具图走原件 URL 打穿 P4。

**人周区间。** 2.5–4.5。假设：无生成管道；夹具由开发命令本地生成，预置小 webp 已按 SHA-256 放进夹具工程；不接执行器。

**演示脚本。**

### 阶段 4：执行器与文生图

**用户能做什么。** 把文本连到文生图的提示词槽，或只用草稿，点「运行此节点」（请求只含 `RunScope`，执行读工作副本上的新提示词）。立刻看见「正在交给本机队列」（P10，不要写「正在安排……」），然后排队、运行、成功或失败。成功的图：后端写入工作副本并 `node.patch`，字节按 SHA-256 入库，近景只加载缩略图票据。再跑一次（新鲜时先确认，确认后 `force: true`）会多一个版本。设置页能填写本机 ComfyUI 地址。ComfyUI 没开或地址空时看见第 11.1 节句子。缺提示词时徽章不变。本机同时只跑一个。运行中改字（已上屏进工作副本，合并不得盖掉 `phase`），这次跑完后节点过期，不自动第二跑。取消有三种终态。刷新能重新挂上。本阶段接通 `POST /api/projects/current/media/ingest`：先入库再建模材节点。空画布次句此时可写「或把图片拖进来」。

**范围。** 共享类型、配方加载器、拒绝界面格式、任务库、本地车道并发 1、Comfy 客户端（先允许替身）、`CapabilityService`、假执行器、`RunSnapshot`/`RunEvent`、点击后 100ms 目标内按钮变取消（P10）、不定进度、取消 P13/P14、离开再回来 P15、**哈希入库、进程内出缩略图、票据、`PUT /api/app/comfy-base-url`**、创建节点自动贴上唯一一张 `recipe.image.txt2img.fictional`。

**模块与目录。** `apps/backend/src/execution/`、`comfy/client.ts`、`media/` 入库与 thumb 配方、`recipes/recipe.image.txt2img.fictional.json`、浏览器 `execution/` 客户端与 WebSocket（`/api/execution/runs/:id/events`）。设置页最小：Comfy 地址。

### 阶段 5：图生图、参考图与三种运行

**用户能做什么。** 导入图片。做图生图（提示词 + 正好一张原图）。做参考图生成（至少一张参考图，可加风格参考和角色参考）。槽有序号。交换两个槽，目标过期，源不过期。一个图片输出连到两个生成节点。一次最多 4 张变体。拖到空白得到新图片节点，源条还在。改上游文本后只有下游过期，直到用户点按钮才有新运行。三种按钮行为与第 5.7 节一致。连了遮罩但配方不接受：「这张配方还不能用遮罩。」4 张里只成功一部分时失败格可见，可只补失败的，已成功种子不变。关掉后端再打开，过期节点不会自己跑。

**范围。** `img2img` / `reference` 配方与绑定（第 9.5 节）、`source_image` 与有序 `reference_image`、三种 scope 的计划函数与 `force`（第 5.7 节）、部分失败、`retryFailed`、导入图片（复用阶段 4 入库）、取消尚未开始的任务不打到 Comfy 替身、失败格点击（第 5.5 节）。

**非范围。** 视频、音频、Windows 凭据库、桌面壳、遮罩画笔。

**模块与目录。** `recipes/recipe.image.img2img.fictional.json`、`recipes/recipe.image.reference.fictional.json`；计划函数单测。

**数据与接口。** 计划规则：运行此节点只含自己；运行下游不含起点，只跑空/失败/过期，**跳过部分成功**；运行选中部分不把选区外过期上游拉进来跑，点名的新鲜节点确认后 `force: true`。成环整批不入队。跳过用中性样式，失败才用错误样式。

**交互要点。** 图生图没有「一到四张参考图」。参考图生成才使用参考图/风格/角色参考，上限各 4。多选检查器不把多个节点的参数合成一份。素材节点没有「运行此节点」。点失败格：预览错误句，`output` 空，下游过期。

**难点与方案。** 变体串行提交。第 2 个失败时默认停住后续下标。用户主徽章仍是成功或过期加副文案。`retryFailed` 指纹变了就拒绝。

**可在本机演示的验收。** 导入同一张图两次，磁盘上只有一份 blob。改提示词后下游只出现过期，无新 `POST /runs`。运行下游：没改过的分支被跳过并有中性句子；部分成功的节点被跳过，任务条可提供「只补失败的」。运行选中部分只跑选中的。部分失败「4 张里成功了 2 张」，点失败格下游过期；只补失败张时成功种子不变。重启后端，过期节点不自动跑。

**风险。** 把图生图做成参考图槽。运行下游偷偷把起点也跑了。预检失败把已有成功徽章改成失败。运行下游去补失败格，和成功徽章打架。

**人周区间。** 1.5–3。假设：阶段 4 的任务库和替身已稳定；图片解码库若装不上，用可见的 `partial` 文案，不改显示原图。

**演示脚本。**

1. 导入图片 → 图生图：提示词 + 原图槽 → 跑通（替身或真机）。
2. 参考图生成：两张参考图 + 可选风格参考，交换槽顺序，目标过期、源不过期。
3. 一个输出连两个下游。改文本，两个都过期，都不自跑。点「运行下游」（从文本）：两个过期的跑，新鲜的跳过。
4. 只选下游其中一个点「运行选中部分」：不把另一个拉进来，也不重跑上游。
5. `variantCount=4`，替身让第 2 张失败：失败格可见；只补失败；成功那张种子不变。
6. 遮罩连上但配方不接受：运行前「这张配方还不能用遮罩。」线还在。

### 阶段 6：结果版本、缩略图与工程可拷走

**用户能做什么。** 同一次节点再运行成功，看见新版本（例如「版本 2 / 共 3」），能切回旧版，旧图还在。近景图片走缩略图票据（阶段 4 已有）。把工程文件夹拷到另一路径打开，缩略图还在。故意移走一个被引用的 blob，节点「找不到原来的媒体文件」，相对路径在次句，不是裂图。查看大图时滚轮不在底下缩放画布。来源展示角色和上游节点，不是 Comfy 类名。删掉一个节点并重新打开后，原图在 `media/trash` 里而不是立刻消失。自动保存失败有句子。

**范围。** 版本切换 UI；缺失/partial 文案打磨；拷走；打开时回收隔离（不在会话内删）；损坏工程打开备份；自动保存与手动保存冲突（第 9.10 节）；`data-result-state`；带刚生成缩略图再观察 P4/P20。

**非范围。** 重新发明入库格式、视频代理、密钥、桌面壳。不要为了过帧率把缩略图全部关掉。不要把「第一次哈希」放到本阶段——那必须已经在阶段 4 发生。

**模块与目录。** 回收扫描、`media/trash`、检查器来源与版本列表。

**数据与接口。** 回收扫描必须覆盖 `output`、`outputText`、`versions[].variants[]`、拖出节点、autosave 与 bak。任一应参与的 JSON 解析失败则整次取消回收。

**交互要点。** 缩略图淡入目标 180ms；拖拽一开始就跳到终态（P20）。切换版本目标 ≤ 100ms 换缩略图，周围节点不动。缩略图失败棋盘格 +「重试」。出图不把周围节点挤开。

**难点与方案。** 杀毒软件锁文件：有限次退避，失败保留 `.part`。Windows 长路径用 `\\?\` 前缀，工程 JSON 仍只存短相对路径。

**可在本机演示的验收。** E1 版本可见且可切回。E2 一百夹具加刚生成的缩略图，出图淡入时一开始拖拽就跳终态，P4 仍要观察。E3 拷走后图片还在；工程文件无二进制、无 `test-key-not-real`、无真实密钥。E4 查看器滚轮不缩放画布。打开时无人引用进 trash；清空回收站才物理删除。

**风险。** 会话内立即删除导致撤销找不到文件。回收漏扫变体或拖出节点。缩略图失败改原图 URL。

**人周区间。** 1–2.5。假设：阶段 4–5 已能写出至少一张图的哈希与缩略图。

**演示脚本。**

1. 同一节点成功两次，切换版本 1 / 2，周围节点不动。
2. 开发者工具确认画布 `img` 的 URL 是票据且指向 derived 缩略图，不是 blob 原件。
3. 复制整个工程文件夹到另一目录打开，图还在。打开 JSON，没有二进制。
4. 移走一个 blob 再打开：「找不到原来的媒体文件」，次句正斜杠相对路径。
5. 删除节点、保存、关掉再打开：文件在 `media/trash`，不是当场没了。
6. 制造自动保存失败（目标目录只读）：横幅「自动保存失败，当前修改还在这个页面上。」手动保存仍可走第 9.9 节冲突规则。

### 阶段 7：一条图生视频

**用户能做什么。** 把一张图连到首帧，可选尾帧和提示词。选中**夹具配方**运行：成功节点上能看见时长、封面、首帧图和尾帧图芯片；播放只在覆盖层查看器里，地址只允许代理。代理没好：「正在准备预览」。选中 **`requiresSecret: true` 的桩配方**、凭据库为空时点运行：提交前「还没有配置这一家的密钥。」不发网络。缺首帧、时长不在配方档位内，同样提交前失败。过期和版本规则与图片相同。文生视频和对口型仍然禁用。导入视频文件在本阶段开放，遵守不播原片。开始一次长任务后切到别的标签两分钟再回来。

**范围。** `img2video` 描述符与槽；配方文件 `recipes/recipe.video.img2video.fixture.json`（`adapterId: example.video.fixture`，`requiresSecret: false`）；配方文件 `recipes/recipe.video.img2video.needs-secret.json`（`adapterId: example.video.needs-secret`）；ffmpeg 派生（找不到则原件仍保存，派生失败，节点 `partial`）；`data-playback="poster"`；P28/P29。检查器显示配方 `id`/`title`，不要把 adapterId 当配方文件名。

**非范围。** 文生视频、对口型、第二家厂商、Windows 凭据库正式实现。没有密钥和真实厂商授权时，**不得演示成已经出片**。夹具成功不得写某一家的名字。真实厂商只有适配器作者自己有可用授权时才替换夹具。

**模块与目录。** `execution/adapters/`；`ffmpeg/`；视频节点外壳与芯片；查看器在覆盖层。

**数据与接口。** 第 9.5 节 `CloudVideoAdapter`。夹具 `submit` 不读 `SecretStore`。桩配方 `recipe.video.img2video.needs-secret` 在 `requiresSecret && !present(secretRef)` 时预检失败。视频变体在原片、时长、首帧、尾帧、封面、代理齐之前不得 `succeeded`。`PROXY_MEDIA_FAILED` 时允许稍后只重试派生，不二次 `submit`。拟定 ffmpeg 命令见第 9.3 节。

**交互要点。** 节点矩形上不放原片。远看是带播放三角的色块。芯片在帧文件还没有时禁用。时长未知显示「时长未知」。查看器同一时间只播一个。

**难点与方案。** 本机没有 ffmpeg 是普通状态。「重新生成预览」只重跑派生。夹具 `poll` 在测试里把间隔改小。创建图生视频节点时若两张配方都 enabled：默认夹具，检查器可换成缺密钥桩。

**可在本机演示的验收。** F1：夹具路径封面+时长；DOM 没有指向原片的 `video`；缺首帧预检；提示词拖进首帧槽角色错误。F2：代理未好时平移一百夹具仍观察 P4/P29。F3：切标签两分钟再回来。F4：查看器只播代理。F5：换成 needs-secret 配方，空凭据库点运行 → 「还没有配置这一家的密钥。」网络面板无外网请求。ffmpeg 缺失：原件在，句子说明不能播放。

**风险。** 封面没好就退回原片。用封面或代理冒充首帧。让夹具也绕过「真云端必须有密钥」。把厂商报文写进核心。

**人周区间。** 2–4。区间宽是因为本机目前没有 ffmpeg、命令未核实。

**演示脚本。**

1. 图片 → 图生视频首帧，缺首帧点运行 → 「还缺首帧。」
2. 检查器确认当前配方是夹具，跑通封面、时长、首尾帧芯片。开发者工具确认没有原片 URL。
3. 代理未就绪时拖一百夹具，画布仍能平移；主句「正在准备预览」。
4. 开始任务，切走两分钟再回来；刷新；取消，终态为三种之一。
5. 卸掉 ffmpeg 配置，原件仍在，「重新生成预览」不调用 submit。
6. 换成 needs-secret 配方，不填密钥，点运行 → 「还没有配置这一家的密钥。」
7. 文生视频、对口型仍是「这一类还没接入。」

### 阶段 8：参考音频与未接入能力

**用户能做什么。** 导入音频，看见时长，选中后可以播放，未选中不自动出声。音频参考作为带角色的线；拖进参考图槽会回弹。开发用的能力列表里能看见文生视频和对口型，状态是未接入。正式工具栏没有一排可点的灰按钮。已经接入的图生视频路径仍能走。

**范围。** 音频素材节点；`audio_reference` 角色枚举已在，但没有可运行节点提供这个槽。类型留在文件格式里，避免以后推倒工程文件。

**非范围。** 对口型可跑、波形动画、音频进视频槽。若要砍范围，**整段不做**，角色枚举保留。砍掉之后，前七个阶段的验收仍然成立。

**模块与目录。** 音频节点外壳；导入 MIME `audio/*`；媒体 kind `audio`。不走视频代理。

**数据与接口。** `MediaRef.durationMs`；播放地址用后端票据。第一版不画波形；做不到便宜就只用时长。

**交互要点。** 拖拽期间不重算波形。远景只画音频色块。把音频文件在本阶段之前拖进来：「音频文件还不能导入。」

**难点与方案。** 防止工具栏堆满不能点的按钮：未接入项放在「以后再做」，点了不产生队列任务，也不出现堆栈。

**可在本机演示的验收。** G1 角色回弹，句子里是「音频参考」和「参考图」。G2 空状态「还没有音频」；有内容时显示时长；未选中不出声。G3 未接入能力人话；图生视频仍可走 F1。

**风险。** 为验收临时加会卡的动画波形。把对口型用视频剖面 if 分支硬塞。

**人周区间。** 0.5–1.5。可后移。假设：复用入库和票据，不另开存储。

**演示脚本。**

1. 拖入 wav/mp3（第 9.3 节允许的魔数），节点显示时长。未选中无声音。
2. 从音频拉线到参考图槽，回弹。
3. 打开「以后再做」，点文生视频 → 「这一类还没接入。」队列长度不变。

### 阶段 9：多厂商、密钥、失败与恢复

**用户能做什么。** 在设置页看到某提供方「已配置」或「未配置」，不回显明文。对 **`requiresSecret: true`** 的桩或真云端配方，没密钥时点运行：「还没有配置这一家的密钥。」不发请求。夹具配方不走这条。用假密钥 `test-key-not-real` 走拒绝路径：「密钥被拒绝。」在界面、复制出的错误、工程目录里搜索这串字符，零次命中。云端超过 15 秒没有心跳：主句改为「云端还在处理，上次有回应是 N 秒前」，百分比不自己增加。本地与云端任务条分段，不合成一根进度。运行中杀后端再打开：能对上的恢复；对不上的「本机服务重启过，这个任务的结果不确定」，转圈停止。云端不保证取消：「已停止在这里等待」，次句说明对方可能仍会完成，本应用不再接收那次结果。本地取消仍走三种终态。

**范围。** `SecretStore` 的 Windows 实现；设置页密钥区；云端心跳真话（P30）；同时展开的运行明细目标不超过 8 条（P31）；重启对账四条路径的测试；「只重跑失败的」只提交失败项。新厂商 = 新适配器 + 新配方，不改 `CapabilityService` 形状，不改连线方式。

**非范围。** 第二家真实厂商的报文；云端文生图；把密钥写进工程换取「拷走就能跑」。不要把 H1 拿去卡夹具配方。

**模块与目录。** `apps/backend/src/secrets/`；设置 UI；适配器替换夹具 id（仅当作者有授权）。凭据目标名见第 9.7 节。

**数据与接口。** 工程最多存 `SecretRef`（providerId + account），不是密钥。`GET` 密钥只返回 present。凭据库拒绝写入：「系统凭据库拒绝保存这把密钥。密钥没有写入工程。」禁止改写成明文文件。

**交互要点。** 设置页与错误句子里都搜不到密钥。拷贝工程到另一用户：作品和媒体在，运行云端时「没有找到这个提供方的密钥。请在这台电脑上重新填写。」删除密钥不改工程里的 providerId。

**难点与方案。** 本会话没有调用 `CredWrite` / `CryptProtectData`，也没有改文件 ACL。落地时核实 session.token 与 DPAPI 文件不是所有用户可读。若 `CredWrite` 与文档不一致，停在这一阶段处理，不要改回明文。

**可在本机演示的验收。** H1 空凭据库对 `requiresSecret: true` 的配方不发云请求；夹具仍可跑。H2 假密钥搜索零命中。H3 心跳停滞与 9 条明细折叠。H4 杀后端恢复 / 不确定终态（P16）。H5 云端取消文案与本地取消文案不混用。部分失败「只重跑失败的」成功项不闪回排队。

**风险。** 厂商错误正文把密钥回显，写入日志前必须打掉。开放代理（客户端在请求里另给 Comfy URL）——禁止。

**人周区间。** 1–2.5。假设：夹具视频已能走提交/轮询/取消；Windows 凭据库可用。真厂商替换另计，且没有授权就不做。

**演示脚本。**

1. 选中 needs-secret 配方，未填密钥运行 → 「还没有配置这一家的密钥。」网络无请求。夹具配方在同一工程里仍能跑。
2. 保存测试钥匙，工程目录全文搜索该串 → 0 命中。设置页只显示已配置。
3. 假执行器拒绝密钥 → 「密钥被拒绝。」再搜索零命中。
4. 云端任务暂停心跳 15 秒以上，百分比不爬。同时一条本地排队，任务条两段。
5. 运行中杀后端再开，转圈停止或恢复为真实状态，过期节点不自动跑。

### 阶段 10：桌面壳（后置）

**用户能做什么。** 本阶段 **什么都不做**。第一版继续用浏览器打开 `127.0.0.1`。

**范围。** 只记录以后若要做壳时的约束，避免现在引入 Electron / Tauri 依赖。

**非范围。** 安装包、更新通道、托盘、无边框窗口、系统文件对话框作为第一版前提。文件进来靠拖放和 `<input type="file">`。

**可在本机演示的验收。** 本阶段没有开始之前，不拿壳的标准卡浏览器版。一旦开始：在壳里重做 B1/B2，预算仍是 P3/P4/P5，不通过就不能说壳完成；长任务关窗再开，恢复语义与第 5.8 / 体验离开再回来相同；假密钥搜索范围加上壳日志，零次命中。

**风险。** 现在选壳会把「独立后端」和「主进程兼后端」搅在一起。静默把浏览器版的通过记录抄到壳上。

**人周区间。** **0**（本版本）。将来真做时另估 1.5–3，且必须重测预算表，不能沿用浏览器记录。

**演示脚本。** 无。阶段 1–9 的演示不依赖壳。

## 11. 贯穿全程的体验与性能预算

下表全是 **目标**，不是本次测量。本会话没有录制帧率，没有跑延迟实验。某一行的「生效」阶段还没到，就不拿它卡前面的阶段。生效之后，该行就是通过条件的一部分。没有读数不允许把帧率条记通过。一次失败不允许当场把目标改小。

## 12. 测试策略

现在不写测试代码，不选测试框架。对应阶段的界面存在之后，把同一批用例自动化。三条线都不依赖真实 GPU 出图才能把状态走完。真实出图每条能力只留一条演示，避免验收被模型速度绑架。

阶段完成要同时满足：该阶段每一条演示都有记录（通过 / 不通过 / 未观察）；预算表里从该阶段开始生效的行都至少观察过一次；视觉最低线没有退回。未观察不算通过。空白不能算完成。

### 12.1 画布交互

夹具：空、二十、一百、一千远。必须覆盖：平移三秒与缩放锚点；拖节点松手撤销重做且只占一步；框选「已选 N 个」；拖组跟手；合法槽 / 非法处回弹；中文组字与撤销整句；文本节点内滚轮不缩放画布；一千远色块且无原片 `video`；150% 系统缩放热区；减少动态效果后仍能读成败。命中顺序用固定重叠夹具。

### 12.2 任务状态机

假执行器必须能：立即成功、立即失败、一直运行直到被取消、取消时已经成功、取消后不给答复、本地队列已被占住、刷新后仍在跑、重启后任务库对不上。每一行断言用户主句，不能只断言内部枚举。

| 起点 | 动作 | 终点 | 用户必须看见 |

| 无任务 | 编辑上游文本 | 下游过期，无任务 | 「上游改过了，不会自动重跑」。没有新的 taskId |
| 无任务，槽齐 | 运行此节点 | 提交中 | 「正在交给本机队列」，按钮为取消 |

## 15. 第一周可以动手的任务拆解

仓库是空的。第一周目标对齐阶段 1 的可演示切片，并给阶段 2 留好目录，不要在第一周接模型。

**假设。** 一名熟悉 React + TS + Node 的人，Windows，本机 Node 已是 v24。不假设已有 UI 框架以外的画布库。第一周结束应能对着阶段 1 演示脚本走一遍，记录通过/不通过/未观察。

按天只是建议顺序，不是日历承诺。

1. **初始化单体仓库。** `apps/web`、`apps/backend`、`packages/schema`。TypeScript 严格模式。前后端都能 `npm` 脚本启动。前端只听 `127.0.0.1:5173`，把 `/api` 的 HTTP 与 WebSocket 代理到 8787。
2. **写死工程 schema 草案。** 把第 9.1–9.2 节的类型放进 `packages/schema`。加校验：正斜杠路径、拒绝密钥键名、`schemaVersion !== 1` 拒打开。单测用夹具 JSON，不连 UI。
3. **后端骨架。** `main.ts`：只绑 `127.0.0.1`、单实例锁、一次性令牌、`GET /health`、Host / Origin 白名单（第 6 节）。端口占用时退出并打印第 6 节那句。终端打印 `#token=` 地址。
