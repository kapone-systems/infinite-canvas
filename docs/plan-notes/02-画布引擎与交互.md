# 画布引擎与交互

本文只规定画布怎么画、怎么点、怎么撤销。模型 API、密钥存储、ffmpeg 参数、ComfyUI 的 HTTP 路径不在这里。工作区里没有既有画布代码，下面的类型都是草案，不是从现有模块摘出来的。

文中的毫秒、缩放阈值、挂载上限、历史条数，都是选定的设计目标或实现常量，不是本机测出来的帧率或容量。这次没有跑性能测试，也没有访问云厂商 API。2026-09-22 只核对过三份公开许可证页的摘要：xyflow 仓库的 LICENSE 摘要为 MIT；Excalidraw 仓库的 LICENSE 为 MIT（版权行 2020 Excalidraw）；tldraw 仓库的 LICENSE.md 标题是 “tldraw license”，不是 MIT。tldraw 那份摘要写明：开发环境可以改、可以打包，生产环境要另有试用或商业协议和 License Key；不能关掉 key 检查、不能去掉声明、不能把它当成独立产品发行；文本还写到可以强制水印和用量限制，并可能把用量数据发给 tldraw。这不是法务意见，采纳任何第三方内核之前要再读一遍原文。

写作时 `docs/plan-notes/` 下还没有产品、执行、媒体、体验那四份说明。文末的依赖是画布向它们要的合同，不是对已有段落的摘录。

## 1. 结论

推荐自研混合渲染，不把现成节点图库或白板库当成内核。

- 浏览器里用 TypeScript 和 React。节点外壳（标题、文本、槽、变体条、按钮）是 DOM，因为中文输入法必须走真正的输入框。
- 平移和缩放只改世界层一个 `translate3d` + `scale`，热路径上不调用 `setState`。
- 连线、远处色块、点阵背景画在一张覆盖视口的 Canvas 2D 上。第一版不引入 WebGL、Pixi、Konva、Fabric。
- 文档状态和撤销栈由我们自己的 `EditorStore` 持有。撤销记命令的正向和反向操作，不记整页快照。
- 近处（缩放 ≥ 0.8）才挂节点 DOM 和缩略图。远处只画色块。视频节点只画封面，画布上不放原片。
- 一百个节点是正常工作规模：近景下挂视口里那一批完整外壳。一千个节点不许挂成一千个 DOM；同时挂载的完整外壳硬顶为 120，其余只留在数据和色块里。

否决 React Flow / xyflow、Rete、LiteGraph、AntV X6 作为内核，是因为它们的基本形是「端口对端口」。本产品的基本形是「有角色的有序槽」和「收在节点内部的变体条」。把槽伪装成端口，界面会滑向第二个 ComfyUI。它们也没有「远处卸掉 DOM、只留色块」这条路径，一千个带图节点会先死在 DOM 上。许可不是否决 xyflow 的原因。

否决 tldraw、Excalidraw 作为内核。tldraw 的相机手感好，但文档模型是形状和绑定，生成状态、有序槽、变体条、过期标记都要逆着它的 store 再写一遍；许可证也不是 MIT，不能当默认依赖。Excalidraw 是 MIT，但是涂鸦箭头，不是带槽的生成节点，笔画风格和这个产品相反。

否决「第一天就上 WebGL 场景图」。难的是输入法、槽的命中和变体条，不是精灵批处理。WebGL 只作为以后的退路：千节点夹具若在「只画色块和直线」时仍然守不住第 14 节的目标，再单独立项换绘制层，不换文档模型。

## 2. 渲染分层

视口是一个铺满画布区域的容器，`touch-action: none`。从底到顶四层：

1. 背景层。一张不随世界缩放的 Canvas，画屏幕空间的点阵。间距 24px，每 4 格一条稍亮的线，颜色是白色、不透明度 0.06。缩放 &lt; 0.3 时不画点阵。不要用几千个 DOM 点。
2. 色块层。同一张或紧挨着的第二张 Canvas，只画当前不挂 DOM 的节点矩形和直线边。`pointer-events: none`。
3. 世界层。一个 div，`transform-origin: 0 0`，transform 由相机算出。近景节点是这个 div 里的 React 子树。层本身不接收指针，节点根元素才接收。
4. 覆盖层。橡皮筋、框选矩形、拖拽幽灵、指针旁的短提示、右键菜单、视频预览。预览不进世界 transform，避免越放大预览越大。

边和色块的 Canvas 按屏幕像素缓冲，`width = clientWidth * min(devicePixelRatio, 2)`。不要按世界尺寸去开一张巨大画布。每帧先清屏，再画视口里的色块和边。相机拖动过程中边用直线；松手后的下一帧改回三次贝塞尔。这是降载策略，不是已测数据。

节点内部的 DOM 结构固定，方便命中和布局共用同一组常量（第 5 节）：

- 顶栏：标题、状态芯片。顶栏是拖拽手柄。
- 槽区：只在生成节点、且缩放 ≥ 0.8 时出现。
- 预览区：文本框、缩略图、视频封面或空状态。
- 变体条：只有生成节点且 `variants.length > 0` 时出现。

画布模块建议单独放在 `apps/web/src/canvas/`，与执行器、媒体库分开。内部至少切开这些文件，避免写成一个巨大组件：`coords.ts`、`metrics.ts`、`document.ts`、`history.ts`、`spatialIndex.ts`、`hitTest.ts`、`gestures.ts`、`EdgeCanvas.ts`、`NodeChrome.tsx`、`EditorStore.ts`。仓库总目录由总方案决定，这里只要求画布不要把队列、密钥和 ffmpeg 放进上述文件。

## 3. 坐标、相机、平移与缩放

世界坐标的单位是缩放为 1 时的 CSS 像素。原点没有业务含义，节点可以落在负坐标。相机记录的是视口中心所对应的世界点，加上缩放：

```ts
interface Camera {
  x: number;
  y: number;
  zoom: number;
}
```

换算：

```text
screenX = (worldX - camera.x) * zoom + viewportWidth / 2
screenY = (worldY - camera.y) * zoom + viewportHeight / 2
```

反向用同一公式解出世界坐标。所有命中、落点和撤销里的 `x/y` 都用世界坐标。屏幕坐标只活在一次事件里。

缩放范围是 0.08 到 2.5。滚轮以指针下的世界点为锚：该世界点在缩放前后对应同一个屏幕位置。到达上限或下限时不再改变缩放，不弹窗。

平移：

- 按住空格再按主键，或按中键，进入平移。光标是抓手。
- 平移直接写世界层的 transform，不经过 React 状态。
- 松手后把最终相机写进会话。平移不产生撤销记录。

缩放：

- 指针在画布上时，滚轮缩放，并 `preventDefault`，避免 Windows 上 Chromium 把 Ctrl+滚轮当成整页缩放。没有按 Ctrl 时，只要指针在画布背景或节点上且不在可滚动的文本框、变体条里，也由画布消费滚轮。
- 文本框内部、以及已经溢出的变体条，滚轮交给它们自己滚动，并阻止冒泡。变体条没有溢出时，滚轮继续缩放画布。
- 触控板捏合若被浏览器实现成带 ctrl 的滚轮，走同一条路径。第一版不单独做触摸手势。开发机是 Windows，交互以本机 Chromium（Edge 或 Chrome）为准。没有做跨浏览器实测。

适配视图：Ctrl+1 把相机动画到「当前选中节点的包围盒，留 64 世界像素边」。没有选中时，适配全部节点。没有节点时回到 `{x:0,y:0,zoom:1}`。Ctrl+0 把缩放设为 1，中心点不变。这段相机动画 200ms，ease-in-out，任何指针按下都取消动画并立刻采用该指针的结果。`prefers-reduced-motion: reduce` 时动画时长为 0。

相机的持久字段是工程里的 `viewport`，重新打开时恢复。它不属于撤销栈。写盘失败是媒体与工程领域的事；画布只在收到失败时在顶部显示对方给的句子。对方没给句子时显示「视图没能记住，下次打开会回到默认位置」。节点编辑不受这个失败影响。

空画布的背景中央有一行弱提示：「从左侧加上文本或生成，或把图片拖进来」。一旦存在任意节点，这行隐藏。空状态不是模态。

## 4. 文档字段与会话字段

文档和会话分开。文档会进工程文件。会话（相机的进行中手势、选择、悬停、撤销栈）不进工程文件。重新打开工程后，撤销和重做都是空的，按钮为灰，按快捷键没有任何对话框。

```ts
type MediaKind = "text" | "image" | "video" | "audio";

type Role =
  | "prompt"
  | "reference_image"
  | "first_frame"
  | "last_frame"
  | "style_reference"
  | "character_reference"
  | "mask"
  | "audio_reference";

type RunStatus =
  | "idle"
  | "queued"
  | "running"
  | "succeeded"
  | "failed"
  | "cancelled";

interface MediaRef {
  kind: Exclude<MediaKind, "text">;
  /** 工程内相对路径，只用正斜杠。画布不拼磁盘绝对路径，也不接受反斜杠。 */
  relativePath: string;
  contentHash: string | null;
  width: number | null;
  height: number | null;
  durationMs: number | null;
  posterRelativePath: string | null;
  proxyRelativePath: string | null;
  thumbRelativePath: string | null;
}

interface Slot {
  id: string;
  role: Role;
  /** 从 0 起，重排后必须连续。 */
  order: number;
  edgeId: string | null;
}

interface Variant {
  id: string;
  media: MediaRef | null;
  runStatus: Exclude<RunStatus, "idle">;
  errorMessage: string | null;
  createdAt: string;
}

interface CanvasNode {
  id: string;
  kind: "text" | "image" | "video" | "audio" | "generation";
  title: string;
  x: number;
  y: number;
  width: number;
  height: number;
  z: number;
  groupId: string | null;
  /** 纯素材节点为 null。生成节点指向能力 id，例如 txt2img。 */
  capabilityId: string | null;
  /** 文本节点的正文。 */
  text: string;
  /** 生成节点上的本地提示词草稿。槽上连了提示词时不使用它，见第 7 节。 */
  promptDraft: string;
  slots: Slot[];
  variants: Variant[];
  activeVariantId: string | null;
  /** 当前向外提供的媒体。文本节点不使用此字段。 */
  output: MediaRef | null;
  runStatus: RunStatus;
  freshness: "fresh" | "stale";
  /** 排队或运行中又改了输入时为 true。完成事件据此决定落地后是过期还是新鲜。 */
  inputsChangedWhileRunning: boolean;
  errorMessage: string | null;
  /** 执行器没给进度时为 null。画布不自己编百分比。 */
  progress: { ratio: number | null; label: string | null } | null;
  /** 只用于芯片文案，画布不据此调度。 */
  runner: "local" | "cloud" | null;
}

interface Edge {
  id: string;
  sourceNodeId: string;
  targetNodeId: string;
  targetSlotId: string;
  role: Role;
}

interface Group {
  id: string;
  title: string;
  childIds: string[];
}

interface EditorDocument {
  version: 1;
  nodes: Record<string, CanvasNode>;
  edges: Record<string, Edge>;
  groups: Record<string, Group>;
}
```

标识用 `crypto.randomUUID()`。节点默认尺寸：文本 280×180，图片宽 280、高度按宽高比且最小 80，视频宽 320、高度按封面宽高比且最小 180，音频 280×96，生成节点宽 320、高度由第 5 节的公式算出。用户改过的宽高要保留。

分组没有自己的 x/y。框是子节点包围盒向外扩 24 世界像素。这样不会和子节点坐标做成两份真相。

选择、悬停、手势、撤销栈放在 `EditorSession` 里。选择是三组 id：`nodeIds`、`edgeIds`、`groupIds`。一份工程同时只有一个会话。不做协同光标。

能力描述符不是画布发明的执行协议，但画布要能在执行器还没接上时画出第一刀。下面这份预设只用于演示和单测夹具。一旦执行领域传入同 id 的描述符，以描述符为准。

```ts
interface SlotSpec {
  role: Role;
  min: number;
  max: number;
  required: boolean;
}

interface CapabilityDesc {
  id: string;
  label: string;
  output: MediaKind;
  slots: SlotSpec[];
  /** 画布原样显示。没有就用「顺序就是交给生成时的顺序，上面的先交。」 */
  orderHint?: string;
}
```

演示预设：

| id | 输出 | 槽 |
| --- | --- | --- |
| text / image / video / audio 素材 | 与种类相同 | 无 |
| txt2img | image | 提示词 1 个，必填 |
| img2img | image | 提示词 1 个必填；参考图最少 1 个、最多 4 个，必填 |
| img2video | video | 首帧 1 个必填；尾帧 1 个可选；提示词 1 个可选 |

「参考图」不是第四种生成器。它是槽角色，加上用户放进来的图片节点。角色参考、风格参考、遮罩、音频参考第一版就留在 `Role` 里，添加菜单只列出当前能力描述符允许的角色。描述符没写 `max` 时按 1 处理。

角色的显示名和接受的媒体种类固定如下。边的颜色是设计令牌，不是测量值。

| role | 显示名 | 接受 | 边颜色 |
| --- | --- | --- | --- |
| prompt | 提示词 | text | #d4a017 |
| reference_image | 参考图 | image | #4c8dff |
| first_frame | 首帧 | image | #2fbfb5 |
| last_frame | 尾帧 | image | #3ec6e0 |
| style_reference | 风格参考 | image | #a07be0 |
| character_reference | 角色参考 | image | #e07aaa |
| mask | 遮罩 | image | #9aa0a6 |
| audio_reference | 音频参考 | audio | #5cbf7a |

视频输出在第一版不能接到任何槽。提示写：「视频结果现在还不能接到别的槽上。要用画面的话，拖首帧或尾帧。」首帧和尾帧是视频节点上的两枚图片芯片，种类按 image 处理。遮罩第一版只接受一张图，不在画布里做画笔。

## 5. 布局常量

外壳和命中测试共用 `metrics.ts`，禁止一边用 CSS 一边用另一套魔法数。

```text
header = 40
slotRow = 36
addSlotRow = 28
previewMin = 120
variantStrip = 72   // variants.length === 0 时高度为 0
pad = 8
```

生成节点高度 = header + 槽行总高 + addSlotRow + previewMin + variantStrip + pad。输出锚点固定在节点局部坐标 `(width, 48)`，不随变体条变高而跳。槽锚点在左边缘，y = header + order * slotRow + slotRow / 2。远景色块用节点的 x、y、width、height，锚点用同一公式，这样卸掉 DOM 之后线不会挪地方。

近景 DOM 必须按这些常量排，不要用测量去改文档坐标。测量只允许出现在开发期断言里：DOM 锚点和公式相差超过 1 世界像素时在控制台报警，不改用户数据。

## 6. 命中测试

空间索引是均匀网格，格子边长 512 世界像素。节点 id 登记在它的矩形覆盖到的格子里。提交移动命令时更新登记。拖拽过程中的临时位移不改索引，命中拖拽中的节点时用临时矩形。

一次指针按下按这个顺序，命中即停：

1. 覆盖层里的菜单、预览、提示。这些是普通 DOM。
2. 正在连线或拖变体时，把兼容槽的命中盒向四周扩 12 屏幕像素。先测槽，再测别的。
3. 近景已挂载节点内部：文本框、按钮、变体单元格、槽的握把、槽体、顶栏、缩放手柄、输出锚点。用 DOM 命中，再映射回节点 id 和部位。
4. 远景或未挂载节点：用世界坐标查网格，点落在矩形内的，取 z 最大的。平局取 id 字典序较大的，保证稳定。
5. 边：指针到折线的屏幕距离 ≤ 8。多条都在容差内时，取最近的；已选中的边若在容差内则优先它，避免被旁边的线抢走。边画在节点下面，点在节点身上时不会选中边。
6. 分组框的标题条和留白。点在子节点上不算点在分组上。
7. 空白背景。

输出锚点的热区是 16×16 屏幕像素，画出来的圆可以是 8 像素。远景色块的输出热区是右缘中点附近 16 屏幕像素，不要求先放大就能开始拉线，但松手规则见第 8 节。

选中节点时把绘制顺序临时抬高，让它盖住重叠的邻居。这个抬高不写入 `z`，也不进撤销。只有菜单里的「置于顶层」「置于底层」才改 `z` 并形成命令。

点空白会清掉选择，除非这次按下最后变成了框选或平移。

命中函数保持纯函数：`(doc, session, worldPoint, screenPoint) => Hit`。单测不挂 React 也能跑。

## 7. 手势总则

指针只用 Pointer Events。按下时对画布容器 `setPointerCapture`，拖出浏览器窗口仍继续，直到 pointerup 或 pointercancel。右键不平移，它打开菜单。

统一状态：

```text
idle
pending        已按下，还没超过阈值
pan            平移相机
marquee        框选
move           移动节点
connect        拉线
extract        从变体条拖出
reorder-slot   重排槽
resize         改节点宽高
```

从 pending 离开的阈值是 4 屏幕像素。没超过阈值就松开，算点击，不算拖拽。按下后窗口失焦或 pointercancel：手势作废，文档不改，不产生命令。用户能看见的只有幽灵或橡皮筋消失。

进行中的移动、拉线、抽出、重排、缩放，每帧最多吃一次指针位置（`requestAnimationFrame` 合并）。禁止在 pointermove 里 `setState`。临时位移放在会话的 gesture 上，画布直接改 DOM style 或重画 Canvas。

同一时刻只有一个手势。第二个指针按下时忽略，直到当前手势结束。

节点正文的文本框在获得焦点后，不开始移动手势。双击预览区里的文本才聚焦；单击顶栏仍然是选择和准备拖拽。生成节点的提示词草稿框同样吃掉按下事件。Windows 中文输入法：`compositionstart` 到 `compositionend` 之间不提交命令，也不要在 `compositionupdate` 里把组字当成一次编辑。

## 8. 拖拽节点

按下部位是顶栏、预览区的非文本区域、或远景色块，且当前工具不是抓手、也没按空格：

1. 若该节点不在选择里，且没按 Shift，选择改成只有它。这个选择变化不进撤销。
2. 超过 4 像素后进入 move。若按下时按着 Alt，先复制一份选择（新 id，位置先与原来重合），再移动复制品，原来的留在原地。复制规则与第 10 节的粘贴相同。整个「复制并移动」是一条命令。
3. 移动的是当前选择展开后的节点集合。选中的是分组时，展开成它的全部子节点。子节点相对位置不变。
4. 按住 Shift 时，位移锁在水平或垂直里位移更大的那一轴。
5. 与其他节点的边或中心线距离 ≤ 6 屏幕像素时吸附，并画一条对齐辅助线。辅助线不进文档。被拖的节点彼此之间不互相吸附。
6. 指针进入视口边缘 24 像素内时，相机向该方向自动平移。渗透越深越快，最快每帧 24 屏幕像素。自动平移不进撤销。节点的世界坐标要加上相机的变化，使节点仍留在指针下。
7. 松开时若世界位移不为 0，提交一条 `moveNodes`。标签是「移动 N 个节点」。位移为 0 则不提交。
8. 分组框不单独存储位置。子节点移动提交后，框用新的包围盒再画。

拖拽进行中，已挂载节点用 CSS transform 显示临时位置；未挂载的色块由 Canvas 按临时位置重画。边的两端若在被拖集合里，或只有一端在，都按临时位置重画。

失败与边界：

- 自动平移到了缩放不变、坐标可表示的范围即可。不设世界边界，也不要因为坐标变大而报错。
- 若提交时不变量检查失败，整条命令丢弃，节点弹回按下时的位置，指针旁提示「这一步没能完成，画布还保持原样。」
- 拖拽过程中执行器如果送来了结果补丁，先排队，等松开并成功提交移动之后再应用。避免补丁和临时位置打架。

远景色块也可以拖。不因为没挂 DOM 就禁止移动。

## 9. 连线与有序槽

一条边从源节点的输出锚点出发，落到目标节点的一个槽。槽在同一时刻最多一条边。一个输出可以连到很多个槽。不允许连到自己。不允许形成有向环；提交前从目标节点沿现有边做深度优先搜索，能回到源节点就拒绝。

槽的顺序是用户可见的，从上到下，显示成 1 起的序号。边记在 `targetSlotId` 上，不记序号。重排槽只改 `order`，边跟着槽走，边的 id 不变。

开始拉线有两个方向，结果相同：

- 从输出锚点按下并拖出。
- 从某个槽体按下并拖出（不是槽左侧的握把；握把是重排）。这条线的目标槽就是这个槽，松手时要落在某个节点的输出锚点上。

拖动时画橡皮筋，起点是锚点，终点是指针的世界坐标。每帧最多更新一次。

松手时的判定顺序：

1. 落在兼容槽的扩展命中盒里：占用这个槽。若该槽已有边，替换它（旧边删除，新边写上，一条命令，标签「更换槽上的连线」）。若落点更接近两条槽之间的缝而不是槽体，则插入一个同角色的新槽再连上，原有槽的 order 后移。缝的命中只在该角色还没到 `max` 时有效。
2. 落在远景或中景色块上：不猜测槽。橡皮筋消失，提示「放大到能看清槽之后再松开」。不自动放大，避免按下途中画面突然跳。
3. 落在源节点自己身上：提示「不能连到自己」。
4. 会成环：提示「会形成循环，已取消」。
5. 种类不合：提示「不能把「视频」接到「提示词」槽」，引号里的两个名字用这次的源种类和槽的显示名。该槽闪一下边框，不位移节点。
6. 该角色已达 max，且不是替换已有槽：提示「这个角色的槽已经满了」。
7. 落在空白或其他节点的非槽区域：提示「要连到槽上，已取消」。不创建新节点。

取消时文档不变，没有撤销记录。成功时一条命令里同时写边、槽的 `edgeId`，以及第 12 节的过期标记。

从槽里把已连上的芯片拖走：松手在空白处等于断开；松手在另一个兼容槽上等于把这条边挪过去。也是一条命令。若目标槽已占用，按替换处理。

添加槽：槽区底部的「添加槽」打开菜单，只列出该能力还没达到 max 的角色。选中后追加一个空槽，命令标签「添加槽」。空槽显示角色名和「必填」或「可选」。必填只是外观，画布不在点击运行时做第二套校验，避免和执行器的规则分叉。

删除空槽是一条命令。删除已连槽会同时断开边，并让该生成节点及下游过期。

键盘：焦点在某个槽上时，Alt+上/下 重排，Delete 只断开边并保留槽，Backspace 在空槽上删除槽。这些都是命令。

重排手势：拖握把，其他槽让出 120ms 的位置动画。松开后一条 `reorderSlots`，标签「调整槽的顺序」。动画被 `prefers-reduced-motion` 关掉。

兼容表（源的输出种类 → 槽）：

| 源 | 可落入的槽 |
| --- | --- |
| text | 只有提示词 |
| image | 参考图、首帧、尾帧、风格参考、角色参考、遮罩 |
| audio | 只有音频参考 |
| video | 无。只能改拖它的首帧或尾帧芯片 |

生成节点的输出种类看能力描述符的 `output`，不看它有没有已经跑完。还没有结果时也允许连线。槽上显示「已连接，对方还没有结果」。若描述符说输出是 image，而当前激活变体的媒体却是别的种类，以变体的实际种类为准来拒绝或接受，并在槽上显示实际种类。这样不会把一条视频结果塞进图片槽。

提示词的取值规则，画布和执行器必须共用同一个纯函数 `resolvePrompt(doc, nodeId)`：

- 该节点有提示词槽且槽上有边：用源文本节点的 `text`。源是空字符串就用空字符串，不用本地草稿顶上。输入框只读，框下写「提示词来自连线」。
- 没有这条边：用该节点的 `promptDraft`。
- 文本节点自己的输出就是它的 `text`，不经过这个草稿。

媒体槽共用 `resolveSlotMedia(doc, slotId): MediaRef | null`，读源节点的 `output`。执行器不要自己再解释一套「没连上就用草稿」。

## 10. 变体条，以及拖出新节点

变体默认只出现在生成节点底部的横条里。一次运行返回多张图时，全部追加进这条，不铺成多个节点。

单元格至少 64×64 屏幕像素（近景下）。当前变体有 2px 环和「当前」两个字。失败的格子是红标，不自动变成当前。排队和运行中的格子显示同一节点的进度状态，不解码图片。横条溢出时可以横向滚动，滚动位置不进撤销。

点击（没超过拖出阈值）：

- 把该变体设为 `activeVariantId`，并更新节点 `output`。一条命令，标签「切换当前变体」。
- 若该变体有媒体，下游生成节点标成过期，预览换成这张缩略图，120ms 交叉淡化。不自动运行。
- 若该变体失败且没有媒体：仍允许点选，以便在预览区读 `errorMessage`。`output` 变为 null，下游照样过期。预览区显示错误句子，没有句子时显示「生成失败，没有更多说明」。
- 排队或运行中的格子可以点选来看进度，但不改变 `output`，也不标过期。

拖出新手势，按这个顺序判定，避免和横条滚动打架：

1. 在单元格上按下。
2. 移动仍在变体条矩形内，且主要是横向：交给横条滚动，不进入抽出。
3. 指针离开变体条矩形超过 8 屏幕像素，或按下时就按着 Alt：进入 extract。排队中、运行中、或没有 `media` 的格子不能进入。提示分别是「还在生成，生成完才能拖出去」和「这个变体没有媒体，不能拖出去」。不产生命令。
4. 幽灵跟着指针。幽灵是封面或缩略图的一个副本，比原格大约 1.04 倍，带阴影，角上有「+」。原格保持原样、不淡出，因为变体并不离开横条。
5. 松开位置按下面三条处理，成功与否都先拿掉幽灵。

松开：

- 落在另一个节点的兼容槽上：创建一枚新的素材节点，并创建一条进该槽的边。这是一条命令，标签「把变体抽成节点并连到槽」。新节点放在目标节点左侧 24 世界像素处，避免盖住目标。新节点的种类等于变体媒体的种类，`output` 与变体引用同一 `MediaRef`（同一相对路径和哈希），不复制字节。源节点的变体条、当前变体、`output` 都不变，因此下游不会因为这次抽出而过期。槽上原有的边按第 9 节的替换规则处理，并让目标节点及其下游过期，因为目标的输入变了。
- 落在空白背景：只创建素材节点，放在松开的世界坐标，选中它。一条命令，标签「把变体抽成节点」。不连线，不标过期。
- 落回源变体条、落在节点身上但没进槽、或种类不合：不创建节点。提示「没有落到槽上，已取消」或第 9 节的种类拒绝句。没有命令。

新素材节点没有槽、没有变体条、不能「运行此节点」。它的下游若以后连出去，移动它不过期，替换它的媒体（重新拖入文件盖掉）才过期。

视频变体抽出去变成视频节点，画布上仍只显示封面。首帧、尾帧芯片使用同一套 extract 手势，但新节点种类是 image，媒体引用由媒体领域返回的那一帧图片承担。芯片在还没有帧文件时显示「封面还没好」同一级别的禁用：首帧未就绪就显示「首帧还没好」，不能拖。

这个「抽出后横条里仍然留着」是有意的，和第 16 节的取舍写在一起。幽灵上的「+」用来说明这是抽出一份引用，不是把变体抠走。

撤销抽出：删掉新节点和它带来的那条边，源变体条保持原样。若当时替换过目标槽上的旧边，旧边一并回来。这些都在同一条命令的反向操作里，不靠整页快照。

## 11. 选择、分组、复制

点击节点：只选它。Shift+点击：切换它是否在选择中。点击边：只选那条边。Shift+点击边：把边加进选择或移出。框选不选边，否则一拖会卷进所有穿过矩形的线。

框选：在空白处按下并超过 4 像素。默认要求节点矩形完全落在框内。按下时按着 Alt 则改为相交即选中。Shift+框选是追加，不是替换。框是覆盖层上的矩形，不进撤销。松开后只改会话里的选择。

分组：

- Ctrl+G：选择展开后的节点数 ≥ 2 才创建分组。不足时提示「至少选中两个节点才能成组」，没有命令。
- 新分组的标题默认是「分组」。双击标题改名，改名不过期，一条命令，和文本编辑一样合并。
- 点击分组标题或框的留白：选择该分组，工具栏显示标题和子节点个数。
- 点击子节点：只选子节点，不升级成选中整个分组。
- 拖标题或留白：移动全部子节点，一条移动命令。
- 拖子节点：只移动子节点，框随后重算。
- Ctrl+Shift+G 或菜单「解散分组」：删掉分组记录，子节点和边都留着。一条命令。
- 对选中的分组按 Delete：删除分组、全部子节点、以及任何一端落在这些节点上的边。一条命令。每个会话第一次这样删时，指针旁提示一次「分组和里面的节点都删了，可以撤销」，不阻断。
- 删除节点后若某分组剩下不足 2 个子节点，同一条删除命令里解散该分组。

分组不影响连线含义，也不是执行单元。运行选中部分时，若选择里有分组，先展开成子节点再交给执行器。

复制与粘贴：

- Ctrl+C 把选中节点的文档字段放进会话剪贴板，不写系统剪贴板的二进制。媒体只抄 `MediaRef`。
- Ctrl+V 或 Ctrl+D：新 id，位置各偏移 (24, 24) 世界像素。两端都在被复制集合里的边一并复制并指向新槽 id。只有一端在集合里的边不复制，避免悄悄占掉外面的槽。一条命令。
- 系统剪贴板若是文件拖放或粘贴文件，走第 13 节的导入，不走节点复制。

全选 Ctrl+A 选中文档里全部节点 id，不管在不在视口里。不要为了全选去挂载 DOM。工具栏写「已选 N 个」。

Delete 或 Backspace：焦点不在输入框里时，删除选中的节点和选中的边。删除节点时把它两端的边一并删除。一条命令，标签「删除 N 个节点」或「断开连线」。若其中有 `runStatus` 为 queued 或 running 的节点，画布照样删，并通知执行领域「这些 id 已删除，能取消就取消」。节点不留幽灵。随后若结果才到达，丢弃该结果，不把节点复活。取消失败不归画布弹错；执行领域若要说话，用它自己的句子。画布不再把节点画回来。

## 12. 撤销：命令，不是整页快照

一次用户动作在松开、失焦或合并窗口结束时，最多产生一条历史记录。记录里是操作列表，不是文档的前后两份拷贝。

```ts
type Op =
  | { op: "set"; path: string; value: unknown; prev: unknown }
  | { op: "put-node"; node: CanvasNode }
  | { op: "drop-node"; id: string; node: CanvasNode }
  | { op: "put-edge"; edge: Edge }
  | { op: "drop-edge"; id: string; edge: Edge }
  | { op: "put-group"; group: Group }
  | { op: "drop-group"; id: string; group: Group };

interface HistoryEntry {
  id: string;
  label: string;
  redo: Op[];
  undo: Op[];
  coalesceKey?: string;
  /** 只影响会话选择，不写进工程文件。 */
  selectAfterRedo: string[];
  selectAfterUndo: string[];
}
```

`set` 的 path 是文档内部路径，例如 `nodes.${id}.x`。反向操作就是把 `prev` 写回去。`put-*` 的反向是对应的 `drop-*`，drop 里留着被删对象，所以撤销删除能原样放回，包括槽和变体。不把缩略图像素放进操作。媒体只以 `MediaRef` 的字段出现。

应用必须是事务：先在副本上折叠操作，再跑第 15 节的不变量。失败就丢弃副本，文档保持原样，提示「这一步没能完成，画布还保持原样。」成功才替换文档并把记录推入过去栈，同时清空重做栈。外部补丁（执行器送来的状态和变体）不是用户命令：直接改文档，不推入撤销栈，也不清空重做栈。

合并规则：

| 动作 | 是否进栈 | coalesceKey | 何时封口 |
| --- | --- | --- | --- |
| 平移、缩放、悬停、框选、点选、抬高绘制顺序 | 否 | — | — |
| 拖拽移动或 Alt 复制拖拽 | 是，整次一条 | 不跨手势合并 | pointerup |
| 方向键轻推 | 是 | `nudge:` + 选中 id 排序后拼接 | 距上次轻推超过 400ms |
| 文本或标题或提示词草稿 | 是 | `text:` + 节点 id + 字段名 | 失焦，或最后一次输入后 600ms，或插入了别的种类的命令 |
| 输入法组字 | 否，等 compositionend | 与文本相同 | compositionend 之后才进入上面的 600ms |
| 切换当前变体 | 是，每次点击一条 | 不合并 | 立即 |
| 连线、断开、重排槽、抽出变体、成组、解散、删除、粘贴 | 是，每次一条 | 不合并 | 手势结束或按键当时 |

栈深 100 条。超过时丢掉最旧的一条。这个深度是常量，不是测出来的内存上限。一条「移动一千个节点」只存一千对坐标，可以接受。禁止用「每次指针移动深拷贝整个 EditorDocument」来实现撤销。

撤销和重做只动文档操作和 `selectAfter*`。不恢复相机。撤销一条删除后，被恢复的节点处于选中。若反向操作引用的 id 已经不在文档里（例如用户删了节点，执行器又在外部补丁里清过相关字段），跳过无法应用的操作；若一条都没应用成功，不把文档改坏，提示同一句「这一步没能完成，画布还保持原样。」

输入法与文本合并期间，节点上可以显示草稿。封口时才把前后字符串写成一条 `set`。封口前按 Esc：取消这次未封口的文本合并，恢复聚焦时的字符串，不留半条历史。

执行器后来的状态可以盖过芯片显示，但不会因此删掉用户的撤销记录。例如用户撤销了提示词，运行中的任务仍按提交时的输入跑完；落地规则见第 13 节，可能把节点标成过期。这不是撤销失败。

## 13. 过期，以及画布上的运行状态

上游修改只把下游标成过期，画布里没有任何路径会去调用运行。没有 `useEffect` 监听输入变化来跑图。

会标过期的命令，在同一条操作列表里写下 `freshness` 和必要时的 `inputsChangedWhileRunning`：

| 操作 | 过期范围 |
| --- | --- |
| 移动、缩放节点、改标题、改 z、成组、解散、抽出变体但没接到槽上 | 无 |
| 修改文本节点的 text，或修改生成节点的 promptDraft（且当前确实在用草稿） | 该节点若是生成节点则包含它，再加上全部下游生成节点 |
| 连接、断开、替换、重排槽 | 目标生成节点和它的下游生成节点 |
| 切换当前变体导致 output 变化 | 该节点的下游生成节点。该节点自己的这次结果不过期 |
| 用新文件盖掉素材节点的媒体 | 该素材的下游生成节点 |

下游的算法（画布标过期、以及「运行下游」按钮是否可点，都用这一份）：

```text
collectDownstream(doc, seeds):
  从 seeds 沿 edge.source → edge.target 走有向边
  不把 seeds 自己算进去
  跳过没有 capabilityId 的节点，但继续穿过它们
  返回去重后的生成节点 id
```

环已经在连线时拒绝，所以这里不会死循环。仍然加一个访问集，防止坏数据。

从未运行过的生成节点（`runStatus === "idle"`）保持 fresh。它本来就没有可过期的结果。若它正在 queued 或 running，不改 `runStatus`，只把 `inputsChangedWhileRunning` 设为 true。

芯片按这张表画。旧的成功预览在失败、取消、过期时都留着，不把图画空白。

| runStatus | freshness | inputsChangedWhileRunning | 用户看见 |
| --- | --- | --- | --- |
| idle | fresh | false | 预览区「还没有结果」 |
| queued | 任意 | false | 芯片「排队」。runner 为 local 时第二行「本机同时只跑一个」 |
| queued | 任意 | true | 「排队」，再加「输入已变，这次跑完会标成过期」 |
| running | 任意 | false | 「运行中」。有 ratio 就画确定进度条，没有就画不定进度条。label 原样显示 |
| running | 任意 | true | 「运行中」，再加「输入已变，这次跑完会标成过期」 |
| succeeded | fresh | false | 结果图或封面，没有过期标 |
| succeeded | stale | false | 结果仍在，角标「过期」。悬停「上游改过了，不会自动重跑」 |
| failed | 任意 | false | 「失败」加上 errorMessage |
| failed | 任意 | true | 「失败」、错误句子、以及「输入已经和这次任务不一样」 |
| cancelled | 任意 | 任意 | 「已取消」。有旧的成功变体就继续显示它 |

`errorMessage` 为空时，失败格子和预览用「生成失败，没有更多说明」。进度 label 若包含 `KSampler`、`VAE`、`CLIP`、`Load Checkpoint` 这些词，画布改显示「正在生成」。这只是显示过滤，不是在解析工作流。

执行器送来的完成补丁是外部补丁，不进撤销栈。规则：

- 成功：把返回的每个媒体追加为成功变体，`activeVariantId` 设为其中最后一个，更新 `output`。失败的那几项若一并送来，只作为失败变体挂在条上，不抢当前变体。
- 若完成时 `inputsChangedWhileRunning` 为 true：成功落地后 `freshness = "stale"`，并把该标志清掉。用户会看到结果和「过期」同时出现。
- 若该标志为 false：成功落地后 `freshness = "fresh"`。
- 失败：`runStatus = "failed"`，写 `errorMessage`，不切换当前变体，不清除 `inputsChangedWhileRunning`。
- 取消确认：`runStatus = "cancelled"`。画布不自己把「运行中」改成「已取消」，除非执行器确认。取消请求发出后芯片仍是「运行中」，直到确认或失败。取消请求失败时提示「没能取消，仍在运行」。

三个运行动作是画布上的按钮，动作本身发给执行领域：

```ts
type RunIntent =
  | { type: "run-node"; nodeId: string }
  | { type: "run-downstream"; originNodeIds: string[] }
  | { type: "run-selection"; nodeIds: string[] };
```

画布不展开运行顺序，只做按钮是否可点。执行器读取同一份文档自己排序。可点规则：

| 按钮 | 可点 | 不可点时的悬停 |
| --- | --- | --- |
| 运行此节点 | 恰好一个生成节点，且不是 queued/running | 「没有选中节点」/「选中的不是生成节点」/「这个节点正在跑」 |
| 运行下游 | 选择展开后，`collectDownstream` 非空 | 「下游没有要跑的生成节点」 |
| 运行选中部分 | 展开后至少两个节点，且其中至少有一个生成节点 | 「选中的不是生成节点」或「至少要选中一块能跑的部分」 |
| 三个都不可点 | 后端连接状态为断开 | 「后端没连上，现在不能跑」 |

正在跑的那个生成节点上，主按钮变成「取消运行」。排队时主按钮是「取消排队」，发给同一条取消意图，由执行器区分。画布不显示本地并行度控件。云端节点只是 `runner: "cloud"` 的另一枚芯片，画布不限制它的并发。

部分失败时，每个节点画自己的芯片。一个节点失败不清空画布，也不把邻居改成失败。

## 14. 一百个节点和一千个节点

两种规模用同一套代码，差别是预算，不是两套渲染器。

空间索引、视口裁剪、拖拽不 `setState`、边走 Canvas，从第一天就开。不要等节点变多再补。

近景挂载：缩放 ≥ 0.8 时，挂载「与视口相交，再向外扩 0.5 个视口」的节点。同时挂载的完整外壳硬顶 120。超过时，保留离视口中心最近的 120 个，其余即使落在近景视口里也画成色块。每个会话第一次发生截断时提示一次「这一屏节点太多，边缘的先显示成色块。」

一百个节点：

- 文档全在内存里。
- 常见 1440×900 屏幕、缩放 ≥ 0.8、节点大约 320px 宽时，视口里大约只有十几到几十个外壳，到不了 120 的顶。用户应看到完整槽、变体条和缩略图。
- 缩略图只向已挂载节点请求。滚出过扫描围就中止请求（AbortController）。
- 边按视口裁剪后重画。一百条贝塞尔可以在松手后画完，拖相机时用直线。
- 撤销一条移动只含这些节点的坐标操作。
- 这一档不画小地图也可以工作。若用户缩放到 0.8 以下，仍按第 15 节进入色块，即使只有几十个节点。远近由缩放决定，不由总数决定。

一千个节点：

- 仍然只有一个文档。禁止为了「省事」把一千个节点都挂成 React 组件。
- 近景下挂载数仍然 ≤ 120。平移时回收 DOM：离开过扫描围的卸载，进入的再挂。卸载会丢掉输入焦点；若文本框正聚焦而节点要被卸载，先按第 12 节封口文本命令再卸载。
- 缩放到能看见全部节点时，缩放会低于 0.3，进入远景：挂载数为 0，一张 Canvas 画一千个圆角矩形。标题仅在该色块的屏幕宽度 ≥ 64 时绘制，字号用屏幕像素，避免又小又糊。
- 图片解码并发上限 24，优先离视口中心近的。没轮到的近景节点先保持色块，轮到再补图。24 是设计限额，不是测出来的最优值。
- 边：与视口相交的都要画，不许静默少画。相机手势过程中全部降成 1px 直线并去掉标签；松手后对视口内的边补贝塞尔和角色色。悬停或选中的边即使超过视口也画，避免选择「消失」。
- 拖拽一千个已选节点时，只在手势对象里存一个位移。已挂载的用 CSS transform，色块在 Canvas 上加这个位移。松开才写一千个坐标操作。禁止每个 pointermove 更新一千次 React props。
- 全选、成组、标过期都是数据操作。分组框是一个矩形，不要为分组再挂一千个子 DOM。
- 小地图放在这一档：角上一块约 180×120 的 Canvas，只画色块和视口矩形，点击或拖动视口矩形即平移相机。小地图不挂节点 DOM，不进撤销。
- 若千节点夹具在「远景、直线、无图」时仍守不住第 17 节的目标，先脏矩形重画 Canvas，再考虑把色块和边换成 WebGL。不把节点外壳改成 WebGL 文本。

夹具由开发命令在本地生成，不连云。一百档用「网格排列的文本和生成节点，无图」。一千档先用无图色块，等缩略图管道有了再复验「带缩略图路径、但远景不发请求」。没有夹具结果之前，不宣称帧率。

## 15. 远近层次、图片、视频与音频

三档由缩放决定：

| 档 | zoom | 画什么 | 能做什么 |
| --- | --- | --- | --- |
| 远 | &lt; 0.3 | 色块。屏幕宽度 ≥ 64 才画标题。直线边，无角色字。不发图片和封面请求 | 平移、框选、拖动色块、点选。不能编辑文字，不能把线松进槽 |
| 中 | 0.3 ≤ zoom &lt; 0.8 | 色块加标题。边用角色色，仍无槽的 DOM | 同上。开始拉线可以，松手在色块上会取消并提示放大 |
| 近 | ≥ 0.8 | 完整外壳、缩略图、槽、变体条 | 全部手势 |

色块颜色：文本 #3d4a5c，图片 #3e5c4a，视频 #5c4a3e，音频 #4a3e5c，生成且空闲 #3a3a42，运行或排队 #3a4a5c，失败 #5c3a3a。过期时在色块顶部加 4px 的 #d4a017 条。视频色块上画一个小三角，表示这是片而不是图。这些颜色是令牌。

图片：

- 近景已挂载节点的 `img` 只请求 `thumbRelativePath`。没有缩略图路径时用色块，不请求原图。
- URL 由媒体领域的函数提供，画布不把磁盘路径写进 `src`。
- 加载失败：预览区棋盘格加「缩略图没加载出来」和按钮「重试」。重试只再请求一次该 URL。同一节点同一会话里连续失败 3 次后不再自动请求，按钮仍留着。节点矩形和边保持不动。

视频不是大图片：

- 节点上只放封面 `posterRelativePath`。没有封面就显示色块和「封面还没好」，若 `durationMs` 有值，仍显示时长。
- 时长画成 `m:ss`。没有时长就显示「时长未知」，不要显示成 0:00。
- 节点上可以有播放按钮。它打开的是覆盖层里的预览，预览的地址只允许是 `proxyRelativePath` 对应的后端 URL。代理还没有时，按钮禁用，句子是「正在准备预览」。
- 禁止给画布上的 `<video>` 或预览设置原片路径。工程里若只有原片、没有代理，播放按钮保持禁用，封面照常显示。
- 首帧、尾帧是两枚小芯片，不是自动生成的节点。拖拽规则见第 10 节。
- 远景和中景不请求封面。

音频：

- 近景节点是一条控制，显示时长和播放、暂停。播放地址用媒体领域给的后端 URL。第一版不画波形，免得编造峰值。
- 远景只画音频色块。
- 音频参考槽上的缩略是一个小图标加源节点标题，不是频谱。

从操作系统拖入文件：

- `image/*`：交给媒体领域，成功后创建图片节点，`output` 用返回的 `MediaRef`。等待时幽灵上写「正在放入…」。失败不创建节点，提示「这张图没能放进媒体库」。若对方有更具体的句子，用对方的。
- `video/*`：在「一条图生视频」那一档之前，不创建节点，提示「视频文件还不能导入」。那一档之后走与图片相同的引用流程，节点种类为 video。
- `audio/*`：在音频档之前提示「音频文件还不能导入」。
- `text/plain`：小于 100000 个字符则创建文本节点并写入 `text`。超过则拒绝，提示「文本太长，没有放进节点」。100000 是选定上限。
- 多个文件一次拖入：能创建的放进同一条命令，位置错开 24 像素。部分失败时提示「N 个里有 M 个没放进去」，撤销会去掉已经创建的那些。
- 返回的路径若不是工程内相对路径、或含有反斜杠、或是绝对路径：拒绝创建，提示「媒体路径不是相对的正斜杠路径，节点没创建」。

后端断开时：顶部一条非模态横幅「本机后端没连上。画布还能移动和编辑，图片会先显示成色块。」近景也不发新的图片请求。已显示的图可以留在内存里。运行按钮按第 13 节禁用。后端恢复后横幅消失，视口内节点重新请求缩略图。

## 16. 动效原则

动效只用来解释变化。画布上不做循环呼吸、不做粒子、不用节点抖动表示错误。抖动会改命中位置。

| 什么 | 时长 | 说明 |
| --- | --- | --- |
| 指针拖着的节点、幽灵、橡皮筋、相机平移 | 0 | 必须 1:1 跟手，不许缓动 |
| 选中环、槽高亮 | 120ms | ease-out |
| 槽重排时其他槽让位 | 120ms | 只动画 transform |
| 切换当前变体时预览交叉淡化 | 120ms | 失败变体不淡入一张破图，直接换句子 |
| 新变体格出现 | 160ms | 淡入 |
| 适配视图的相机 | 200ms | 可被指针打断 |
| 远景一千个色块 | 0 | 不逐个淡入 |

`prefers-reduced-motion: reduce` 时上表时长全部为 0。拖拽中的影子可以保留，它不是动画。

运行中的不确定进度是芯片上的细条，不是整张节点在发光。成功落地时新格子淡入即可，不要把节点放大弹一下。

## 17. 交互延迟预算

下表全是目标，不是本次测量。体验领域若公布预算表，实现以那张表为准，但不得为了追帧而把一千个完整 DOM 挂上。冲突时先减细节，不先加 DOM。

| 交互 | 目标 | 守不住时先降什么 | 用户看见什么 |
| --- | --- | --- | --- |
| 按下到选中描边 | 同一帧，不超过 16ms | 阴影可以晚一帧 | 先看到 1px 描边 |
| 平移和缩放 | 跟手，目标 60fps；降到 30fps 时仍须能演示 | 先藏点阵，再在手势期间把视口内节点改画成色块，松手后按缩放档恢复 | 画面变简，没有弹窗 |
| 拖节点 | 节点与指针相差不超过 1 帧 | 拖动期间不画缩略图，只移动色块或描边 | 松手后图回来 |
| 橡皮筋 | 每帧最多重画一次 | 曲线改直线 | 线变直，仍跟手 |
| 按下时的命中 | 候选集上的计算不超过 8ms | 超时则这次只做节点命中，不做边命中 | 点在线上可能要再点一次空白处的线段 |
| 文本 | 系统输入法，不经画布重绘 | 不适用 | 组字条由系统画 |
| 撤销结构改动 | 下一帧能看到位置和线；图可以后到 | 先恢复矩形和边 | 节点先出现，缩略图后补 |
| 变体条滚动 | 原生滚动 | 不适用 | 普通滚动条 |
| 拒绝类提示 | 松开后 1 帧内出现，1.6s 后消失 | 不适用 | 指针旁一句中文，同时只留一句 |

没有任何一条允许用「整页快照进撤销」或「pointermove 里 setState」来换实现速度。

## 19. 加载、保存与不变量

画布不直接写工程文件。它把 `EditorDocument` 和 `viewport` 交给工程领域。撤销栈留在内存里。

打开时 `version` 高于 1：不打开文档，整画布用一句话「这份工程是更新的版本写的，画布没有打开它，以免写坏。」不要部分打开。`version` 低于 1 或缺失：同样拒绝，句子是「还不能打开这个版本的工程」。第一版没有迁移函数。

打开 version 为 1 的文档后跑不变量：

- 每条边的 `targetSlotId` 存在，且该槽的 `edgeId` 指回这条边。
- 一个 `edgeId` 不被两个槽占用。
- `activeVariantId` 要么为 null，要么属于该节点的 `variants`。
- 分组的 `childIds` 都存在，且子节点的 `groupId` 指回该分组。
- 没有自己连自己的边。
- 没有有向环。
- 所有 `relativePath`、`posterRelativePath`、`proxyRelativePath`、`thumbRelativePath` 要么为 null，要么是不含 `..`、不以 `/` 开头、不含反斜杠的相对路径。

坏掉的边从打开后的内存文档里拿掉，其他节点保留。顶部横幅：「有 N 条线因为数据不完整被暂时拿掉了，还没写回磁盘。」用户按「写回修复」才把拿掉边的结果变成一条命令并允许保存；在那之前关闭窗口不得悄悄覆盖原文件。这句「不得覆盖」要工程领域配合，画布负责不发出保存。用户也可以不修复就继续在内存里编辑，但保存按钮保持禁用，悬停「先处理被拿掉的线，或另存」。另存是否提供，由工程领域决定。画布至少要能把当前内存文档交出去，并标明它是修复后的副本。

每次用户命令提交前都跑同一套不变量。失败则拒绝整条命令。

## 20. 工程师不要做的事

- 不要做 KSampler、VAE、Checkpoint、CLIP 这类计算节点，也不要做「在 ComfyUI 里打开这张图」的往返编辑。
- 不要把每个变体自动铺成节点。只有第 10 节的拖出手势才创建节点。
- 不要在平移、缩放、拖拽的 pointermove 里 `setState`。
- 不要用整页深拷贝当撤销。
- 不要在节点或预览里播放原片。
- 不要在松手到空白时自动创建一个连线用的无名节点。
- 不要因为上游改了就自动运行。
- 不要把本地队列画成可以并行跑多个的控件。
- 不要把 API Key 放进节点字段、撤销操作或工程 JSON。

## 21. 因已定边界而放弃的做法

边界冲突时以边界为准。下面这些是因此不采用的做法，避免以后被当成漏做。

- 放弃用 React Flow、Rete、LiteGraph、X6 把「有序槽」装成端口。那样更快能拉线，但会变成第二个 ComfyUI。端口库的框选、小地图、撤销也不要混进来。
- 放弃 tldraw 作为内核。手感要自己做。许可证摘要也表明它不适合当无额外商业协议的默认依赖。Excalidraw 虽是 MIT，一并放弃，因为它是白板笔画不是槽。
- 放弃第一版 WebGL / Pixi / Konva / Fabric 场景图。绘制层只有 Canvas 2D。若千节点夹具守不住预算，再单独立项换绘制，不换文档。
- 放弃把变体拖出实现成「从横条里抠走」。字面上的「变成」可以理解成移动。移动会改变源节点的当前输出，整条下游被标过期，和「我只是想把这张图放到画布上」相反。第一版采用引用抽出：新节点共享 `MediaRef`，源变体条保留，幽灵带「+」。若产品说明坚持要抠走，只改这一条命令的操作列表，不改手势状态机。
- 放弃在画布上自动为每个变体、首帧、尾帧生成节点。
- 放弃节点内循环播放视频、以及把视频节点画成一张没有时长的大图。也放弃在画布上做遮罩画笔。
- 放弃桌面壳才有的原生窗口手势和系统文件对话框作为第一版前提。文件进来靠拖放和 `<input type="file">`，字节交给本机后端。
- 放弃纯静态页直接读媒体目录。缩略图和代理都走后端 URL。后端没起来时画布仍能平移和编辑，图变成色块。
- 放弃上游一变就自动重跑，也放弃用自动重跑来掩盖过期状态。
- 放弃本地并行调度界面。云端并发不在画布上画成另一套队列，只显示节点自己的芯片。
- 放弃任意工作流往返，以及把 ComfyUI 计算节点暴露成用户能连的线。
- 放弃把撤销做成整页快照。边界要求的命令式撤销也更适合一千个节点：快照会把媒体字段反复复制进内存。
- 放弃第一版触摸屏专用布局。开发机是 Windows 桌面浏览器。触控笔只要浏览器把它实现成指针事件就能拖，不单独适配。
- 放弃「参考图」作为一种独立生成器和一套独立渲染器。它是槽角色加图片节点。若产品说明要单独的 kind，可以加字段，不必新做一种画布。

## 22. 跨领域依赖

产品与信息架构：

- 节点种类、角色显示名、以及「抽出变体是引用还是抠走」以产品说明为最终语义。本文暂定引用抽出。若产品改成抠走，画布改 `extractVariant` 的操作列表：从源 `variants` 删掉该格，并在它曾是当前变体时改 `activeVariantId` 和 `output`，再按第 13 节标下游过期。
- 分组是否参与执行，本文规定不参与，只是空间上的框。
- 生成状态的名字若与本文的 `RunStatus` 不一致，以产品的状态机为准，但画布需要能映射到第 13 节那张「用户看见什么」的表。映射不上的状态显示芯片「未知状态」，不要画成成功。
- 三个运行动作的中文名若要改，改文案即可，意图种类不要合并成一个模糊的「运行」。

执行与模型接入：

- 提供 `CapabilityDesc` 列表。画布的添加槽菜单、工具栏和兼容判断都读它。演示预设只是后备。
- 提供任务补丁：`runStatus`、`progress`、`errorMessage`、`runner`、变体媒体引用。`errorMessage` 和 `progress.label` 必须是能给用户看的句子。画布会过滤 KSampler、VAE、CLIP、Load Checkpoint 这几个词。
- 运行意图用第 13 节的 `RunIntent`。拓扑顺序和「一批里部分失败」由执行器决定。画布只按节点画结果。
- 完成补丁必须遵守 `inputsChangedWhileRunning`：标志为 true 时，成功落地也要把 `freshness` 写成 `stale`。
- 删除正在跑的节点后，执行器应取消或丢弃迟到结果。画布保证不再把该 id 画回来。
- `resolvePrompt` 与 `resolveSlotMedia` 必须和画布共用同一实现。重启后续跑也读文档，不要只相信点击当时的临时字符串。
- 画布不接收、也不保存 API Key、底模内部图、或 ComfyUI 计算图。

媒体工程与运行形态：

- 提供 `mediaUrl(relativePath) -> http(s) URL`，只指向本机后端。画布不读 `file://`。
- 一张图或一段视频落盘后，返回 `MediaRef` 的全部路径字段。缺缩略图、缺封面、缺代理都要允许为 null，画布按第 15 节降级，不要返回空字符串冒充路径。
- 路径规则：工程内、相对、正斜杠、不含 `..`。
- 视频必须能最终给出时长、封面、首帧、尾帧和代理。缺哪一项，画布就禁用对应控件并显示第 15 节的句子。
- 卸载节点或滚出视口时，画布会中止缩略图请求。后端要允许客户端断开，不要当成错误弹窗。
- 工程文件保存 `EditorDocument` 和 `viewport`。不要把撤销栈和密钥写进去。画布在不变量失败时会拒绝发出覆盖保存。
- 内容哈希相同的抽出节点共享路径。回收无引用文件时，要同时看变体条里的引用和抽出节点的引用。画布不自己删文件。

体验质量与验收：

- 第 17 节的数字是画布提出的目标。体验说明若另有预算表，实现时合并，但 LOD 和 120 挂载顶不能被「全程全细节 60fps」推翻。
- 每个阶段的演示都要包含这一阶段已经存在的动效和失败句，不要留到最后统一美化。
- 请把「拖拽过程中没有整页 React 提交」和「撤销栈里没有整页快照」写成可检查项。例如在千节点夹具里拖动时，记录 store 订阅次数，目标是手势期间为 0 次文档订阅。这是目标，不是已测结果。

本文不依赖密钥存储的任何接口。密钥不应出现在画布进程的文档对象里。

## 23. 建议落在哪些阶段

画布工作嵌进总方案的切片里，不单独拖到最后做「手感阶段」。每段结束都要能在本机浏览器里演示。人周由总方案估，这里不估。

工程地基与空画布：

- 做出视口、相机、点阵、空状态、滚轮 `preventDefault`、空间索引的空实现。
- 验收看：空画布能平移缩放，刷新后若工程领域已能存 `viewport` 则位置还在；不能存时至少内存里的相机是对的。没有节点也能演示。

画布手感：

- 文本节点和生成节点的外壳、拖拽、吸附、框选、多选、分组、复制粘贴、命令式撤销、远中近三档。这一档可以还没有真图，近景画占位，远景画色块。
- 挂载顶 120、拖拽不 `setState`、直线/贝塞尔切换，在这一档就做好。
- 用无图的一百节点和一千节点夹具演示：缩放到近处只出现视口内的外壳；缩放到远处是色块；拖动已选集合时文档订阅不在 pointermove 里触发；撤销一次移动只回退一条。
- 小地图可以跟一千节点夹具一起出现。

语义图：

- 有序槽、角色色、兼容拒绝、成环拒绝、变体条、切换当前变体、拖出新节点、过期角标。
- 演示用本地按钮伪造「上游文本改了」，只看到下游角标变成「过期」，网络面板里没有运行请求。再演示把变体拖到空白和拖到槽上各一次，确认源变体条还在。
- 三个运行按钮此阶段可以只弹出意图的 JSON 或日志，不一定真的跑模型。禁用理由的句子要已经是最终文案。

执行器与文生图、图生图：

- 把芯片接到真的任务补丁。演示排队、运行中改提示词、成功、失败、取消失败、一批里一个失败另一个成功。
- 画布这一档不新增手势。若必须改字段，只加执行器已经给出的补丁字段。

结果、缩略图与可拷走的工程：

- 把占位换成 `thumbRelativePath`。演示缩略图失败与重试、后端关掉时的横幅、以及抽出的节点与源变体共享同一相对路径。
- 带图再跑一次一百节点夹具：远景不应发出缩略图请求。

一条图生视频：

- 视频节点的封面、时长、禁用的原片、代理预览、首帧尾帧芯片。
- 演示：画布节点的网络请求里没有原片 URL；代理未就绪时按钮是「正在准备预览」；把首帧拖进图生视频节点的首帧槽。

参考音频和更多能力：

- 音频节点和音频参考槽。描述符从执行器来，画布不改手势。
- 新角色只要落在现有 `Role` 里，就不再改渲染器。

多厂商、失败与恢复：

- 画布只增加 `runner` 芯片文案和执行器已经定义的失败句子。不在画布里分厂商做不同的连线方式。
- 重启后续跑是执行器的事。画布重新打开工程后撤销栈为空，芯片显示执行器恢复出来的状态。

桌面壳后置：

- 画布不改。若壳只是包一层浏览器，指针与滚轮行为应与本机浏览器一致。不在壳阶段重写命中和撤销。
