## 1. 产品定义

这是一个从零开始的本地应用，不是第二个 ComfyUI。本体是一张无限画布。用户在画布上摆文本、图片、视频、音频，以及一次生成结果，再用带角色的线把它们连起来。

一次生成结果不是第五种二进制，也不是 KSampler、VAE 这类计算节点。它是一种节点：绑定一个用户能看懂的能力（例如文生图），用有序槽接收输入，运行之后在节点内部放下这次的结果。计算图留在本机配方里，不画到画布上，也不能把任意 ComfyUI 工作流导进来再导出去。

生成后端有两类，对画布是同一个能力接口。一类是本机 ComfyUI，只通过 API 格式的配方填槽执行。一类是外部模型的 API Key。用户换的是「这张配方」或「这一家云端」，不是换一套连线方式。

第一版的运行形态是本机浏览器加本机后端。不是纯静态页，也不是现在就做的桌面壳。后端负责工程、媒体、ffmpeg、任务库、密钥，并代理 ComfyUI，避免浏览器跨域直连。开发机是 Windows。工程内引用一律是正斜杠相对路径。

不追求一次做完。每个阶段结束都要有一个能在本机演示的切片。这个阶段已经存在的空状态、失败句子、禁用原因和过期角标，都算这个阶段的验收，不留到最后统一美化。

## 2. 目标用户

下面是从边界推出来的使用对象，不是访谈结论，也没有使用人数或成功率可引用。

第一版只服务一个人、一台 Windows 电脑、一个浏览器窗口。这个人用画布组织文本、图片和后来的一段视频，素材要么是自己写的或导入的，要么是本机 ComfyUI 或一家外部模型生成的。他需要看见「这张图从哪句话、哪张参考图来」，并在上游改了之后知道下游旧结果已经过期。他不在画布上编辑采样器、VAE 或一整张工作流。

因此第一版不为这些人做专门能力：多人同时改同一工程、在手机上作画、把 ComfyUI 的节点图当主界面、以及把密钥交给别人或写进工程文件。

打开工程的人被当成这台机器的使用者。工程可以拷到另一台机器，但密钥和 ComfyUI 地址不跟着走。另一台机器缺配方或缺密钥时，旧结果还在，只是不能再跑。见第 13 节。

## 3. 核心场景

每个场景都是以后验收时能对着做的路径。没有写进场景的能力，不在第一刀里做。

**写一句提示词并出图。** 用户添加文本节点并写字，添加文生图节点，把文本连到提示词槽，运行这一个节点。节点从空到排队、运行，然后成功或失败。成功后图出现在这个节点里，不自动铺成一排新节点。

**同一句话分出两张结果。** 一个文本节点连到两个文生图节点。改一次字，两个生成节点都过期，而且都不会自己重跑。

**多张图汇成一次生成。** 用户把原图、风格参考、角色参考分别连进目标节点从上到下的槽。顺序就是交给生成的顺序。没有「一捆没有角色、也没有先后」的线。

**变体留在节点里，需要时再拖出去。** 一次运行可以要多张变体。它们出现在节点底部的变体条。只有用户把某一张拖到画布上，才变成新的图片节点。拖出去是复制一份引用，变体条里原来的那张还在。

**上游改了，下游只标过期。** 用户改文本、换参数、换连线或换成另一张变体之后，受影响的生成节点标成过期，预览仍留着旧结果。没有任何自动重跑。用户自己点「运行此节点」「运行下游」或「运行选中部分」。

**图生图和图生视频用的不是同一类输入。** 图生图改的是一张确定的原图。参考图生成吃的是有序的参考图、风格参考或角色参考。图生视频吃的是一张首帧，可选尾帧和提示词。视频节点要能看见时长、封面和「现在不能播原片」。

**关掉再打开，工作还在，密钥不在。** 保存之后的工程文件能在本机后端里重新打开。文件里有相对路径和参数，没有图片字节，也没有 API Key。

## 4. 词汇

这些词在后文里不再混用。

| 词 | 含义 |
| --- | --- |
| 工程 | 一个目录里的一份画布。身份是 `projectId`。 |
| 节点 | 画布上的一块。种类只有文本、图片、视频、音频、生成。 |
| 素材节点 | 文本、图片、视频、音频。它们不能自己调用模型。 |
| 生成节点 | 一次生成结果所在的节点。对外输出仍是文本、图片、视频或音频中的一种。 |
| 槽 | 生成节点上的一个有序入口。同一时刻最多接一条线。 |
| 角色 | 这条线在目标槽上的职责，例如提示词、原图、首帧。角色写在槽上，边与槽保持一致。 |
| 变体 | 某一个结果版本里的一张（或一条）输出。默认只活在变体条里。 |
| 版本 | 一次运行产生的一批变体。新的成功运行追加版本，不覆盖旧版本的媒体。 |
| 当前输出 | 当前版本里被选中的那一个变体。扇出的所有下游读的都是它。 |
| 过期 | 节点还有旧的成功结果，但旧结果的指纹已经对不上现在的输入或参数。不是失败。 |
| 配方 | 应用自带的一份填槽说明。用户只看见配方标题。本机配方内部才有 API 格式工作流。 |
| 绑定 | 某个能力在这台机器上的一条可运行通路：要么是一张本机配方，要么是一家云端。工程只存配方 id 和版本，不存密钥，不存 ComfyUI 地址。 |
| 下游 | 沿输出线能走到的全部分支里的生成节点，不含起点自己。中间穿过素材节点时继续往下走。 |
| 内容脏 | 用户的工作相对上次保存有改动，顶栏出现「未保存」。 |
| 首帧 | 有两个东西，不要混。槽角色「首帧」是图生视频的输入。视频上的「首帧图」是这条视频导出的第一帧图片。尾帧同样。 |

分组是画布上的框，不是节点种类，也不是一次运行的单位。手势在画布说明里。产品只规定：分组不改变连线含义，不参与指纹，运行前先展开成里面的节点。

## 5. 工程、画布和顶层字段

一个工程是用户选定的一个目录。工程文件建议命名为 `project.json`，放在该目录下。媒体库在同一目录内。用户在 Windows 上选的文件夹可以带盘符和反斜杠；写入工程文件之前必须收成相对该目录的正斜杠路径。工程文件里不得出现盘符、不得出现反斜杠、不得出现以 `/` 开头的路径、不得出现 `..`。

媒体按内容哈希存放。两个节点用到同一批字节时，磁盘上只有一份，工程里两处引用的相对路径可以相同。第一版不因为删除节点就删除媒体文件，否则会误删历史版本还在引用的哈希。磁盘因此会增长。回收无引用文件不在第一刀。

`project.json` 的顶层字段：

| 字段 | 类型 | 必填 | 含义 |
| --- | --- | --- | --- |
| `schemaVersion` | 数字 | 是 | 第一版只允许 `1`。更高或缺失：整份不打开，句子见第 13 节。第一版没有迁移。 |
| `projectId` | 字符串 | 是 | 创建时生成，保存不改变。另存为必须换新 id。 |
| `name` | 字符串 | 是 | 顶栏显示的工程名。默认为文件夹名。改名会标脏。 |
| `mediaHashAlgorithm` | 字符串 | 是 | 第一版固定写 `"sha256"`。这是选型，不是测速结果。 |
| `contentRevision` | 整数 | 是 | 从 0 起。只有第 11 节列出的内容操作才加 1。 |
| `savedContentRevision` | 整数 | 是 | 上次成功写入磁盘时的 `contentRevision`。两者不等，顶栏为「未保存」。 |
| `nextSerial` | 整数 | 是 | 用来生成默认标题。删除节点不把序号收回，避免新节点和已删节点看起来同名。 |
| `viewport` | 对象或空 | 否 | 相机。重新打开时恢复。改视口不加 `contentRevision`，不点亮「未保存」。 |
| `nodes` | 节点映射 | 是 | 键是节点 id。 |
| `edges` | 边映射 | 是 | 键是边 id。 |
| `groups` | 分组映射 | 是 | 可以是空对象。 |

新建工程在用户第一次改内容之前是干净的。空画布本身不标脏。

视口、选择、悬停、撤销栈不决定内容脏。撤销栈只活在这一次打开里，不写入工程。重新打开后撤销和重做都是空的，按钮为灰，按快捷键不弹窗。

节点 id、边 id、版本 id、变体 id 都是工程内唯一的不透明字符串，用 UUID 即可。不得用标题当 id。

时间用带时区偏移的 ISO-8601 字符串。界面按本机时区显示。没有时间时写空，不要写成 0。

保存是覆盖这个 `project.json`，不是新开一个历史版本。另存为是新目录或新文件、新的 `projectId`，生成版本列表原样复制，之后两份工程各自改各自的。第一版不做工程级的时间旅行。

保存时若磁盘上的 `contentRevision` 已经不是本次打开时读到的值，拒绝覆盖。句子：「这份工程在这次打开之后被写过。为避免覆盖，请另存为。」内存里的修改保持「未保存」。第一版不锁文件，也不做协同。

只改了视口时，允许单独把视口写入磁盘，并且不把内容标脏。写视口失败时，节点编辑不受影响。画布说明里的句子是：「视图没能记住，下次打开会回到默认位置」。沿用这句。

内容保存失败时，内存修订还在，`savedContentRevision` 不变。句子：「没能保存，修改还在。」

启动时若本机后端连不上：整页只有「请先启动本机后端。」不进入一个只存在浏览器内存里的工程。编辑过程中后端断开：顶栏非模态横幅「本机后端没连上。这个窗口里的修改还在，但现在不能保存，也不能生成。」已显示的图可以留着。后端恢复后横幅消失，保存和运行恢复。

## 6. 节点类型与字段

五种节点，没有第六种。生成节点的 `outputKind` 决定它向外提供的是文本、图片、视频还是音频。

公共字段：

| 字段 | 类型 | 必填 | 含义 |
| --- | --- | --- | --- |
| `id` | 字符串 | 是 | 稳定 id。 |
| `kind` | 枚举 | 是 | `text`、`image`、`video`、`audio`、`generation`。 |
| `title` | 字符串 | 是 | 可改。不参与指纹，改标题不让下游过期。默认标题用种类加 `nextSerial`，例如「文本 1」「文生图 2」。 |
| `x` `y` | 数字 | 是 | 世界坐标。可以是负数。移动会标脏，不让下游过期。 |
| `width` `height` | 数字 | 是 | 用户改过就必须保留。默认尺寸由画布说明给出，产品不另定一套像素。 |
| `z` | 整数 | 是 | 重叠时谁在上面。置于顶层或底层会标脏，不过期。 |
| `groupId` | 字符串或空 | 是 | 不属于分组时为空。 |
| `origin` | 枚举 | 是 | `authored`（用户写下的文本）、`imported`（导入的文件）、`generated`（生成节点）、`detached`（从变体或首帧、尾帧、封面拖出的素材）。 |
| `createdAt` `updatedAt` | 字符串 | 是 | `updatedAt` 只在内容修订时更新，不因平移视口更新。 |
| `outputRevision` | 整数 | 是 | 从 1 起。当前对外输出的身份变了才加 1。下游过期看的是输出身份，不是坐标。 |

文本节点另外有：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `text` | 字符串 | 正文，允许空字符串。空字符串仍然是节点，但满足不了必填提示词。 |
| `capabilityId` | 空 | 文本节点永远为空。没有模型调用。 |

图片、视频、音频素材节点另外有一个 `output`。没有结果时 `output` 为空。字段形状见下面的媒体引用。图片和视频、音频没有正文。它们没有槽，没有变体条，不能「运行此节点」。

生成节点另外有：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `capabilityId` | 字符串 | 创建后第一版不能改能力。要换成别的能力，就新建节点。避免槽方案对不上。 |
| `profileId` | 字符串 | 例如 `txt2img`。和能力一起决定槽的允许角色。 |
| `recipeId` | 字符串或空 | 这台机器上选用的配方。空表示还没选。 |
| `recipeVersion` | 整数或空 | 与配方一起写入。工程不内嵌工作流正文。 |
| `outputKind` | 枚举 | `text`、`image`、`video` 或 `audio`。由能力决定，用户不能单独改。 |
| `promptDraft` | 字符串 | 本地提示词草稿。只有在没有提示词连线时才使用。 |
| `params` | 对象 | 用户能改的参数。键来自配方。不得放入类名、工作流或密钥。 |
| `variantCount` | 整数 | 下次运行要几张。下限 1，上限 4。4 是产品裁剪，不是显存测量。 |
| `slots` | 槽数组 | 见第 7 节。 |
| `versions` | 版本数组 | 只收至少有一张成功媒体的运行。追加，不替换旧项。 |
| `currentVersionId` | 字符串或空 | 变体条正在展示的版本。 |
| `activeVariantId` | 字符串或空 | 必须属于当前版本，或为空。 |
| `output` | 媒体引用或空 | 必须等于当前变体的媒体。文本类结果见版本上的正文，不用这个字段装长文本。 |
| `phase` | 枚举 | `idle`、`queued`、`running`、`succeeded`、`failed`。这是存储相位，不是用户徽章。 |
| `freshness` | 枚举 | `fresh` 或 `stale`。只描述「最近一个成功版本的指纹是否还对得上现在的输入」。从未成功时保持 `fresh`，徽章仍然是空或失败，不会显示成功。 |
| `inputsChangedWhileRunning` | 布尔 | 排队或运行中输入又变了。完成时用来决定落地后是过期还是新鲜。 |
| `lastSuccessFingerprint` | 字符串或空 | 当前成功版本写入时的指纹。 |
| `lastAttemptFingerprint` | 字符串或空 | 最近一次尝试入队时的指纹。 |
| `lastError` | 对象或空 | `{ code, message, detail? }`。`message` 是一句中文。 |
| `runner` | `local`、`cloud` 或空 | 只用于芯片文案，不在画布上调度。 |
| `progress` | 对象或空 | `{ ratio, label }`。执行器没给时为空。产品不编百分比。 |

从变体拖出的素材节点另有 `provenance`：`{ sourceNodeId, versionId, variantId }`。源节点后来被删除时，这三个 id 可以悬空，素材自己的媒体引用仍然有效。不因为源没了就把拖出的图清掉。

默认标题和默认尺寸不够成「未保存」。用户把节点留在刚创建的位置，只要创建这个动作发生了，工程就脏了。创建是内容操作。

打开工程时要检查：

- `activeVariantId` 要么为空，要么属于 `currentVersionId` 那一版。
- `output` 的内容哈希要么为空，要么等于该变体的哈希。不一致时以变体为准改正内存，顶栏标脏，横幅：「有一个节点的对外结果和变体对不上，已按变体改好，需要保存。」
- 分组的子节点双向一致：子节点的 `groupId` 指回分组，分组的 `childIds` 都存在。
- 路径符合第 5 节。坏路径不猜盘符。该媒体显示「媒体引用不完整」，不创建替代文件。

边的不变量见第 7 节。坏掉的边从打开后的内存里拿掉，其他节点保留。横幅：「有 N 条线因为数据不完整被暂时拿掉了，还没写回磁盘。」在用户明确保存修复之前，不得覆盖原文件。这与画布说明一致。

## 7. 边、角色与有序槽

一条边从源节点的唯一输出出发，落到目标生成节点的一个槽。素材节点没有输入槽。第一版不允许把线连到文本、图片、视频或音频素材上。

边的字段：

| 字段 | 类型 | 必填 | 含义 |
| --- | --- | --- | --- |
| `id` | 字符串 | 是 | 稳定 id。重排槽不改变边的 id。 |
| `sourceNodeId` | 字符串 | 是 | 输出那一侧。 |
| `targetNodeId` | 字符串 | 是 | 必须是生成节点。 |
| `targetSlotId` | 字符串 | 是 | 落到哪一个槽。 |
| `role` | 枚举 | 是 | 必须等于该槽的 `role`。线的标签读这个字段，避免再猜。 |

槽的字段：

| 字段 | 类型 | 必填 | 含义 |
| --- | --- | --- | --- |
| `id` | 字符串 | 是 | 稳定 id。重排后 id 不变，线还在这个槽上。 |
| `role` | 枚举 | 是 | 见下表。 |
| `order` | 整数 | 是 | 从 0 起，同一节点内必须连续。界面序号从 1 显示。 |
| `edgeId` | 字符串或空 | 是 | 空槽为空。一个槽最多一条边。 |

必填、可选、某个角色最多几个槽，以能力描述符为准，不在每个槽上再存一份，避免两套真相。描述符没写上限时按 1。槽上的「必填」「可选」是描述符换算出来的外观。

角色的正式 id 以这张表为准。显示名是界面用语。执行说明里的 `reference` 不准另存一套；存进工程的字符串是 `reference_image`。

| `role` | 显示名 | 接受的源 | 第一版谁使用 |
| --- | --- | --- | --- |
| `prompt` | 提示词 | 文本节点 | 需要文字的能力。第一版每个生成节点最多 1 个提示词槽。 |
| `source_image` | 原图 | 图片，或输出为图片的生成节点 | 图生图，正好 1 个，必填。 |
| `reference_image` | 参考图 | 同上 | 参考图生成。按槽的顺序从 1 数。 |
| `style_reference` | 风格参考 | 同上 | 参考图生成的可选槽。 |
| `character_reference` | 角色参考 | 同上 | 同上。 |
| `mask` | 遮罩 | 图片 | 只有配方声明接受时，运行才允许通过。第一版不在画布里画遮罩。 |
| `first_frame` | 首帧 | 图片 | 图生视频，正好 1 个，必填。 |
| `last_frame` | 尾帧 | 图片 | 图生视频，最多 1 个，可选。 |
| `audio_reference` | 音频参考 | 音频 | 枚举先留着。第一刀没有对口型，界面不提供这个槽。 |

正式 id 里保留 `source_image`，是因为任务书的角色列表用了「例如」，而图生图若没有原图，就会和参考图混成一捆无名的图。这不是把计算节点暴露给用户。

连线规则：

- 不允许连到自己。松开时提示「不能连到自己」。不创建边。
- 不允许有向环。提示「会形成循环，已取消」。
- 种类不合。提示「不能把「视频」接到「提示词」槽」，两个名字用这次的源种类和槽的显示名。
- 视频输出第一版不能落到任何槽。提示「视频结果现在还不能接到别的槽上。要用画面的话，拖首帧或尾帧。」首帧图和尾帧图按图片拖出，见第 14 节。
- 一个槽已经有线时，把新线松进这个槽等于替换。旧线删除，新线写上。这是一次操作。
- 松在空白处：不创建节点，提示「要连到槽上，已取消」。
- 还没有结果的生成节点也允许被连出去。槽上显示「已连接，对方还没有结果」。真要运行时，必填槽没有可用媒体，按缺输入处理，不把线静默丢掉。

提示词只有一个真相，画布和执行必须用同一个规则：

- 提示词槽上有线：用源文本节点的 `text`。源是空字符串就用空字符串，不用草稿顶上。输入框只读，下面写「提示词来自连线」。
- 没有这条线：用该生成节点的 `promptDraft`。
- 文本节点自己的输出就是它的 `text`。

这样空画布上可以先在生成节点里写草稿跑通文生图，也可以把草稿换成可复用、可扇出的文本节点。两种来源不会同时生效。

媒体槽读源节点的当前 `output`。源是生成节点时，就是它当前选中的变体，即使那个结果已经过期。过期不把图藏起来。

多个同角色的槽靠 `order` 区分先后。执行按界面从上到下的顺序使用。用户重排槽，就是在改这个顺序。

添加槽时，菜单只列出该能力还没达到上限的角色。第一版提示词槽不提供「再加一个」。不在界面上做多段提示词拼接。执行侧若保留拼接函数，第一版描述符的提示词 `maxCount` 仍是 1。

遮罩可以连到声明了该槽的节点上。若这张配方实际上不接受遮罩，线留着，运行前拒绝，句子：「这张配方还不能用遮罩。」不要悄悄丢掉这条线。

## 8. 变体、版本与汇合

一次运行请求 `variantCount` 张变体，入队前就为每个下标抽好种子。用户参数里可以用「随机」。随机的含义是：判断过期时，指纹只记录「现在选的是随机」，不把具体数字算进去。否则每次抽到的种子不同，节点会永远过期。真正抽到的 32 位无符号整数写在该变体的 `seedUsed` 上，界面标成「实际种子」。用户点「使用这次的种子」后，参数从随机改成那个整数，指纹变化，节点过期。再跑一次仍然随机的节点，会抽新种子并追加新版本，不覆盖旧版本。

版本的字段：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `id` | 字符串 | 稳定 id。 |
| `createdAt` | 字符串 | 这一版第一次有成功媒体的时间。 |
| `fingerprint` | 字符串 | 入队时的输入指纹。 |
| `recipeId` `recipeVersion` | 字符串、整数 | 当时用的配方，方便以后配方没了还能说明。 |
| `paramSnapshot` | 对象 | 当时的用户参数。种子若是随机，这里仍写「随机」；具体数字在变体上。 |
| `variantCountRequested` | 整数 | 用户要的张数。 |
| `variants` | 变体数组 | 这一版的全部格子，含失败占位。 |

变体的字段：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `id` | 字符串 | 稳定 id。 |
| `index` | 整数 | 从 0 起，对应该次抽好的种子。 |
| `phase` | 枚举 | `queued`、`running`、`succeeded`、`failed`、`cancelled`。 |
| `seedUsed` | 整数或空 | 入队时抽定。失败重试且指纹未变时不重抽。 |
| `output` | 媒体引用或空 | 成功时必有。视频必须带齐第 14 节的字段才算成功。 |
| `error` | 对象或空 | 失败格子的一句中文。 |
| `createdAt` | 字符串 | 该格子进入终态的时间。 |

变体条默认只显示 `currentVersionId` 这一版，不把历史上每一次运行的所有图片平铺成一条无限横条。节点上另有版本切换，列出时间，并标出哪一版是当前。切换版本会改 `activeVariantId` 和 `output`，`outputRevision` 加 1，下游过期。若选中的旧版本指纹等于现在的输入，节点自己是成功；对不上就是过期。旧版本的文件不删除。

当前变体的规则：

- 新版本落地时，当前变体设为这一版里最后一个成功变体。失败格子不自动变成当前。
- 用户点击已有媒体的格子：它变为当前，下游过期。该节点自己这次的结果不过期。
- 点击失败格子：允许，以便阅读错误。`output` 变为空，下游照样过期。预览区显示 `error.message`，没有句子时显示「生成失败，没有更多说明」。
- 排队或运行中的格子可以点来看进度，但不改变 `output`，也不标下游过期。
- 第一版不能从变体条里删掉单独一格。不想要某一版时，切换到别的版本即可。该版仍留在列表里。

部分成功：这一版至少一张成功时，版本成立。主徽章按第 10 节走成功或过期，不另设一种主状态。副文案：「4 张里成功了 2 张。」数字用实际请求数和成功数。失败的下标是错误占位，不是空白。指纹没变时，用户可以「只补失败的这几张」：补进当前版本的空位，不新开版本，成功格子的种子不变。指纹已经变了就拒绝，句子：「输入已经变了，不能只补失败的那几张。请重新运行这个节点。」一张都没有时，不创建版本，按失败处理。

拖出变体：

- 拖到空白：新建同种类的素材节点，`origin` 为 `detached`，`output` 与该变体同一内容哈希和相对路径，不复制字节。源变体条、当前变体、源的 `output` 都不变，所以不会因为拖出而让下游过期。
- 拖到另一个节点的兼容槽：同样新建素材节点，并接上那条槽。若该槽已有线，按替换处理。目标节点及其下游过期，因为目标的输入变了。源仍然不变。
- 排队中、运行中、或没有媒体的格子不能拖出。
- 落回原处或种类不合：不创建节点。

扇出：一个输出可以连到很多个槽。所有下游读到的都是同一个当前输出，不会隐含地「每条线各取一个变体」。

汇合：多个源节点进入同一个目标的多个槽。槽的 `order` 就是顺序。把风格参考和角色参考交换位置，等于改了目标的输入，目标及其下游过期。两条源节点自己不过期。

例子。文本「一只猫」连到文生图 B。B 跑完得到版本 v1，用户选中第二张，并把它拖到空白，成为图片 P。P 再连到图生视频 V 的首帧。B 的输出另外连到图生图 G 的原图槽。用户把文本改成「一只狗」并提交。B 过期，G 也过期。P 不过期，V 也不过期，因为它们读的是拖出时的那份哈希，不是 B 的实时输出。没有任何节点自动重跑。用户再跑 B，成功后追加 v2，v1 还在。B 的当前输出换成 v2，G 仍然过期。P 和 V 仍然不过期。

再跑若改成整组替换变体条，v1 会消失，拖出规则也会和「旧结果还在」矛盾。所以不替换。执行说明里「新变体替换变体条」那一句不采用。

## 9. 能力、参数和第一刀范围

用户添加的是能力剖面，不是计算节点。第一刀要能跑的只有下面四条。其余出现在「以后再做」里，禁用，句子一律是：「这一类还没接入。」不要为了演示去请求一个空地址，也不要假装成功。

| 用户看见的名字 | 种类 | `profileId` | 第一刀 | 槽 |
| --- | --- | --- | --- | --- |
| 文生图 | `image.generate` | `txt2img` | 要跑 | 提示词 1 个，必填。没有图像槽。 |
| 图生图 | `image.generate` | `img2img` | 要跑 | 提示词 1 个必填；原图正好 1 个必填；遮罩最多 1 个，且只有配方接受时才能跑通。 |
| 参考图生成 | `image.generate` | `reference` | 要跑 | 提示词 1 个必填；参考图至少 1 个；风格参考、角色参考可选。张数上限写在配方上。配方没写时，产品上限各 4 个。 |
| 图生视频 | `video.generate` | `img2video` | 图像三条跑通后再接一条 | 首帧正好 1 个必填；尾帧最多 1 个可选；提示词 1 个可选。参考图槽只有这条配方声明接受时才出现。没有音频槽。 |
| 文生文 | `text.generate` | `complete` | 只留接口 | 不注册可运行配方。 |
| 文生视频 | `video.generate` | `txt2video` | 只留接口 | 同上。 |
| 对口型 | `video.lipsync` | `talking-head` | 只留接口 | 同上。将来也是「一张图槽加音频参考」，现在不能创建成可运行节点。 |

文本节点不是 `text.generate`。手写文本在第一刀就要有。文生文是以后的生成节点。

文生图、图生图、参考图生成是同一种类的三个剖面，不是三套连线界面。图生视频和以后的文生视频同属视频种类，用剖面区分。对口型单独种类，避免用视频剖面里的分支去假装已经会做。

用户能改的参数用中文显示名，不出现类名。配方没有声明的参数，面板里不画。产品不另写一套「最佳步数」或「最佳相关性」。节点创建时的默认值必须来自配方自己的默认值。

文生图至少要有这些用户参数，若配方把它们标成用户可见：种子（整数或「随机」）、宽度、高度。步数和提示词相关性只有配方标成用户可见才出现，显示名用「步数」和「提示词相关性」，不出现采样器节点的名字。宽度和高度的产品范围沿用执行说明里的设计边界：256 到 2048。这不是画质测量。超出时运行前拒绝，句子把显示名和上下限说出来，例如「宽度要在 256 和 2048 之间。」

变体张数是节点上的 `variantCount`，不是工作流内部的 batch。超过 4 时运行前拒绝：「一次最多出 4 张。要更多，请再跑一次。」

图生视频的时长只允许配方声明的那些值。本文不规定合法秒数，也不把某一家的档位写成事实。配方没有声明时长时，面板不画时长控件，运行使用配方内置时长。非法值在运行前拒绝，不提交。

换模型等于换一张配方。第一版不做通用的模型文件浏览器。配方标题对用户可见。配方正文、类名、ComfyUI 地址和 API Key 都不可见。

本机配方和云端绑定从阶段 2 起就出现在同一个能力接口里。阶段 2 的演示可以只跑通本机文生图。云端图像不在第一刀。云端第一刀只接这一条图生视频。没配密钥时，图生视频点运行的句子是：「还没有配置这一家的密钥。」不发请求。

密钥放在操作系统凭据库。设置页只显示「已配置」或「未配置」，不回显明文，也不能从工程里读回来。清除密钥不改写已经保存的工程。具体存到凭据库的哪个键，由执行说明规定，产品只要求：在 `project.json`、节点字段、撤销记录和给用户看的错误句子里都搜不到密钥。

ComfyUI 的基地址是本机后端配置，不写进工程。换一台机器打开同一工程时，旧图还在。配方在这台机器上不可用时，运行按钮禁用。知道标题时：「这台机器上没有可用的配方「标题」。」不知道标题时：「找不到这张配方。」不要把节点改成失败，也不要清掉变体。

## 10. 生成状态机

用户在生成节点上只看见一个主徽章。存储用 `phase` 和 `freshness`，以免「正在跑」和「跑完会过期」互相覆盖。徽章按下面的顺序判断，命中就停。

| 顺序 | 条件 | 主徽章 | 预览 |
| --- | --- | --- | --- |
| 1 | `phase` 为 `queued` | 排队 | 若已有成功版本，继续显示那一版；没有就显示「还没有结果」。 |
| 2 | `phase` 为 `running` | 运行 | 同上。有进度比例就画确定进度，没有就画不确定进度，不编百分比。 |
| 3 | 从未有过成功版本，且 `phase` 为 `failed` | 失败 | 「还没有结果」，加上失败句子。 |
| 4 | 从未有过成功版本，且 `phase` 为 `idle` | 空 | 「还没有结果」。 |
| 5 | 有成功版本，且现在的输入指纹不等于 `lastSuccessFingerprint` | 过期 | 旧结果留着。角标「过期」。 |
| 6 | 有成功版本，最近一次尝试失败，且该尝试的指纹等于现在的输入指纹 | 失败 | 上一成功版本的图留着，加上失败句子。 |
| 7 | 有成功版本，且指纹相符，最近一次不是失败 | 成功 | 当前变体。 |

因此主徽章至少覆盖空、排队、运行、成功、失败、过期。不增加「部分成功」「中断」「已取消」作为永久主徽章。

补充文案，不另占一种主状态：

- 排队或运行时，若 `inputsChangedWhileRunning` 为真，加一句：「输入已变，这次跑完会标成过期。」
- 过期的悬停：「上游改过了，不会自动重跑。」若最近一次尝试也失败了，预览区仍显示那句失败原因，避免错误被过期角标吞掉。
- 部分成功的副文案见第 8 节。变体条里失败格单独标出。
- 取消没有产生新版本。`phase` 回到进入这次排队之前的静止相位，主徽章按上表重算，并短暂提示「已取消」。重新打开工程后不再挂着「已取消」。任务库里那次任务可以记成已取消。
- 重启后正在对账：不先闪成失败。有未完成任务时，徽章仍是排队或运行，副文案：「正在核对上次没跑完的任务。」对不上时变成失败，句子：「重启后没能对上上次的任务。可以续跑。」续跑只补当前版本里没完成的变体，不新开版本，并且只有指纹没变才允许。对不上且用户不点续跑时，不得自动再提交。
- 执行域若给出无法映射的状态，徽章显示「未知状态」，不得画成成功。

过期怎么传播：

- 从被改节点的输出出发，下游定义里的每一个生成节点都标过期。不自动入队。
- 从未成功的节点保持空或失败，不叫过期。它没有可过期的旧结果。
- 已经过期的保持过期。
- 正在排队或运行的不改 `phase`，只把 `inputsChangedWhileRunning` 设为真。不取消这一次。
- 跑完时若现在的指纹已经和入队时不同：新版本仍然写入，然后徽章为过期。句子：「跑完的时候输入已经变了，这张图已标成过期。」不自动再跑。
- 选中过期节点的当前图，下游仍可读它。

会让「自己（若已有成功版本）以及全部下游」过期的操作：提交文本修改；修改正在生效的提示词草稿；改参数；换配方；连接、断开、替换、重排槽；添加或删除槽；用新文件换掉素材的媒体。

只让下游过期、不让自己这次结果过期的操作：切换当前变体；切换到一个指纹已经对不上的历史版本时自己改为过期，切换到指纹仍相符的版本时自己是成功。两种切换都让下游过期，因为对外输出变了。

完全不过期的操作：移动、改尺寸、改标题、改 z、成组、解散、只把变体拖到空白、平移缩放、选中。

空节点缺输入时保持空，不要预写成失败。

状态转移：

| 从 | 事件 | 到 | 用户还看见 |
| --- | --- | --- | --- |
| 空 | 运行通过预检 | 排队 | 「正在安排……」立刻出现，然后变为排队。 |
| 失败 | 重试通过预检 | 排队 | 旧图若有则留着。 |
| 过期 | 运行通过预检 | 排队 | 旧图留着。 |
| 成功且指纹相符 | 用户确认再跑 | 排队 | 旧图留着。确认框见第 12 节。 |
| 排队 | 本机或云端真正开始 | 运行 | 进度或不确定进度。 |
| 排队 | 取消，且还没交给上游 | 回到排队前的静止徽章 | 短暂「已取消」。没有新版本。 |
| 运行 | 至少一张成功，且指纹仍相符 | 成功 | 新版本出现在版本列表里，变体条切到这一版。 |
| 运行 | 至少一张成功，但完成时指纹已变 | 过期 | 新版本在，角标过期，并有第 10 节那句。 |
| 运行 | 一张都没有 | 失败 | 没有新版本。旧成功版本的预览留着。 |
| 运行 | 用户请求取消 | 徽章仍为运行 | 副文案「正在取消」。直到执行器确认才回到静止徽章。 |
| 成功 | 输入指纹变了 | 过期 | 预览不空白。 |
| 过期或失败 | 用户撤销，使指纹又相符 | 成功或原来的失败 | 撤销可以取消过期。撤销不能删掉已经落地的版本。 |

预检失败不入队，不改 `phase`，不追加版本，也不把成功改成失败。句子写在按钮旁或对应的槽上。预检包括：缺必填槽、种类不合、配方不接受这条线、参数越界、这台机器没有配方、云端没密钥、这一类还没接入、这个节点已经在排队或运行、选中的图形成环。

入队之后才发生的失败才把 `phase` 写成 `failed`，并写入 `lastError`。旧版本不删除。

本机车道同时只有一个生成在执行。一个节点要的多张变体在本机上按顺序完成，完成一张就出现在当前这一版的变体条里；全部结束前徽章保持运行。用户看不见、也不能调节「本地并行度」。云端车道不占用这一个名额。云端同时进行的上限，产品初值沿用执行说明里的 2。这是为了让演示里看得到两条互不依赖的云任务可以重叠，不是实测吞吐，也不是厂商限额。依赖还没成功的上游时，下游任务继续排队，不占云端名额。

排队文案里的「前面还有几个」只统计本应用提交的本机任务。用户若同时在 ComfyUI 自己的界面里排队，本应用不保证数得清那些任务。可以另有一句：「ComfyUI 正在跑别的任务，这一张会等它。」这不是把两条队列假装成已经核对过的同一个数字。

## 11. 什么标脏，什么新开版本

内容脏看 `contentRevision`。排队位置、进度百分比、对账中的刷新，都不点亮「未保存」。失败句子以任务库为回填来源：只是失败、当前版本指针没变时，不强迫用户按保存；重新打开后由任务库把失败填回节点。换机器只拷走工程文件、不拷任务库时，失败句子可以不在，最后一次成功版本还在。这是已知限制。

成功版本落地会增加 `contentRevision`。否则用户不保存就丢掉「当前指着哪一版」。这次落地不进入撤销栈。撤销到保存点时，不得删掉任务库里已经写成的媒体；若工程指针被撤销到旧版，那是一次新的内容修订，下游按切换版本处理。

下表是开工时要逐项对上的规则。

| 操作 | 内容脏 | 版本 | 过期 | 用户看见 |
| --- | --- | --- | --- | --- |
| 平移、缩放、框选、点选 | 否 | 无 | 无 | 视口可单独记住。 |
| 新建节点、粘贴、成组、解散 | 是 | 不新开生成版本 | 粘贴不自动过期；成组不过期 | 新节点有新 id。 |
| 删除节点或边 | 是 | 不删除媒体文件，不删除任务库历史 | 失去输入的下游按第 10 节重算 | 正在跑的节点也立刻从画布消失，并通知执行侧能取消就取消。迟到的结果丢弃，不把节点复活。可以撤销放回节点。 |
| 移动、改尺寸、改标题、改 z | 是 | 无 | 无 | 标题不参与输出。 |
| 文本或草稿正在输入、输入法组字中 | 是，合并为一次编辑 | 无 | 还不过期 | 组字期间不提交。失焦、或停顿后封口，规则与画布说明的文本合并一致。 |
| 文本或正在生效的草稿封口，且内容变了 | 是 | 覆盖正文或草稿本身，不新开生成版本 | 该生成节点（若草稿生效且已有成功版本）和全部下游 | 下游角标过期，不跑。 |
| 封口但文字没变 | 否 | 无 | 无 | 不多写一条历史。 |
| 导入或替换素材成功 | 是 | 替换的是素材节点的当前指针。旧哈希文件留着。不叫生成版本 | 该素材的下游 | 新图出现。 |
| 导入失败 | 否 | 无 | 无 | 不创建半个节点。句子：「这张图没能放进媒体库。」视频和音频在未开放的阶段另有拒绝句，见第 14 节。 |
| 连线、断开、替换槽、重排、增删槽 | 是 | 无 | 目标及其下游 | 线的标签始终是角色名。 |
| 被拒绝的连线 | 否 | 无 | 无 | 文档不变。有一句原因。 |
| 改参数、换配方、改变体张数 | 是 | 无。下次运行才用新值 | 自己（若已有成功版本）和下游 | 旧图还在，角标过期。 |
| 通过预检并入队 | 否 | 无 | 无 | 徽章变为排队。 |
| 运行成功，至少一张 | 是 | 追加新版本，不覆盖旧版本 | 自己变为成功或过期；当前输出变了，所以下游过期 | 版本列表多一版。变体条显示这一版。 |
| 只补当前版本里失败的格子，且指纹未变 | 是 | 不新开版本 | 若对外输出没变，下游不过期；若补完后当前变体换了，下游过期 | 成功格子的种子不变。 |
| 运行失败，一张都没有 | 否（指针未变） | 不新开版本 | 不因为失败本身再去标下游 | 旧图留着，徽章失败。 |
| 取消成功 | 否 | 无 | 无 | 短暂「已取消」，徽章回到静止态。 |
| 切换变体或切换版本 | 是 | 无 | 下游；自己是否过期见第 10 节 | 预览换成那一张。 |
| 拖出变体到空白 | 是 | 新的是节点，不是版本 | 无 | 源变体条还在。 |
| 拖出并连到槽 | 是 | 新节点 | 目标及其下游 | 源不变。 |
| 保存成功 | 清除脏标记 | 覆盖工程文件，不是生成版本 | 无 | 不弹成功对话框。 |
| 保存失败或保存冲突 | 保持脏 | 不写坏原文件 | 无 | 第 5 节的句子。 |
| 另存为 | 新文件从干净开始 | 复制版本列表 | 无 | 新 `projectId`。 |
| 撤销到与上次保存一致 | 清除脏标记 | 不能撤销掉已落地的生成版本 | 指纹若恢复，过期角标消失 | 撤销栈空时按钮为灰。 |

复制节点：新 id，位置错开，两端都在被复制集合里的边一起复制。只有一端在集合里的边不复制，避免悄悄占掉外面的槽。复制品若原件正在排队或运行，复制品回到静止徽章，不继承那条任务。版本和媒体引用按原样复制（同一哈希）。这是内容脏，不是新的一次生成。

## 12. 三种运行

运行动作只有三个，不要合并成一个含糊的「运行」。拓扑顺序和跳过原因由执行侧计算，画布只展示它返回的计划和每个节点自己的徽章。计划摘要必须是人话。跳过用中性样式，失败才用错误样式。

**运行此节点。** 只跑这一个生成节点。不把上游加进来，也不跑下游。上游即使过期，也只读取它现在的输出。计划里若用到了过期输入，摘要写：「将用上游当前的过期结果运行 1 个节点。」不阻断。

当前徽章若是成功且指纹相符，先确认：「当前结果还没过期。再跑会新增一个版本，旧结果还留在版本里，不会被盖掉。」主按钮：「新增版本并运行」。次按钮：「取消」。空、失败、过期不弹这句，因为用户点运行就是想要一次新的结果。

文本节点和别的素材节点没有「运行此节点」。悬停：「文本不用跑。改字之后，用到它的节点会标成过期。」其他素材把「文本」换成该种类。

**运行下游。** 不含起点自己。只跑下游里空、失败、过期、以及部分成功且仍可补失败格子的生成节点。指纹相符的成功节点跳过。起点是文本时，不为文本建任务。

若起点自己是过期或失败的生成节点，先说明：「这次不会重跑当前节点。下游用的是它现在的输出。」主按钮：「仍然运行下游」。次按钮：「取消」。用户若要先更新起点，取消后再点「运行此节点」。不在这里发明第四个运行命令。

**运行选中部分。** 先把分组展开成节点。只考虑选中的生成节点，不把选区外的节点拉进来跑。选区外的上游只作为当前输入。选中的生成节点即使用户没改过也要跑，因为这是点名。跑之前若其中有指纹相符的成功节点，确认：「选中的生成节点都会再跑，包括还没过期的。每个都会新增版本。」选区里至少要有一个生成节点。只有一个时也允许，效果与「运行此节点」相同，包括上面的确认。

同一批里，某个选中节点所依赖的另一个选中节点失败了，或因缺输入没跑：下游这个不提交。句子：「上游没成功，这一步没跑。」与它没有依赖关系的选中节点继续。一批的摘要要点名数量，例如：「这一批 3 个节点：1 个成功，1 个失败，1 个因上游失败没跑。」

双击或在已经排队、运行时再点：不产生第二批。句子：「这个节点已经在跑。」

三个按钮在后端断开时都禁用。悬停：「后端没连上，现在不能跑。」

删除选择、右键里的运行项，都使用同一套可点条件和同一句悬停。不可点的菜单项留在菜单里并禁用，不要只在控制台解释。

本机并发为 1，交给本机车道自己排队。云端另一条车道。调度器启动时不扫描全部过期节点来补跑。过期但用户没点的节点保持过期。

## 13. 失败、空和过期时用户看见什么

节点上只放一句中文。运行记录里是同一句，外加可选详情。详情默认收起，最多 200 个字符。不出现栈、密钥、完整工作流、磁盘绝对路径、类名。进度或错误原文里若带有 `KSampler`、`VAE`、`CLIP`、`Load Checkpoint` 这些词，界面改显示「正在生成」或改成下表的人话，这只是显示过滤，不是在解析工作流。

下表的句子与执行说明里已经写定的保持一致，避免同一错误两套文案。预检类不改徽章；入队后的失败才进入失败徽章，并且旧的成功预览留着。

| 情况 | 句子 | 徽章 |
| --- | --- | --- |
| 缺提示词、原图或首帧 | 「还缺提示词。」「还缺原图。」「还缺首帧。」按缺的角色换名字 | 不变 |
| 种类不合 | 「这个槽要的是图片，连进来的不是。」 | 不变 |
| 配方不接受该角色 | 「这张配方还不能用遮罩。」其他角色同一句式 | 不变 |
| 参数越界 | 「宽度要在 256 和 2048 之间。」换成该参数的显示名和配方上下限 | 不变 |
| 没密钥 | 「还没有配置这一家的密钥。」 | 不变 |
| 还没接入 | 「这一类还没接入。」 | 不变 |
| 已在跑 | 「这个节点已经在跑。」 | 保持排队或运行 |
| 成环 | 「这些节点连成了环，没法决定先跑谁。」整批不入队 | 不变 |
| 连不上 ComfyUI | 「连不上本机 ComfyUI。请确认它已启动，并且后端配置的地址可达。」 | 失败。旧变体留着 |
| ComfyUI 拒绝提交 | 「ComfyUI 拒绝了这次提交。」 | 失败。旧变体留着 |
| ComfyUI 执行失败 | 「ComfyUI 执行失败。」 | 失败。新下标是失败占位 |
| 说完成但没有结果 | 「ComfyUI 说完成了，但没有返回图片。」视频则说「没有返回视频」 | 失败 |
| 图片没传到 ComfyUI | 「图片没有传给 ComfyUI。」 | 失败。不提交 |
| 图片没传到视频服务 | 「图片没有传给视频服务。」 | 失败。不进入等待 |
| 视频服务拒绝 | 「视频服务拒绝了这次提交。」 | 失败。旧变体留着 |
| 等视频超时 | 「等视频结果超时了。可以稍后只重试这一次。」 | 失败。不自动继续等 |
| 配方是界面格式 | 「这是 ComfyUI 的界面格式。本应用只接受 API 格式，并且要包在我们自己的配方里。」 | 不变，不入队 |
| 配方缺计算节点 | 「配方「标题」要用到的节点「类名」在这台 ComfyUI 里不存在。请换配方或改配方。」类名只出现在这句，不出现在画布节点图上 | 失败或运行前拒绝均可，旧变体留着 |
| 找不到配方 | 「找不到这张配方。」 | 不把旧成功改成失败。运行禁用 |
| 结果没进媒体库 | 「结果没有写进媒体库。」 | 失败 |
| 视频衍生物没齐 | 「视频文件已经下载，但封面或代理没有生成，画布还不能播放。」 | 不进入成功版本，徽章失败。不改播原片 |
| 用户取消 | 短暂「已取消。」 | 回到静止徽章 |
| 重启对不上 | 「重启后没能对上上次的任务。可以续跑。」 | 失败，直到用户续跑或再运行 |
| 空 | 「还没有结果」 | 空 |
| 过期 | 角标「过期」，悬停「上游改过了，不会自动重跑」 | 过期 |
| 跑完时输入已变 | 「跑完的时候输入已经变了，这张图已标成过期。」 | 过期 |
| 工程版本太新 | 「这份工程是更新的版本写的，画布没有打开它，以免写坏。」 | 整份不打开 |
| 工程版本太旧或没有 | 「还不能打开这个版本的工程。」 | 整份不打开 |
| 后端启动时不在 | 「请先启动本机后端。」 | 不进画布 |
| 中途后端断开 | 「本机后端没连上。这个窗口里的修改还在，但现在不能保存，也不能生成。」 | 已打开的节点留着 |
| 保存失败 | 「没能保存，修改还在。」 | 保持未保存 |
| 保存冲突 | 「这份工程在这次打开之后被写过。为避免覆盖，请另存为。」 | 保持未保存 |
| 媒体路径不合法 | 「媒体路径不是相对的正斜杠路径，节点没创建。」 | 不创建 |
| 文本太长 | 「文本太长，没有放进节点。」上限 100000 个字符，沿用画布说明的选定上限 | 不创建 |
| 缩略图失败 | 「缩略图没加载出来」，并有「重试」 | 节点和边不动 |
| 命令做不成 | 「这一步没能完成，画布还保持原样。」 | 文档不变 |
| 没有任何错误句子 | 「生成失败，没有更多说明。」 | 按失败显示 |

跳过不是失败。摘要例如：「将运行 2 个节点，跳过 1 个未改过的节点。」

空画布中央一行弱提示，沿用画布说明：「从左侧加上文本或生成，或把图片拖进来」。有任意节点后隐藏。它不是模态。

失败和过期必须有文字，不能只靠颜色。状态芯片和预览区所占的高度在空、排队、运行、成功、失败、过期之间不抽掉，避免节点上下跳动。具体像素以画布说明的固定分区为准，产品要求的是这个结果。

## 14. 视频和音频在产品上的差别

视频不是一张很大的图片。无论是生成版本里的视频变体，还是导入的视频节点，媒体引用都使用同一组字段：

| 字段 | 含义 |
| --- | --- |
| `relativePath` | 原文件的工程内相对路径。画布不得把它设成播放地址。 |
| `contentHash` | 原文件哈希。未知则为空，不要编。 |
| `width` `height` | 像素。未知则为空。 |
| `durationMs` | 时长，毫秒。未知则为空。界面显示为 `m:ss`。没有时长就显示「时长未知」，不要显示成 `0:00`。 |
| `firstFrameRelativePath` | 首帧图。 |
| `lastFrameRelativePath` | 尾帧图。 |
| `coverRelativePath` | 封面。节点上画的是封面，不是原片的一帧现场解码。 |
| `proxyRelativePath` | 唯一允许被画布播放的文件。 |
| `thumbRelativePath` | 近景图片用的缩略图。视频节点不靠它播放。 |

生成出来的视频，只有时长、首帧图、尾帧图、封面、代理和原文件哈希都写进媒体库之后，才进入成功版本。缺任何一件，这次不算成功，句子见第 13 节，画布不改播原片。

导入的视频不是生成，没有成功或失败徽章。原文件入库后节点就可以存在。代理未就绪时，播放控件禁用，句子：「正在准备预览」。代理最终失败：「预览没准备好，画布不播放原片。」封面可以先显示。两种情况下都提供「在文件夹中显示」，打开的是系统里的文件位置，不是在节点里播原片。

播放若存在，只能发生在画布覆盖层的预览里，地址只能是代理。节点矩形上不放原片，也不循环播放。远看时视频是带播放三角的色块，不是一张没有时长的图。手势和远近层次由画布说明规定。

首帧图、尾帧图、封面是视频节点上的芯片，不是自动出现的节点。用户把芯片拖出去，才得到图片节点，引用那张帧图的哈希。帧文件还没有时，芯片禁用，句子分别是「首帧还没好」「尾帧还没好」「封面还没好」。

在「一条图生视频」阶段之前，把视频文件拖进画布：不创建节点，提示「视频文件还不能导入」。

音频节点第一刀不出现在添加菜单里。角色枚举保留 `audio_reference`，但没有可运行节点会提供这个槽。若更晚的阶段做导入，音频节点显示时长和播放、暂停，不画波形，也不编造峰值。在那之前把音频文件拖进来，提示「音频文件还不能导入」。

图片导入从第一刀的文本阶段之后、文生图之前就要能用，以便图生图有原图。拖入或选择文件后，先入库，成功才创建节点。等待时可以有「正在放入…」。失败不留节点。

## 15. 界面上用户能找到的东西

本文不规定字体、颜色和坐标算法。区域要有，是为了让字段有地方放。

顶栏：工程名、未保存点、保存、另存为、本机后端是否连上、本机 ComfyUI 是否可达。后端和 ComfyUI 分成两件事。后端在而 ComfyUI 不在时，仍可编辑和保存；本机生成按第 13 节失败；不依赖 ComfyUI 的云端任务是否可跑，由那张配方自己决定。

工具栏从能力列表渲染，不把某一家的名字写死在按钮上。第一刀可见项：文本、导入图片、文生图、图生图、参考图生成。图生视频在它的阶段变为可点。文生文、文生视频、对口型从文生图阶段起就出现在「以后再做」，禁用。

画布：无限平面。空状态见第 13 节。平移和缩放不标脏。

单选检查器：

- 文本：标题、正文、说明「改字并提交后，用到它的节点会过期」。有「运行下游」，没有「运行此节点」。
- 图片素材：预览、像素尺寸、替换文件、来源是导入还是从哪个节点的哪一版拖出。
- 视频素材或视频结果：封面、时长、代理是否可播、首帧图和尾帧图芯片、「在文件夹中显示」。没有原片播放按钮。
- 生成节点：主徽章和一句原因、当前预览、当前版本的变体条、版本切换、从上到下的槽（角色名和从 1 开始的序号）、中文参数、配方标题、实际种子、「运行此节点」和「运行下游」。
- 排队时主按钮是「取消排队」。运行时是「取消运行」。过期时主按钮仍是「运行此节点」，不要改成自动跑。

多选检查器不把多个节点的参数合成一份。只显示「已选 N 个」、删除、以及「运行选中部分」。

运行记录：这一次的计划摘要、每个节点是跑了、跳过了还是失败了。不展示工作流 JSON，不展示密钥。

设置：本机后端地址一类的本机配置、密钥的已配置状态、重新检查 ComfyUI。这些不写进工程文件。

右键和快捷键的清单以画布说明为准。产品只要求：运行三项的中文名不要改义，禁用时看得到原因。

## 16. 每个阶段用户能完成的事

每一阶段都在本机 Windows 上、用浏览器加本机后端演示。后一阶段不得把前一阶段的句子、禁用态和「不自动重跑」退回去。精美在这里的含义是：空状态有引导、徽章和预览区不乱跳、失败和过期有中文、按钮禁用时有原因、线有角色名。不要求独立的美化阶段，也不在这里规定帧率。

**阶段 1：文本工程。**

用户能新建工程，看见空画布提示，添加文本，输入中文并提交，移动节点，平移和缩放，看见「未保存」，保存，再打开后正文还在，视口还在。撤销能收回这一次打开里的改字和移动。关掉再打开，撤销是空的。工程文件里是正文，不是二进制。把文本拖得太长会被拒绝。后端没启动时进不了画布。

这一阶段还不能出图。验收时故意保存失败一次（例如目标文件不可写），必须仍是「未保存」，句子是「没能保存，修改还在。」

**阶段 2：文生图。**

用户能把文本连到文生图的提示词槽，也能只用草稿跑通一次。线的标签是「提示词」。点运行后立刻看见「正在安排……」，然后排队、运行、成功或失败。成功的图来自媒体库的相对路径，工程里没有图像字节。再跑一次会多一个版本，能切回第一版，旧图还在。ComfyUI 没开时看见第 13 节那句，不是空白或一叠栈。缺提示词时徽章不变，槽旁是「还缺提示词。」本机同时只跑一个：第二个任务显示排队，而不是和第一个一起跑。运行中改字，这一次跑完，节点过期，并出现「跑完的时候输入已经变了，这张图已标成过期。」没有自动第二跑。

「以后再做」里已经能看见图生视频、文生文、文生视频、对口型，点上去只有「这一类还没接入。」

**阶段 3：图生图、参考图、变体、汇合和三种运行。**

用户能导入图片，做图生图（提示词加正好一张原图），做参考图生成（至少一张参考图，并可加上风格参考和角色参考）。槽有从上到下的序号。交换两个槽，目标过期，源不过期。一个图片输出可以连到两个生成节点。一次最多要 4 张变体；多要会被拒绝。变体留在条里。拖到空白得到新图片节点，源条还在，下游不因此过期。拖进一个槽则会替换该槽并让目标过期。

改上游文本后，只有下游生成节点过期，网络上没有新的运行请求，直到用户点按钮。三种按钮的行为与第 12 节一致：运行下游不包含自己；没改过的分支被跳过并有中性句子；运行选中部分不会把没选中的过期上游自动拉进来跑。连了遮罩但配方不接受时，看见「这张配方还不能用遮罩。」

取消尚未开始的任务后，徽章回到静止态，没有新版本。4 张里只成功一部分时，失败格可见，可以只补失败的几张，已成功的种子不变。关掉后端再打开，过期节点不会自己跑；未完成的那次要么继续显示核对中的排队或运行，要么给出重启那一句。

**阶段 4：一条图生视频。**

用户能把一张图连到首帧，可选地连尾帧和提示词，运行这一条图生视频。成功的节点或拖出的视频节点上能看见时长、封面、首帧图和尾帧图。播放的只是代理。代理没好时按钮是「正在准备预览」或失败句子，节点上的请求不是原片。缺首帧、时长不在配方档位内、没密钥，三次都在提交前失败，各有第 13 节的句子。过期和版本规则与图片相同。文生视频和对口型仍然禁用。

没有密钥和真实厂商授权时，不得演示成已经出片。可以用执行侧的本地夹具把状态和字段走完，但界面不得写某一家的名字，也不得显示伪造的成功视频。真实厂商只有在适配器作者自己有可用授权时才替换夹具。本文不记录那次请求。

导入视频文件在这一阶段开放，并遵守不播原片的规则。

**阶段 5：可以后移。**

导入音频，看见时长，可以播放。仍然没有对口型可跑，所以音频参考槽不会出现在可运行节点上。若要砍范围，整段不做，角色枚举保留。砍掉之后，前四个阶段的验收仍然成立。

## 17. 非目标

第一版明确不做这些事。没写在第 16 节里的，默认也不是这一刀的承诺。

- 不把 KSampler、VAE、Checkpoint、CLIP 画成用户能连的节点，也不做「在 ComfyUI 里打开这张图」的往返编辑。
- 不做任意工作流的导入导出。
- 不把每个变体自动铺成节点，也不在松手到空白时自动造一个用来连线的无名节点。
- 不在上游一变时自动重跑，不用自动重跑来掩盖过期。
- 不在画布上播放原片，不把视频画成没有时长的大图，不在画布里做遮罩画笔或音频波形。
- 不做桌面壳，不把 Electron 或 Tauri 当成第一版前提。
- 不做纯静态页，不让浏览器持有 API Key 或直连 ComfyUI。
- 不把密钥、媒体字节、ComfyUI 地址写进工程。
- 不做文生视频、对口型、文生文的可运行适配器，不做第二家云厂商，不做云端文生图。
- 不做本地并行跑多个生成，也不提供调节并行度的控件。
- 不做多人协作、冲突合并以外的「另一窗口正在写」提示已经由保存冲突覆盖。不做评论、图层市场、插件商店。
- 不做工程级时间旅行。结果历史只到生成节点的版本列表。
- 不回收无引用媒体，不在第一版保证磁盘不增长。
- 不把任务库拷进工程，因此只拷工程文件到另一台机器时，不保证失败句子还在。
- 不规定、也不宣称帧率、并发吞吐或某一家模型的时延。

## 18. 因已定边界而放弃的做法

边界冲突时以边界为准。下面这些是因此不采用的做法，避免以后被当成漏做。邻域说明里若仍写着相反的句子，实现时改邻域，不改边界。

- 放弃把本产品做成 ComfyUI 的另一种节点皮肤。那样能更快接上现成工作流，但用户会看见计算节点，直接违反「不是第二个 ComfyUI」。
- 放弃任意工作流往返。放弃把浏览器直连 ComfyUI 当成省掉后端的办法，因为那既是纯静态页走不通的跨域，也会把密钥和计算图带到页面上。
- 放弃第一版桌面壳。验收环境就是本机浏览器加本机后端。
- 放弃上游一改就自动重跑，包括「只自动跑脏了的那几个」这种省事路径。过期必须停在角标上，等用户点三个运行动作之一。
- 放弃无角色、无顺序的线束。也放弃一个槽上挂多条无名线。多个参考图就是多个有序号的槽。
- 放弃把图生图做成「一到四张参考图」。图生图的底图是原图槽。参考图生成才使用参考图、风格参考和角色参考。画布说明里的演示预设若把图生图写成参考图槽，以本文为准。
- 放弃把变体拖出做成「从条里抠走」。抠走会改变源节点的当前输出，整条下游被标过期，和「我只是想把这张图放到画布上」相反。第一版是引用抽出：新节点共享哈希，源变体条保留。
- 放弃成功运行时替换整条变体、删掉上一版。边界要求分得清新版本和覆盖。覆盖只发生在保存工程、改正文、改参数、替换素材指针。生成成功只追加。
- 放弃画布内播放原片，以及封面没好就退回原片。也放弃视频节点没有时长、首帧图、尾帧图、封面和代理这些字段。
- 放弃在第一刀做文生视频、对口型、更多厂商。能力种类和剖面 id 先留着，菜单里禁用。
- 放弃本地并发大于 1，也放弃把云端并发写成某一家的真实配额。初值 2 只是产品初值。
- 放弃把 API Key 放进工程换取「拷走文件夹就能跑」。换机器后需要重新配置密钥。这是边界，不是漏做。
- 放弃第一版媒体垃圾回收。历史版本和拖出节点可能共享哈希，收早了会把还在用的文件删掉。

另外放弃的、并不是边界原文点名、但会和上面几条打架的实现：永久把节点标成「已取消」；缺一个提示词就把已有成功徽章改成失败；运行下游时偷偷把起点自己也跑了；运行此节点遇到新鲜结果时静默跳过，让用户以为按钮坏了。这些在第 10 节和第 12 节已改成可演示的行为。

## 建议落在哪些阶段

阶段按第 16 节的用户切片切割。邻域在同一阶段里做自己的那一截，但阶段结束的标准是用户能完成的事，不是只有色块或只有日志。

| 阶段 | 用户能演示的事 | 产品上必须已经成立的规则 | 主要落点 |
| --- | --- | --- | --- |
| 1 文本工程 | 空画布、写字、脏标记、保存、重开、撤销 | 工程不嵌二进制；视口不算脏；保存失败保持脏 | 工程文件、画布手感、文本节点 |
| 2 文生图 | 一条提示词出图；排队和失败有句子；再跑多一版 | 六种徽章、追加版本、本机并发 1、预检不毁旧图、以后再做的入口禁用 | 本机配方的文生图、任务库、变体条的一版 |
| 3 图生图与参考图 | 原图槽、有序参考槽、拖出变体、三种运行、取消和部分失败 | 过期不自动跑；运行下游不含自己；遮罩不静默丢弃 | 槽与指纹、三种 scope、导入图片 |
| 4 一条图生视频 | 首帧到一段视频；只播代理；缺密钥有句子 | 视频字段齐才算成功；文生视频和对口型仍禁用 | 一条云端或夹具通路、ffmpeg 的衍生物、密钥端口 |
| 5 可后移 | 导入音频 | 对口型仍然不可跑 | 音频素材节点。砍掉不影响前四阶段 |

阶段 2 结束时，能力描述符的形状就不再为「以后还有视频和对口型」而改字段。新厂商应是新的绑定加新配方，不是新的节点种类，也不是新的连线方式。若某种输入放不进第 7 节的角色，先加角色并写明显示名，不要在画布上临时拉一条没有角色的线。
