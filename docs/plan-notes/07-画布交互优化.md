# 无限画布

本文是这个仓库的分析，不是主文件，也不是修改清单。阶段、字段和验收仍以 [无限画布开发方案](../无限画布开发方案.md) 为准。做到哪一步只写在 [进度查询与工程审查](../进度查询与工程审查.md)。过程讨论在 `docs/plan-notes/` 的前几份里，和本文打架时以开发方案第 1.3 节为准。

此后在这个仓库里的工作，以修改这张已经存在的无限画布为主线。先认得它是哪一个系统，再在这个系统上改。不另起一个产品，不把计算图画到画布上，也不在本文里记修改意见或进度。

## 1. 它是什么

这是一个人、一台电脑、一个窗口里的本地应用。用户在一张没有边界的画布上摆文本、图片、视频、音频和生成结果，用带角色、有顺序的线把它们连起来，再自己点运行。

画布是本体。用户看见的只有五种节点：文本、图片、视频、音频、生成。生成节点上的东西是一次结果，不是一张 ComfyUI 计算图。KSampler、VAE、Checkpoint、CLIP 不出现在画布上。配方留在本机，用户只看见配方的标题。

生成对画布只有一个入口。本机 ComfyUI 和云端模型换的是配方或绑定，不是另一套连线。浏览器不持有密钥，不直连 ComfyUI，不读磁盘。

一条能走通的路径是：写一句提示词，连到文生图，运行此节点，图出现在这个节点里，不自动铺成一排新节点。同一句文字可以连到两个生成节点。改一次字，两个都过期，而且都不会自己重跑。多张图汇进一个节点时，顺序就是槽从上到下的顺序，没有一捆没有角色、也没有先后的线。

## 2. 文档长什么样

一个工程是用户选定的一个文件夹。身份是 `projectId`。文件是 `canvas.project.json`，旁边有备份和自动保存。媒体库在同一文件夹里，按 SHA-256 存放。工程 JSON 只记正斜杠相对路径和参数，不记盘符、反斜杠、二进制、API Key，也不记 ComfyUI 地址。

`nodes`、`edges`、`groups` 都是按 id 的映射，不是数组。节点可以落在负坐标。分组是画布上的框，不是第六种节点，也不是一次运行的单位。分组不改变连线的含义，不进指纹。运行前先展开成里面的节点。

槽是生成节点上的有序入口。同一时刻一个槽最多一条线。角色写在槽上：提示词、原图、参考图、风格参考、角色参考、遮罩、首帧、尾帧、音频参考。边从源节点的当前输出落到目标槽。边不记变体下标。换当前变体就是换输出，下游因此过期。

版本是一次运行产生的一批变体。新的成功追加版本，不覆盖旧版本的媒体。变体默认留在节点底部的横条里。拖到画布上是抽出一份引用，源变体条里原来的还在，不是抠走。当前输出是当前版本里选中的那一个变体，扇出的下游读的都是它。

过期不是失败。节点上还有旧的成功结果，但指纹已经对不上现在的输入或参数。预览仍留着旧结果。上游一变，只标过期，不自动重跑。会让下游过期的，是文字已上屏、改参数、换配方、连线、断开、替换、重排槽、增删槽、换掉素材。移动、改标题、改视口、只改还没生效的草稿，不加对外输出的修订号。

内容脏看 `contentRevision`。视口可以单独写，不点亮「未保存」。撤销栈只活在这一次打开里，不写入工程。保存是覆盖这一份工程文件。另存为必须换新的 `projectId`。磁盘上的修订号如果已经不是这次打开时读到的值，拒绝覆盖，避免写坏别人刚写过的那一份。

`schemaVersion` 只接受 1。太新或太旧，整份不打开。

## 3. 运行时怎么切开

浏览器只访问 `127.0.0.1` 上的 HTTP 和 WebSocket。令牌在地址片段里。变更请求要核 Origin 和 Host。媒体字节不走自定义头，走短时票据，所以近景图片的地址是票据，不是磁盘路径，也不是原图。

后端同一时刻只打开一个工程。工作副本在后端内存里。运行读的是这份副本，浏览器不必为了生成先点保存。客户端提交的是合并，不是整表覆盖。排队、运行、版本和哈希以服务器刚写的为准。用户编辑带来的过期，在前端用和后端同一套函数算，再随副本同步。生成落地由后端写副本，再把补丁送回页面。

任务库是应用数据目录里的 SQLite，不进工程文件夹。所以工程可以拷走，旧结果还在工程里，失败句子和未完成队列可以不在。这是这个系统的形状，不是少做的一项。

密钥进 Windows 凭据库，不进工程，也不进 `app.json`。ComfyUI 的地址写在应用数据里。ffmpeg 由后端按需拉起。找不到时进程仍能启动，视频侧降级，不把原片播到画布上。

本地车道一次只向本机生成提交一个变体。真正的采样队列在用户自己启动的 ComfyUI 里。本仓库不安装、不内置 ComfyUI。云端适配器在核心外面，第一张视频路径是不联网的夹具。没配密钥就在提交前停住，不发请求。

可运行的能力是文生图、图生图、参考图生成，以及一条图生视频。文生文、文生视频、对口型只留接口，出现在界面上但是禁用。三个运行动作是：此节点、下游、选中部分。下游不含起点自己。选中部分展开后至少一个生成节点即可。运行按钮发出的是 `RunScope`，没有另一套 `RunIntent`。

## 4. 画布怎么成立

画布内核是自研的。近处是 React 画的节点外壳，一张 Canvas 2D 画连线和远处的色块。不用 xyflow、tldraw 这一类当内核：那些库的基本形是端口对端口，或是形状绑定，会把这张画布拖向第二个工作流编辑器，也没有「远处卸掉 DOM、只留色块」。

相机的 x、y 是视口中心对应的世界坐标，不是左上角。缩放锚在指针。范围在方案里写成 0.08 到 2.5。平移和缩放走世界层的 `translate3d` 和 `scale`。拖拽过程不把每一下指针移动推进 React 状态，也不写进撤销。松手才是一条移动命令。

手势同一时刻只有一个：平移、框选、移动、拉线、抽出、重排槽。按下没超过阈值算点击。远景节点仍然可以被选中和拖动，不因为没有 DOM 就变成不能动的色块。命中从上到下要能分清槽、输出口、近景节点、远景色块、边和分组。槽和分组叠在一起时，点中的是槽。

文本是系统输入法的事。组字从 `compositionstart` 到 `compositionend` 不提交命令，也不拿去缩放画布。已上屏才算内容变了。

近景挂载有上限。再远就只画色块。缩略图走票据，解码有并发上限。视频节点上是封面和时长，播放的是代理，不是原片。没有时长就显示时长未知，不用 `0:00` 假装是空片。

小地图、开发夹具和远中近三档，是这张画布能放大到一千个节点时仍成立的方式。难的是命中、槽、输入法和变体条，不是第一天换成 WebGL。

## 5. 仓库怎么对应这张画布

`packages/schema` 是前后端共用的契约：工程类型、校验、连线规则、过期、提示词和槽媒体怎么解析、配方文件长什么样、人话句子。别的包不再写一套同名字段。

`apps/web` 是画布。文档和手势在 `src/canvas`，运行按钮和事件在 `src/execution`，壳在 `App.tsx`。页面只打本机能力接口。

`apps/backend` 是工程、媒体、任务、密钥和执行。HTTP 只听本机。Comfy 客户端、ffmpeg、凭据库都在这一侧。

`apps/desktop` 是后来包上的窗口。它不重写命中和撤销。窗口里的指针和滚轮应与浏览器里同一套。

`recipes/` 里是填槽用的配方。界面格式的 Comfy 工作流会被拒绝。虚构配方用来把槽填进 API 格式，不是某一台机器上已经核实过的工作流。

`eval/` 不是这个产品的模块。

## 6. 主线

这个仓库已经是一张无限画布，不是一份还没开工的计划。方案正文写它的边界，审查文件写阶段走到哪。实现铺在上面说的四个包里。

以后的主线任务就是修改这张画布：改它的手势、文档、生成怎么落回节点、媒体怎么被看见、工程怎么被打开和拷走。修改时它仍是第 1 节那个系统。节点仍只有五种。生成仍从有序槽进去，从当前输出出来。上游改了仍只标过期。浏览器仍不碰密钥和磁盘。

本文不列出要改什么，也不记录已经改到哪。那些分别属于当次的修改，和审查文件里的进度。
