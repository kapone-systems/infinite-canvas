# 执行与模型接入

本文是从零开始的本地无限画布里，「执行与模型接入」这一块的开工说明。读的人没参加过讨论，也应能按本文把任务队列、配方填槽和两类后端接起来。

工作区在写本文时没有可依赖的产品代码。2026-09-22 在工作区根目录执行：

```text
find . -type f \( -name "*.md" -o -name "*.json" -o -name "*.txt" \) ! -path "./eval/*" ! -path "./.zcode/*"
```

该命令在 `eval/` 与 `.zcode/` 之外没有列出产品源码。`eval/infinite-canvas-src/` 里有另一份材料，本文不把它当成已有模块，也不引用它的类型、路径或接口。下面所有「建议放在某文件」都是新仓库里的建议路径，不是已经存在的文件。

本文不画像素，也不做缩略图编码。视频封面和代理文件只规定任务结果里必须有的字段，以及要调用哪个邻域；编码参数不在这里定。

## 1. 这份说明要定下来的事

画布上的生成只有一个入口。节点不关心后面是本机 ComfyUI，还是某个持有 API Key 的外部模型。两边都实现同一套能力接口。

本机这一侧只做一件事：用我们自己的配方，把有角色的有序槽填进 ComfyUI 的 API 格式工作流，再交给 ComfyUI 执行。不把 KSampler、VAE 这类计算节点画到画布上，也不做任意工作流的往返编辑。

云端第一刀只接一条图生视频。文生视频、对口型、更多厂商先留在接口里，不在第一版注册可运行适配器。

本地车道同时只跑 1 个生成任务，真正的采样队列在 ComfyUI 里。云端车道另有自己的并发上限，和本地车道互不等待，除非节点之间有连线依赖。

上游一改，只把下游标成过期。没有任何路径会因为「脏了」就自动开跑。用户能点的运行动作只有三个：运行此节点、运行下游、运行选中部分。

## 2. 已经核实和尚未核实的事

下面两页是 2026-09-22 抓取的 ComfyUI 公开文档，只用来拟定集成，不能代替对本机已安装版本的核对。

- 路由页：<https://docs.comfy.org/development/comfyui-server/comms_routes>，标题为 ComfyUI Server Routes。该页列出了方法与路径，以及 `POST /prompt` 成功时的顶层字段 `prompt_id`、`number`，失败时的顶层字段 `error`、`node_errors`。同页没有给出 `POST /prompt` 的请求体字段表，没有给出上传表单的字段名，没有给出 `GET /history/{prompt_id}` 的响应结构，也没有给出 `POST /queue` 的请求体。
- 消息页：<https://docs.comfy.org/development/comfyui-server/comms_messages>，标题为 ComfyUI Server Messages (WebSocket API)。该页写明执行过程中或队列状态变化时，服务端经 `PromptServer.send_sync` 推送消息，并注明客户端监听位置以当时的 `api.js` 为准。页面没有写适用的服务器版本号。

消息页列出的内置事件和数据字段如下。`execution_error` 的附加信息该页没有逐项展开，本文不补造字段。

| 事件 | 文档中的数据字段 | 我们怎么用 |
| --- | --- | --- |
| `execution_start` | `prompt_id` | 把对应任务从「已提交」标成「执行中」 |
| `executing` | `node`（节点 id，或 `None` 表示整段结束）、`prompt_id` | 只做进度条文案，不把它当成出图成功 |
| `progress` | `node`、`prompt_id`、`value`、`max` | 有则显示确定进度；没有则保持不确定进度 |
| `executed` | `node`、`prompt_id`、`output` | 文档说只有节点返回 UI 更新时才发，不是每个节点结束都发。不作为完成条件 |
| `execution_cached` | `prompt_id`、`nodes` | 只记日志。跳过与否仍由我们自己的指纹决定 |
| `execution_success` | `prompt_id`、`timestamp` | 可以开始取历史和取图。取图成功后任务才算成功 |
| `execution_error` | `prompt_id`，另有文档未展开的附加信息 | 任务失败。详情里只放我们能安全读到的短句，没有就不编 |
| `execution_interrupted` | `prompt_id`、`node_id`、`node_type`、`executed` | 若是用户取消，任务为已取消；否则为失败 |
| `status` | `exec_info`，其中含 `queue_remaining` | 用来显示「前面还有没有别人的任务」，不用来判断我们的图好了没有 |

路由页还列出了这些和本文有关的路径：`POST /upload/image`、`POST /upload/mask`、`GET /view`、`GET /prompt`、`POST /prompt`、`GET /object_info`、`GET /object_info/{node_class}`、`GET /history`、`GET /history/{prompt_id}`、`POST /history`、`GET /queue`、`POST /queue`、`POST /interrupt`、`GET /system_stats`。WebSocket 路径为 `/ws`。该页列出的消息类型比消息页少，以消息页的事件表为准，仍须对照本机版本。

本文没有启动 ComfyUI，没有发过云端请求，没有做性能测量。凡是写着「需对照本机版本核实」的字段，实现时先写解析测试的夹具，用本机实际响应填上，再让任务跑通。不要按社区博客把字段名写死后再说已经核实。

`POST /prompt` 的请求体在上述路由页没有展开。API 格式工作流「以节点 id 为键、每个节点含 `class_type` 与 `inputs`」是本产品的拟定形状，也是配方例子里使用的形状。它不是从这次抓到的文档页抄下来的字段表。落地前必须用本机 `GET /object_info/{node_class}` 核对类名和输入名。

## 3. 运行形态

第一版是本机浏览器加本机后端。不是纯静态页，也不是 Electron 或 Tauri。浏览器只访问本机后端，不直接访问 ComfyUI，也不持有 API Key。这样避免跨域，也避免密钥进页面。

后端负责四件和执行有关的事：代理 ComfyUI、保存任务库、按内容哈希把生成字节交给媒体库、按需向系统凭据库要密钥。工程文件、ffmpeg、画布几何不在本文实现，但本文写明要交给它们的字段。

开发机是 Windows。工程内引用一律是正斜杠相对路径，不以 `/` 开头，不写盘符。后端只在调用文件系统或 ffmpeg 的那一层把相对路径换成系统路径。

建议后端用 Node.js，这样下面的 TypeScript 契约可以放在前后端共享的源文件里。这是开工选型，不是现有代码。共享契约建议放在 `shared/execution-types.ts`。后端执行逻辑建议放在 `server/execution/`。这些目录现在都不存在。

ComfyUI 的基地址是后端配置项 `comfy.baseUrl`，由使用的人填写。公开路由页没有规定端口，本文不把任何一个端口写成已核实的默认值。配置缺失或连不上时，行为见第 11 节，而不是静默改连某个地址。

## 4. 画布侧能看见什么

一个节点里是文本、图片、视频、音频，或一次生成结果。生成结果仍然落在同一个节点上，用变体条收纳多次输出。变体默认不是新节点。只有用户把变体拖出画布时，才由画布域复制成新节点。执行域不创建画布节点。

连线带角色。汇合用有序槽：同一角色可以有多条入边，每条有从 0 起的 `order`，同一节点、同一角色内不得重复。执行域不接受「一捆没有角色、也没有顺序的线」。

角色枚举先包括任务书点名的这些：`prompt`（提示词）、`reference`（参考图）、`first_frame`（首帧）、`last_frame`（尾帧）、`style_reference`（风格参考）、`character_reference`（角色参考）、`mask`（遮罩）、`audio_reference`（音频参考）。

另外增加一个角色 `source_image`（原图）。图生图要改的是一张确定的图，它和参考图、风格参考、角色参考不是一回事。任务书里的角色列表用了「例如」，所以这里补上原图，并在文末说明这是本域为了能实现图生图而加的，不是把计算节点暴露给用户。若产品后来决定把原图并进参考图的 0 号槽，要同时改配方绑定和图生图剖面的 `minCount`，不能只改一边。

文本节点没有模型调用。它的正文就是结果。对文本节点，「运行此节点」禁用，界面写：「文本不用跑。改字之后，用到它的节点会标成过期。」从文本节点点「运行下游」时，不给文本节点建任务，只计划它下游里真正要跑的生成节点。

一个生成节点分出多个结果时，结果是变体条上的多项，不是多条无名输出线。多个节点汇成一个结果时，靠有序槽进入同一个目标节点的一次运行。目标节点成功后，变体条上出现新结果；上游节点自己的结果不动。

## 5. 统一能力接口

能力种类只有少数几个。文生图、图生图、参考图不是三套接口，而是 `image.generate` 的三个剖面，用必填槽区分。图生视频和以后的文生视频同属 `video.generate`，用剖面区分。对口型单独种类，第一版不注册适配器。

第一刀要能跑的剖面：

| 种类 | 剖面 id | 第一版 | 必填槽 | 可选槽 |
| --- | --- | --- | --- | --- |
| `image.generate` | `txt2img` | 要跑 | `prompt` 至少 1 段 | 无图像槽 |
| `image.generate` | `img2img` | 要跑 | `prompt` 至少 1 段，`source_image` 正好 1 张 | `mask` 最多 1 张。第一张图生图配方可以声明不接受遮罩 |
| `image.generate` | `reference` | 要跑 | `prompt` 至少 1 段，`reference` 至少 1 张 | `style_reference`、`character_reference`，张数上限写在该配方上 |
| `video.generate` | `img2video` | 在图像三条跑通后再接一条 | `first_frame` 正好 1 张 | `last_frame` 最多 1 张，`prompt`，`reference`。张数和时长受适配器约束 |
| `text.generate` | `complete` | 只留接口 | `prompt` | 无 |
| `video.generate` | `txt2video` | 只留接口 | `prompt` | `reference` |
| `video.lipsync` | `talking-head` | 只留接口 | 一张图槽加 `audio_reference` | `prompt` |

`implemented: false` 的剖面可以出现在类型和「尚未接入」列表里，运行入口禁用，文案是：「这一类还没接入。」不要为了演示去调一个空的云地址。

用户能改的参数用显示名，不出现类名。文生图第一张配方至少有这些用户参数：`seed`（整数或 `"random"`）、`width`、`height`、`steps`（显示「步数」）、`cfg`（显示「提示词相关性」）。变体张数是节点上的 `variantCount`，不是 Comfy 图里的 batch。它的下限是 1，上限第一版写死 4。这是产品上限，不是测出来的显存上限。超过 4 时，计划阶段就拒绝，界面写：「一次最多出 4 张。要更多，请再跑一次。」

模型文件不做成通用浏览器。第一版换模型等于换一张配方。配方内部可以用字面量写死 Comfy 的模型文件名，用户只看见配方标题。

随机种子在入队前就抽成具体的 32 位无符号整数，按变体下标各抽一个，并写进该变体记录。这样重启后续跑和失败重试不会偷偷换种子。用户以后要复现，看的是变体上的「实际种子」，不是 `"random"` 这个字。

### 5.1 TypeScript 草案

```ts
  implemented: boolean;
  /** 启动时 object_info 核对失败则为 false，并带上原因。 */
  enabled: boolean;
  disabledReason?: string;
}

interface LaneConfig {
  /** 字面量 1。不提供把本地并发调大的配置。 */
  localConcurrency: 1;
  /**
   * 云端同时处于 submitted/running 的任务数上限。
   * 初值 2，只是为了让第一版看得到「两条云任务可以重叠」。
   * 不是实测吞吐，也不是厂商限额。
   */
  cloudConcurrency: number;
}
```

画布只依赖 `CapabilityService`、`RunRequest`、`RunSnapshot`、`RunEvent`、`NodeFreshness` 和 `UserFacingError`。它不引用 Comfy 的类名，不拼云端 URL，不读密钥。

`GraphReadModel` 由节点图领域实现。执行域不扫描画布坐标，只问节点、槽和下游 id。

### 5.2 指纹

指纹是 sha256 的十六进制字符串。被哈希的字节是一段规范化 JSON，键排序固定，内容只包括：

- `recipeId` 与 `recipeVersion`
- 用户参数规范化之后的值（`"random"` 在抽种子之前不进入「成功指纹」；成功指纹里写的是每个变体的 `seedUsed`）
- `variantCount`
- 槽位按 `role`、再按 `order` 排列后的内容：文本用 UTF-8 正文，媒体用 `contentHash`，不用路径，以免同一字节换路径就误判为脏

上次成功的指纹存在节点的执行状态里。计划阶段用同一算法再算一次。相等且 `force` 不为真，就跳过。

任务开始时把当时的指纹记到 `fingerprintAtStart`。跑完后如果现算指纹已经不同，结果仍然写入变体条，但新鲜度写成 `stale`。界面写：「跑完的时候输入已经变了，这张图已标成过期。」不自动再跑。

### 5.3 过期怎么标

`markStaleFrom` 沿着传递下游走。不入队。规则：

- `fresh` 改成 `stale`。旧图还在，角标「过期」。
- 已经是 `stale` 的保持 `stale`。
- `empty` 保持 `empty`。没有旧结果，就不说「过期」。
- `failed` 保持 `failed`。下次会整组重跑，而不是只补失败变体。
- `partial` 改成 `stale`。变体条上已成功的那几张还看得见，但整组都过期，不能只补跑。
- `running` 不取消正在跑的任务。跑完再按上一节比较指纹。
- `interrupted` 改成 `stale` 或保持 `failed` 的语义：旧的中断任务不再续跑原 provider 作业，下次运行按新指纹整组跑。若任务库里那条仍是 `interrupted`，把它收成 `cancelled`，避免续跑按钮把旧种子交回去。

选中变体如果还在，下游槽继续读它，即使它已经过期。过期只是提醒，不是把图藏起来。

## 6. 三种运行动作和计划规则

`planRun` 与 `startRun` 使用同一套计划函数。`startRun` 在写入任务库之前再算一次，不信任浏览器上次缓存的计划。

范围：

- 「运行此节点」：`scope.type = "node"`。只考虑这一个节点。它的上游不管过期与否，都只读取当前选中变体。不把上游加进这一批。
- 「运行下游」：`scope.type = "downstream"`。集合是起点加上传递下游。起点若是文本节点，不建任务。起点若是 `fresh` 且不 `force`，跳过。下游里 `empty`、`stale`、`failed`、`partial`、`interrupted` 的生成节点进入待跑集合。
- 「运行选中部分」：`scope.type = "selection"`。只考虑选中的节点。选区外的上游只作为当前输入读取，不因为过期就被拉进来。选区内若某节点依赖的另一个选中节点被跳过或失败，按下面的依赖规则处理。

拓扑顺序按有向边。有环则这一批直接失败，不提交任何任务。界面写：「这些节点连成了环，没法决定先跑谁。」环检测属于图的不变量，执行域在计划时再查一次。

对待跑集合里的每个节点，按这个顺序决定，命中一条就停：

1. 节点不存在：跳过，原因按缺失输入处理，摘要里写「有一个节点已经不在画布上」。
2. 文本节点：跳过，原因 `text_node`。
3. 没有 `recipeId`，或种类未实现：跳过，原因 `not_implemented`，句子用「这一类还没接入。」
4. 配方文件缺失、是界面格式、或 `object_info` 核对失败：不跳过成成功，而是一条立刻失败的任务，原因 `recipe_rejected`。用户必须看见，不能当成「没有要跑的」。
5. 必填槽数量或类型不对：同上，立刻失败，不发往 Comfy 或云端。
6. 参数越界：立刻失败。
7. 同一节点已有 `queued`、`submitted` 或 `running` 任务：拒绝整次 `startRun`，不部分入队。错误码 `ALREADY_RUNNING`，句子：「这个节点已经在跑。」
8. `force` 不为真，且新鲜度为 `fresh`，且指纹相同：跳过，原因 `fresh`。
9. 同一批里，它依赖的节点计划为失败、或因失败/缺输入被跳过：本节点不执行，记 `upstream_failed` 或 `upstream_not_run`。
10. 其余：建任务，状态 `queued`。

跳过 `fresh` 不是失败。依赖一个被跳过的新鲜节点，等于读它现有结果，下游仍可跑。

`force: true` 只来自明确的「强制重跑」。三个主按钮默认都是 `force: false`。

一批里的任务全部写进任务库之后，`startRun` 才返回。返回体里带计划摘要。调度器异步执行。浏览器用 `subscribe` 收事件。第一版订阅用本机后端的 WebSocket；若实现时 WebSocket 来不及，可以用 SSE，事件名保持 `RunEvent` 不变。不要让浏览器去连 Comfy 的 `/ws`。

同一 `clientRequestId` 若已经有 run，返回那次的快照，不新建。

## 7. 任务库、车道和调度

任务库是后端数据目录里的 SQLite 文件 `execution.sqlite`，不放进工程目录，也不进工程 JSON。工程文件只保存节点上的执行状态（第 13 节），不保存队列。

建议表：`runs`、`tasks`、`variants`、`events`。`events` 追加即可，用来在刷新页面后把进度补齐。第一版不做跨机器同步。

每次状态变化在一个事务里写完：任务行、变体行、节点执行状态、事件。进程在事务中间退出时，重启后看到的仍是上一笔完整状态。

本地车道与云端车道各有一个调度循环。

本地车道：

- 并发恒为 1。没有配置可以把这个数改大。
- 从任务库取最早的 `queued` 且 `lane = "local"`、并且其同一 run 内的上游任务都已成功或被判定为可跳过的任务。
- 一次只把一个变体提交给 ComfyUI。一个节点要 4 张变体，就是串行提交 4 次，不在一张工作流里做 batch。这样失败时可以只重跑某一个下标。
- 提交用文档中的 `POST /prompt`。我们自己的队列仍是事实来源。不把一整批本地任务提前灌进 ComfyUI 的队列。原因：取消尚未执行的项所需要的 `POST /queue` 请求体，在已读的路由页里没有字段表；一次只提交一个，取消就可以落在「还没提交」或「正在执行所以调用 `POST /interrupt`」这两种文档能对上的情况里。
- 该变体到达终态（成功取图、失败、取消）之后，才提交下一个。
- 不调用 `POST /history`，不调用会清空队列的 `POST /queue`。第一版也不猜测「按 prompt_id 删除排队项」的报文。接入本机版本时，如果核实到了单条删除的字段，再补进本地车道，并加测试。在那之前，已提交但 Comfy 还没开始执行的取消，界面写：「已提交，等它一开始就停止。」调度器在收到该 `prompt_id` 的 `executing` 或 `execution_start` 后立刻 `POST /interrupt`。

云端车道：

- 并发数读配置 `cloudConcurrency`，初值 2。这是产品初值，不是实测出来的最佳值，也不是任何厂商的配额。
- 与本地车道并行。一个文生图在本地跑时，一条不依赖它的图生视频可以同时在云端跑。
- 若视频节点的首帧来自同一批里尚未成功的图像节点，视频任务留在 `queued`，不占云端名额。

调度器启动时不扫描「所有过期节点」来补跑。它只继续任务库里未结束的 run。过期但从未被用户点击运行的节点，保持过期。

## 8. 配方文件

配方是安装目录里的只读 JSON，建议路径 `recipes/<id>.json`。第一版修改配方后重启后端，不做运行中热替换。

工程和节点只存 `recipeId` 与当时的 `version`。不把工作流嵌进工程，不把 API Key 嵌进配方。

加载器必须拒绝这两类文件，并且一句人话说完，不把文件内容回显到界面：

- 顶层同时有数组 `nodes` 和 `links`：判定为 ComfyUI 界面格式。错误码 `RECIPE_UI_FORMAT`。句子：「这是 ComfyUI 的界面格式。本应用只接受 API 格式，并且要包在我们自己的配方里。」
- 顶层就是一张 API 格式的 prompt 字典、但没有我们的 `id`、`slots`、`bindings`：拒绝。句子：「请把 API 格式工作流放进配方的 comfy.prompt，不要单独导入一张工作流。」

`comfy.format` 只能是 `"comfy.api"`。其他值拒绝。

配方版本与加载器认识的版本不同：句子「配方版本不受支持。」节点保持原结果。

启动时，对每张 `enabled` 且 `lane = "local"` 的配方，对其中每个 `class_type` 请求 `GET /object_info/{node_class}`。缺任何一个，这张配方 `enabled = false`，`disabledReason` 写明缺的类名。不在每次点击时打一遍全量 `GET /object_info`。后端提供一个「重新检查 ComfyUI」动作刷新这块缓存。类名核对失败时，节点上写：「配方「某标题」要用到的节点某类名在这台 ComfyUI 里不存在。请换配方或改配方。」

绑定规则：

- `mode: "concat"` 只用于文本槽。按 `order` 从小到大用 `separator` 拼接。空槽不拼接。
- `mode: "set"` 把参数或单个媒体的已上传文件名写进 `to.nodeId` 的 `inputs[to.input]`。
- `mode: "byOrder"` 把该 `order` 的媒体写进指定节点。参考图有几张，配方就得有几条 `byOrder`，或者一条带 `order` 的绑定配一个节点 id 模板。第一版用显式多条绑定，不用模板语言。
- 媒体在写入 prompt 之前先上传。上传没成功就不要提交，prompt 里不得留下占位符。
- 用户看不见 `class_type`。绑定目标里的 `nodeId` 是配方内部 id，不是画布节点 id。

云端配方没有 `comfy` 段，也没有 URL 和报文体。只有槽、参数和 `cloud.constraints`。真正的 HTTP 细节留在适配器代码里，而且第一版的示例适配器不发网络（第 12 节）。

## 9. 本机后端如何代理 ComfyUI

浏览器没有到 ComfyUI 的通道。后端模块 `server/execution/comfy/client.ts` 是唯一的调用方。不把 `/prompt` 原样代理给浏览器，否则画布会变成第二个工作流编辑器。

建议后端对浏览器只开这些执行相关的路由：

| 方法与路径 | 作用 |
| --- | --- |
| `GET /api/execution/capabilities` | 返回种类、剖面、哪些已实现 |
| `GET /api/execution/recipes` | 返回配方摘要，含 `enabled` 与人话原因 |
| `POST /api/execution/runs/plan` | 只计划 |
| `POST /api/execution/runs` | 计划并入队 |
| `GET /api/execution/runs/:runId` | 刷新后取快照 |
| `POST /api/execution/runs/:runId/cancel` | 取消这一批里还没成功的任务 |
| `POST /api/execution/runs/:runId/retry-failed` | 只补失败变体 |
| `POST /api/execution/runs/:runId/resume` | 续跑对不上的中断任务 |
| `POST /api/execution/tasks/:taskId/cancel` | 取消单节点 |
| `GET /api/execution/comfy/health` | 可达则带上 `GET /system_stats` 里能读到的简短版本信息；读不到字段就只报告可达 |
| `POST /api/execution/comfy/recheck` | 刷新 object_info 缓存 |
| WebSocket `/api/execution/runs/:runId/events` | 推送 `RunEvent` |

健康检查失败时，HTTP 仍返回 200 加 `{ reachable: false, message: "连不上本机 ComfyUI。请确认它已启动，并且后端配置的地址可达。" }`，不要用 500 把这句话变成一堆栈。用户点运行时，任务再以 `COMFY_UNREACHABLE` 失败一次，节点上同一句。

后端自己调用 Comfy 时的拟定映射如下。路径来自第 2 节的路由页；标了「需核实」的，本会话没有响应样本。

| 我们的步骤 | 拟定调用 | 核实状态 |
| --- | --- | --- |
| 提交一张已填槽的 API 格式工作流 | `POST /prompt` | 路径已见文档。成功只依赖文档写明的 `prompt_id` 与 `number`。请求体需核实。失败读取 `error` 与 `node_errors`，再写成一句中文，不把整个 JSON 贴到节点上 |
| 订阅进度 | 连接 `/ws` | 路径已见文档。查询串是否要 `clientId`，路由页没写，需核实。事件名按消息页 |
| 确认结束并发现输出文件 | `GET /history/{prompt_id}` | 路径已见文档。响应里文件名、子目录、类型字段的位置需核实 |
| 把输出字节取回来 | `GET /view` | 路径已见文档。查询参数名需核实。取回的字节交给媒体库按内容哈希存放 |
| 提交前上传参考图、原图、遮罩、首帧、尾帧 | `POST /upload/image`，遮罩另评估 `POST /upload/mask` | 路径已见文档。表单字段名需核实。核实前用夹具测试，不要把猜测的字段名写进正式客户端还标成已验证 |
| 取消正在执行的一次 | `POST /interrupt` | 路径已见文档。请求体若有，需核实。第一版可以先发空正文，若本机返回 4xx，再按核实结果改 |
| 看前面是否还有不是我们提交的任务 | `GET /queue` | 路径已见文档。响应结构需核实。只用于文案「ComfyUI 里还有别的任务，我们的在后面」。不删除别人的任务 |
| 核对配方类名 | `GET /object_info/{node_class}` | 路径已见文档。响应结构需核实到「缺类名时如何表示」为止 |

`GET /prompt` 在路由页的说明是当前队列状态和执行信息，与 `GET /queue` 职责接近。第一版不以它为完成条件。若本机两者不一致，以能对上 `prompt_id` 的历史记录为准，并记一笔差异。

WebSocket 由后端进程保持连接，再翻译成 `RunEvent`。翻译规则：

- 收到 `execution_start`：该 `prompt_id` 对应变体进入 `running`，发 `task.running`。
- 收到带 `value` 和 `max` 的 `progress`：发 `task.progress`。没收到过 `progress` 时发 `task.progress.indeterminate`，文案「正在绘制」，不要造一个假百分比。
- 收到 `execution_success`：开始取历史和取图。取图、写入媒体库都成功，变体才是 `succeeded`。
- 收到 `execution_error`：变体 `failed`，错误码 `COMFY_EXECUTION_ERROR`。句子：「ComfyUI 执行失败。」若附加信息里有我们能确认的短 `exception_message` 一类字段，放进详情；字段名未核实前，详情可以只有 prompt_id。
- 收到 `execution_interrupted`：若该任务的取消标记已设上，错误码 `CANCELLED_BY_USER`，句子「已取消。」否则句子「ComfyUI 中断了这一次。」
- `executing` 的 `node` 为 `None` 只表示 Comfy 认为节点走完了，仍然要等 `execution_success` 再取图。
- 不把 `execution_cached` 当成可以跳过我们自己的任务。

取图失败或历史里找不到输出：变体失败，错误码 `COMFY_OUTPUT_MISSING`，句子：「ComfyUI 说完成了，但没有返回图片。」

上传失败：不提交 prompt，错误码 `UPLOAD_FAILED`，句子：「图片没有传给 ComfyUI。」

后端日志可以记 `taskId`、`recipeId`、`prompt_id`、状态变迁。不记密钥，不记图片字节，不记完整 prompt 文本。提示词可能是用户不想进日志的内容，第一版日志只记长度和槽位数量。

第一版假定这台 ComfyUI 主要给本应用用。我们不主动清空它的队列。如果 `queue_remaining` 大于 0 且那些项不是我们刚提交的 `prompt_id`，仍然提交我们这一个（排在它的队列后面），界面写：「ComfyUI 正在跑别的任务，这一张会等它。」不等待队列变空才提交，否则用户自己在 Comfy 界面里留一个任务时，我们会永远不提交。

## 10. 文生图：从点击到出图

这一节是第一刀的主路径。节点 A 是文本，正文是提示词。节点 B 是生成节点，配方为 `recipe.image.txt2img.fictional` 换成真实配方之后的那张，剖面 `txt2img`。一条边从 A 到 B，角色 `prompt`，`order` 为 0。B 的 `variantCount` 为 1。B 当前新鲜度是 `empty`。ComfyUI 已启动，配方类名核对已通过。

1. 用户在节点 B 上点击「运行此节点」。按钮立刻进入禁用，节点文案变成「正在安排……」。这一步不需要请求已经返回。若 点击后文字不变，算这一阶段验收失败。
2. 浏览器发送 `POST /api/execution/runs`。体为 `scope: { type: "node", nodeId: B }`，`force: false`，以及一个新的 `clientRequestId`。浏览器不发送工作流，不发送 Comfy 地址。
3. 后端读 `GraphReadModel.getNode(B)`，得到配方、参数、槽位。槽位指向 A 的正文。
4. 计划函数判定 B 要跑。摘要句子：「将运行 1 个节点。」
5. 事务写入 run（`running`）和 task（`queued`），变体 0 为 `queued`。若种子参数是 `"random"`，此时抽定 `seedUsed` 并写入变体行。指纹写入 `fingerprintAtStart`。
6. 返回快照。浏览器把摘要显示在运行记录里，节点文案改为「排队中」。
7. 本地调度器取到该任务。检查 `comfy.baseUrl` 可达。不可达则任务 `failed`，句子见第 9 节，到此结束。
8. 文生图没有图像槽，不上传。绑定器把提示词写入 API 格式 prompt 的对应输入，把宽度、高度、步数、相关性和 `seedUsed` 写入各自输入。
9. 后端 `POST /prompt`。成功则保存返回的 `prompt_id`，变体变为 `submitted`，事件 `task.submitted`。节点文案：「已交给 ComfyUI。」失败则读 `error` / `node_errors`，任务 `failed`，句子：「ComfyUI 拒绝了这次提交。」详情里可以有节点 id，不贴整份 prompt。
10. 后端已连上的 `/ws` 收到该 `prompt_id` 的 `execution_start`，变体变为 `running`。节点文案：「正在绘制。」若随后有 `progress`，进度条用 `value/max`。没有则保持不确定进度。
11. 收到 `execution_success` 后，`GET /history/{prompt_id}`，再按核实过的字段 `GET /view` 取字节。字节交给媒体库，得到内容哈希和相对路径，例如 `media/ab/cd/<hash>.png`。这一步的扩展名按媒体库从 MIME 推出的结果，不在执行域手写死。
12. 变体 `succeeded`，`outputs` 里是一张 `kind: "image"` 的记录。任务 `succeeded`。节点执行状态：`freshness = "fresh"`，`lastSuccessFingerprint` 等于开始时的指纹（若期间提示词没改），`selectedVariantIndex = 0`，变体条有这一张。
13. 后端把 B 的直接下游标成 `stale` 或按第 5.3 节保留 `empty`。不给下游建任务。
14. run 变为 `succeeded`。摘要：「这一批 1 个节点，成功了。」节点文案回到空白或「刚刚完成」，运行按钮恢复。变体条显示这张图。图怎么画是画布的事，执行域只保证相对路径和哈希已经写进节点执行状态。

期间用户若改了节点 A 的字：第 5.3 节不取消 B。B 完成后新鲜度按指纹比较写成 `stale`，句子：「跑完的时候输入已经变了，这张图已标成过期。」

用户双击：第二次请求带同一个 `clientRequestId` 时返回同一次 run。若前端每次点击都换新的 id，而后端看到该节点已是 `queued` 或 `running`，则第二次 `startRun` 失败，句子：「这个节点已经在跑。」不产生第二张图。

节点上只放一句中文。运行记录里放同一句，外加可选详情。不出现栈、密钥、完整工作流、磁盘绝对路径。

## 12. 取消、部分失败、只重跑该跑的部分

### 12.1 取消

取消一批：该 run 里状态还不是 `succeeded` 的任务都进入取消流程。已经成功的变体保留。

- 任务仍是 `queued`：直接 `cancelled`，不访问 Comfy，不访问云端。
- 任务是 `submitted` 或 `running`，车道本地：设取消标记，并 `POST /interrupt`。若它其实还排在 Comfy 队列里、中断打不中当前执行，则按第 7 节，等它一开始再中断。界面在这之前保持「已提交，等它一开始就停止。」
- 云端：调用适配器的 `cancel`。返回 `cancelled` 则任务取消。返回 `already-finished` 则改为去取结果，不把已经成功的结果扔掉。返回 `unsupported` 则停止轮询，任务标成 `cancelled`，句子仍是「已取消。」详情写：「对方可能还会做完，我们不再取回结果。」不把对方的后续回调写进节点。第一版示例适配器的取消必须返回 `cancelled`，方便演示。

取消是幂等的。对已经结束的 run 再取消，返回当前快照，不新增错误。

### 12.2 一批里一部分失败

一批指一次用户点击产生的一个 run，里面可以有多个节点，每个节点可以有多个变体。

节点之间：

- B 失败时，同一批里直接或间接依赖 B 的节点不提交。它们记为跳过，原因 `upstream_failed`。句子：「上游没成功，这一步没跑。」
- 与 B 没有依赖关系的节点继续跑。
- run 的最终状态：全部成功是 `succeeded`；有成功也有失败或这种跳过是 `partial`；没有任何成功且有失败是 `failed`；用户取消导致其余不再跑、且已有成功，是 `partial`；用户取消且没有任何成功，是 `cancelled`。
- 摘要必须点名数量。例子：「这一批 3 个节点：1 个成功，1 个失败，1 个因上游失败没跑。」

变体之间：

- 4 个变体串行。第 2 个失败时，默认停住，不再提交第 3、第 4 个。前 1 个成功结果留在变体条。任务状态 `partial`。节点新鲜度 `partial`。角标「1/4 成功」。失败的下标在变体条里是错误占位，不是空白格。
- 句子：「4 张里成功了 1 张。其余可以只重试失败的。」
- 不把成功的变体自动拖成新的画布节点。

`retryFailed`：

- 只重提该 run 中状态为 `failed` 的变体下标。
- 前提是节点现在的输入指纹仍等于 `fingerprintAtStart`。不等则拒绝，句子：「输入已经变了，不能只补失败的那几张。请重新运行这个节点。」
- 成功的变体不重新提交，种子也不重抽。
- 补跑仍走原来的车道和并发规则。

输入变了之后的「运行此节点」是整组重跑：新变体替换这个节点的变体条。已经拖出成独立节点的副本属于画布域，执行域不删除、不更新它们。

### 12.3 脏了之后只跑该跑的

「该跑」的定义就是第 6 节的计划函数，不是把下游全部强制重跑。

例子：A 文本改了，B 图像因此 `stale`，C 视频又依赖 B 所以也 `stale`，D 是另一支、指纹没变所以仍是 `fresh`。

- 运行 B：只提交 B。C 在 B 成功后被标成 `stale`（它本来就是），但不跑。D 不跑。
- 运行下游，起点是 A：A 跳过（文本）。B 跑。B 成功后 C 跑。D 不在下游里就不跑；若 D 在下游但为 `fresh`，跳过，摘要里写「跳过 1 个未改过的节点」。
- 运行选中部分，只选了 C：C 读取 B 当前那张过期图作为首帧，可以跑。不把 B 拉进这一批。摘要里不必说教，节点 C 若使用了过期输入，计划句子写：「将用上游当前的过期结果运行 1 个节点。」
- 运行选中部分，选了 B 和 D：B 跑，D 跳过。
- 强制重跑选中 B 和 D：两个都跑，即使 D 是新鲜的。

跳过不是失败，运行记录里用中性句子，不用红色错误样式。失败才用错误样式。

## 13. 重启后续跑

进程退出前不特殊刷盘，靠第 7 节的事务。启动时执行对账，不跑过期节点。

对每条状态仍是 `queued` 的任务：调度器照常接手。用户会看到它从「排队中」继续。这是在继续用户已经点击过的那一批，不是新的自动运行。

对每条 `submitted` 或 `running` 的本地任务：

- 用保存的 `prompt_id` 查 `GET /history/{prompt_id}`，并对照 `GET /queue`。两处的解析都依赖需核实的响应结构，对账代码要先有夹具。
- 历史表明成功：走第 10 节的取图和入库。已入库的哈希若媒体库说已经存在，不要再写一份。
- 队列表明仍在：保持 `submitted` 或 `running`，重新挂上 WebSocket 监听。
- Comfy 不可达：不提交第二份。任务保持原状态，节点文案：「正在核对上次没跑完的任务。」调度器按配置 `reconcileBackoffMs` 重试，初值 5000。这是重试间隔的产品初值，不是测量值。
- Comfy 可达，但队列和历史都找不到该 `prompt_id`：任务改为 `interrupted`，节点新鲜度 `interrupted`，句子：「重启后没能对上上次的任务。可以续跑。」不自动再 `POST /prompt`，避免把一次实际上还在别处跑的作业做成双份。用户点「续跑」才调用 `resumeInterrupted`，用原来的 `seedUsed` 重新提交这一个变体。

云端任务同样：有 `providerJobId` 且适配器还能查到，就继续轮询，不占一个新的提交；查不到且服务可达，标 `interrupted`，等用户续跑；服务不可达就保持原状态并重试对账。

对账结束后，若一个 run 的任务全是终态，把 run 收成 `succeeded`、`partial`、`failed` 或 `cancelled`。

后端启动完成之前，浏览器若打开工程，节点上已有的变体路径照常显示（那些在工程文件里）。正在对账的节点显示「正在核对上次没跑完的任务」，不要先闪成失败再变回去。

## 14. 第一个云端视频适配器

画布和调度器只认识 `CloudVideoAdapter`。第一张要接的真实适配器是图生视频，剖面 `img2video`。文生视频和对口型不在这张适配器里用 if 分支硬塞。

适配器必须自己消化下面这些差异。核心代码按字段分支，不按厂商名分支。

| 差异 | 约束字段 | 核心怎么做 | 适配器怎么做 |
| --- | --- | --- | --- |
| 上传方式 | `upload`: `multipart`、`presigned-put`、`remote-url`、`inline-bytes` 四者之一 | 只把本地相对路径和字节流交给适配器 | 选定一种并实现。第一种真实适配器选一种即可，不要四种都做完才允许合并 |
| 轮询 | `pollIntervalMs`、`pollTimeoutMs`，以及适配器内部的状态词表 | 按间隔调用 `poll`，超时则 `CLOUD_POLL_TIMEOUT`。不解析厂商 JSON | 把对方状态映射成 `queued`、`running`、`succeeded`、`failed`。映射表写在适配器里 |
| 首帧、尾帧 | `firstFrame` / `lastFrame`: `unsupported`、`optional`、`required` | 计划阶段就检查。`unsupported` 但用户连了线：`SLOT_UNSUPPORTED`。`required` 但没连：`INPUT_MISSING` | 在 `submit` 里放到对方要求的位置 |
| 参考图张数 | `referenceImageCount.min/max` | 超出则计划失败。句子：「参考图最多 3 张。」数字来自配方 | 按顺序上传，不多传也不少传 |
| 时长 | `duration.unit` 为 `seconds` 或 `frames`；要么 `allowed` 离散档，要么 `min` 与 `max` | 参数控件只展示允许的档或范围。非法值 `PARAM_OUT_OF_RANGE` | 换成对方的字段。核心不写对方的字段名 |

适配器接口：

```ts
type SecretHandle = { providerId: string };

interface CloudSubmitInput {
  taskId: string;
  slots: ResolvedSlotInput[];
  params: Record<string, Scalar>;
  /** 已由媒体库读出的字节。适配器不要自己猜磁盘路径。 */
  files: Array<{ role: SlotRole; order: number; mime: string; bytes: Uint8Array }>;
}

type CloudPollResult =
  | { state: "queued" | "running" }
  | { state: "succeeded" }
  | { state: "failed"; message: string };

interface CloudVideoAdapter {
  id: string;
  kind: "video.generate";
  profileId: "img2video";
  constraints: {
    upload: "multipart" | "presigned-put" | "remote-url" | "inline-bytes";
    firstFrame: "unsupported" | "optional" | "required";
    lastFrame: "unsupported" | "optional" | "required";
    referenceImageCount: { min: number; max: number };
    duration: {
      unit: "seconds" | "frames";
      allowed?: number[];
      min?: number;
      max?: number;
    };
    pollIntervalMs: number;
    pollTimeoutMs: number;
  };
  submit(input: CloudSubmitInput, secret: SecretHandle): Promise<{ providerJobId: string }>;
  poll(providerJobId: string, secret: SecretHandle): Promise<CloudPollResult>;
  cancel(providerJobId: string, secret: SecretHandle): Promise<"cancelled" | "unsupported" | "already-finished">;
  /** 成功后把产物字节交回来。写媒体库、抽封面和代理由核心调媒体域完成。 */
  download(providerJobId: string, secret: SecretHandle): Promise<{ bytes: Uint8Array; mime: string }>;
}
```

`SecretHandle` 不是密钥。适配器在要发请求时通过后端的凭据端口交换真正的密钥。该端口第一版读 Windows 凭据管理器，引用名约定为 `canvas/provider/<providerId>`。工程 JSON 和配方 JSON 都不写这个密钥，也不写凭据管理器里的口令。工程最多保存 `providerId`。

密钥缺失：在 `submit` 之前失败，句子见第 11 节。不要为了「先看看错误格式」发一个不带密钥的真实请求。

视频变体在下面四项都有相对路径之前，不得标成 `succeeded`：原片、时长、首帧静图、尾帧静图、封面、代理文件。时长来自媒体域对原片的读取，不来自用户参数的回声。用户参数里的时长是「想要的时长」；`durationMs` 是产物的时长。两者不一致时不失败，详情里写：「成片时长和选择的档位不一样。」单位用毫秒写进 `durationMs`，句子里换算成秒，保留一位小数即可。

画布播放只用 `proxyRelPath`。执行域不把原片路径放进给播放器的字段。封面用 `coverRelPath`。首帧和尾帧是生成语义，不是播放器的起播点；它们可以和封面是不同文件。若媒体域决定封面等于首帧，可以返回同一相对路径，执行域不反对。

原片下载成功但封面或代理失败：错误码 `PROXY_MEDIA_FAILED`，句子见第 11 节。允许稍后只重试「补媒体」而不是重新花钱生成。第一版实现成：变体保持 `failed`，但 `outputs` 里可以暂存原片哈希；`retryFailed` 发现已有原片且错误码是 `PROXY_MEDIA_FAILED` 时，不再调用 `submit`，只再请媒体域做封面、首尾帧和代理。这个分支要有测试，避免重试时重复提交云端。

第一版先做一个不联网的夹具适配器，id 为 `example.video.fixture`。它的 `submit` 返回虚构的 `providerJobId`（例如 `fixture-job-1`），`poll` 在测试里按调用次数从 `running` 变成 `succeeded`，`download` 返回一小段固定字节。用它把队列、取消、超时、部分失败和代理失败走通。真实厂商适配器以后替换 id 与配方，不改 `CapabilityService`。本文不提供任何厂商的 URL、鉴权头或 JSON 样例。

夹具的 `pollIntervalMs` 在测试里可以改成很小，以免测试真的睡两秒。生产配方上的 2000 不代表测量结果。

## 15. 节点执行状态要写进工程的字段

工程文件的格式由工程领域定。执行域要求每个生成节点能存下这些字段，并且随工程保存，这样换一台只拷工程和媒体库时，变体还在，队列可以不在。

- `recipeId`、`recipeVersion`
- `params`
- `variantCount`、`selectedVariantIndex`
- `freshness`、`lastSuccessFingerprint`
- `variants[]`：`index`、`state`、`seedUsed`、`error.message`、`outputs`（含第 5.1 节的相对路径与哈希，视频还包括时长、首帧、尾帧、封面、代理）

边要能存 `role` 与 `order`。

工程里没有 API Key，没有 Comfy 基地址，没有图片或视频二进制。基地址和密钥在后端本机配置和系统凭据库。

媒体相对路径形如 `media/ab/cd/<完整哈希>.<扩展名>`，正斜杠。哈希算法用 sha256，由媒体域计算。执行域只保存媒体域返回的路径和哈希。

## 16. 验收时什么叫这一域做完了一刀

每一阶段结束都要能在本机浏览器里点给别人看，并且状态文字、禁用按钮、错误句子一起算完成，不留到最后美化。

本会话没有性能实测，所以不写毫秒级指标。验收用眼睛看：点击之后节点文案马上变，不等到出图才动；失败有第 11 节的句子；进度要么是真的 `value/max`，要么是不确定状态，不能先显示 100% 再跳回；取消后转圈会停。

建议的自动化测试，第一版就该有，且不依赖真机 Comfy 和真云：

- 配方加载器拒绝带 `nodes`+`links` 的界面格式。
- 绑定器把两条 `prompt` 按 `order` 用空行拼好，并写入虚构 prompt 的指定输入。
- 计划函数：新鲜节点跳过；过期节点在「运行此节点」时只含自己；「运行下游」含过期下游；选区不把外面的过期节点拉进来。
- 本地车道不会在前一个变体结束前提交下一个。
- 四个变体里第二个失败，则任务为 `partial`，且第三个保持未提交。
- `retryFailed` 在指纹没变时只提交失败下标；指纹变了就拒绝。
- 取消 `queued` 任务不会调用上传或 `POST /prompt` 的测试替身。
- 重启对账：历史里已成功则入库且不二次提交；上游不认识该 id 则变为 `interrupted` 且不自动提交。
- 夹具视频适配器：缺首帧在计划阶段失败；时长不在 `allowed` 里失败；下载成功但代理失败时重试不会再次 `submit`。

真机 Comfy 测试另列，不阻塞上述单测。真机测试至少一张文生图，使用本机 `object_info` 核对过的配方，断言媒体库出现新哈希，且工程状态里的路径是正斜杠相对路径。本文写这份说明时，这只真机测试没有跑。

## 17. 因此放弃了什么

任务书的边界和本文范围冲突时，以边界为准。下面这些是有意不做的，不是漏写。

- 不做第二个 ComfyUI。没有任意工作流的打开、编辑、再导出，也没有计算节点画布。
- 不把 KSampler、VAE 或其他 `class_type` 暴露给用户。步数和提示词相关性只是配方参数的显示名。
- 不保存、不提交界面格式（`nodes` / `links` / `widgets_values` 那一类）。加载器直接拒绝。
- 本地并发不做配置项，固定为 1。不把一批任务预先灌进 Comfy 队列来「提高占用」，因为取消报文尚未核实，而且任务书要求并发为 1。
- 上游修改不自动重跑。重启后续跑只继续用户已经开始、还留在任务库里的那一批。
- 第一版不实现文生视频、对口型、多厂商和文本生成模型。接口和 `implemented: false` 留着，没有适配器，也没有假的云 URL。
- 不做桌面壳，浏览器不直连 ComfyUI。
- 工程文件不嵌二进制、不含 API Key、不含 Comfy 基地址。
- 变体不自动变成新节点。
- 画布不直接播放原片。封面和代理的编码参数、缩略图、像素呈现都不在本域实现。
- 不编造云厂商报文。虚构配方里的图生视频段只有约束字段。
- 不把公开文档没写出的请求体、上传字段、历史响应和队列删除字段写成已核实。对应能力在核对本机版本之前，用测试替身开发。
- 图生图所缺的「原图」角色是本文补上的 `source_image`。没有把它伪装成任务书已经点名的参考图。

## 18. 跨领域依赖

执行域要开工，需要邻域提供下面这些，而不是自己去画节点或自己编缩略图。

节点图领域：

- 实现 `GraphReadModel`：按 id 读节点执行视图、列传递下游、列选区。
- 边持久化 `role` 与 `order`，并保证同一节点同一角色内 `order` 唯一。
- 提供三个动作的入口，分别发送第 6 节的三种 `scope`。强制重跑是单独入口，默认按钮不带 `force`。
- 文本、连线、顺序、参数一变，调用 `markStaleFrom`。不要在图领域里直接插任务。
- 变体条的拖出由画布做。拖出后的新节点是副本。执行域只提供变体下标、相对路径、选中下标和错误句子。
- 环的交互可以在画布上提示，但执行域仍会拒绝带环的一批。

工程领域：

- 工程 JSON 能放下第 15 节的字段。
- 保存时使用正斜杠相对路径。
- 不把 `execution.sqlite`、密钥、Comfy 基地址写进工程。

媒体领域：

- `put(bytes, mime) -> { relPath, contentHash }`，哈希为 sha256，路径形如 `media/ab/cd/<hash>.<ext>`。
- `read(relPath) -> bytes`，供上传前读取原图、参考图、首帧、尾帧、遮罩。
- 相同哈希不重复占空间。执行域重试取图时要能承受「已经存在」。

ffmpeg / 视频媒体领域：

- 输入原片字节或已入库路径，输出 `durationMs`、首帧图、尾帧图、封面图、代理文件的相对路径。
- 任一输出失败要返回失败原因，让执行域写成 `PROXY_MEDIA_FAILED`。
- 不要求本域了解编码参数。本域只要求：在这些路径齐之前，视频变体不算成功；画布拿到的可播放路径只能是代理。

密钥领域：

- Windows 凭据管理器读写 `canvas/provider/<providerId>`。
- 给适配器的只有按 providerId 取密钥的函数。日志和错误句子走不到密钥内容。

画布呈现领域：

- 根据 `NodeFreshness`、任务状态和 `UserFacingError.message` 画角标、按钮禁用和变体条上的失败占位。
- 图片节点显示媒体路径指向的图。缩略图若需要，由画布域自己从已入库图片生成，不向执行域要另一套编码。
- 视频节点只播放 `proxyRelPath`，海报用 `coverRelPath`。

配置：

- 本机配置文件或环境变量提供 `comfy.baseUrl`、`cloudConcurrency`、`reconcileBackoffMs`。后两者有第 7、13 节的初值。不要把它们写进工程，以免换机器时带着别人的 Comfy 地址。

## 19. 建议落在哪些阶段

四个阶段都在本机 Windows 上、用浏览器加本机后端演示。后一阶段开始时，前一阶段的句子、禁用态和跳过逻辑仍然要在。不要为了接视频把文生图的错误显示退回去。

阶段 1：点一次，出一张图。

- 共享类型、配方加载器、拒绝界面格式、任务库、本地车道并发 1、Comfy 客户端替身。
- 文本节点作为提示词槽，一条真实或替身的文生图。
- 走通第 10 节。替身测试全绿；若本机 Comfy 和核对过的配方可用，再加一只真机演示。
- 验收：点击后立刻「正在安排……」，然后「排队中 / 已交给 ComfyUI / 正在绘制」，成功后变体条有图，工程里是相对路径。Comfy 没开时出现第 11 节那句，而不是空白或栈。

阶段 2：图生图、参考图、过期和三种跑法。

- 两张新配方剖面，`source_image` 与有序参考图绑定。
- `markStaleFrom` 接到图的编辑上。
- 三个 scope 的计划函数与第 12.3 节的例子一致，并且界面分得清「跳过」和「失败」。
- 连了遮罩但配方不接受时，出现「这张配方还不能用遮罩。」
- 验收：改提示词后下游只出现「过期」，不会自己跑。运行下游时，没改过的分支被跳过并有句子。演示过程里按钮禁用和角标始终跟得上状态。

阶段 3：变体、部分失败、取消、重启续跑。

- `variantCount` 最大 4，串行提交，部分失败角标「1/4 成功」。
- 取消未提交任务不打到 Comfy 替身；取消执行中任务会调用中断替身。
- 重启对账的四条路径（仍在队列、历史已成功、找不到、上游暂时不可达）都有测试。演示时可以杀掉后端再打开，看到「正在核对……」或「可以续跑」，而不是自动把所有过期节点跑一遍。
- 验收：失败占位在变体条里可见；只重试失败张时，成功的那张种子不变。画面上不出现原始 JSON。

阶段 4：一条图生视频。

- 先接 `example.video.fixture`，把上传方式、轮询、首帧尾帧、参考图张数、时长五类差异走完计划与失败句子。
- 媒体域能产出代理和封面之后，成功变体才带齐视频字段；代理失败的重试不二次 `submit`。
- 真实厂商适配器只有在密钥端口可用、并且适配器作者自己有授权可用的接口时才替换夹具。替换时仍不把厂商报文写进核心，也不写进本文。
- 文生视频和对口型保持「这一类还没接入。」
- 验收：画布播放的是代理文件而不是原片；缺首帧、时长不在档位内、密钥缺失，三种点运行都在提交前失败，并各有一句人话。云端车道可以与一张本地文生图时间重叠，但依赖首帧的那条视频会等图像任务成功后再占名额。

阶段 4 结束时，能力接口不再为「以后还有视频」而改形状。新厂商应是新的 `CloudVideoAdapter` 实现加一张配方。若届时发现某种差异放不进第 14 节的约束字段，先改约束字段和计划阶段的检查，不要在调度器里写厂商名。
